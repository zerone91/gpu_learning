# Tensor Core = 塞进 SIMT 核的小矩阵引擎

> **所属模块**：模块 03 · 两者交汇与扩展（全库伏笔的交汇点）
> **状态**：🟨 学习中（第一版：本质/费曼 + 开发者视角 + 最新架构，知识截至 2026-01）
> **一句话主旨**：Tensor Core 是 NVIDIA 对模块 02 那道选择题的回答——**要脉动阵列的能效，但不接受它的死板**。做法：把矩阵引擎做成**极小的粒度**（一条指令算 16×8×16 级的块），塞进每个 SM 子分区，**用 SIMT 的调度、寄存器堆和访存体系当它的"喂料系统"**。于是"两套词混着出现"有了答案：**矩阵引擎的词（tile/fragment/累加器）描述它的内部，SIMT 的词（warp/warpgroup/屏障）描述喂它的外围**——一个负载、两套硬件、一个kernel。

## 1. 核心概念

### 1.1 它是什么、在哪、算多大

- **位置**：每个 SM 子分区 1 个（一个 SM 共 4 个，§01-01 解剖图里就画了）。它和 FP32 lane、LSU 并列，是**子分区里的一个执行 pipe**（A1 的"Tensor pipe"）。
- **功能**：一条指令完成一个小矩阵块的 **D = A×B + C**。不是 32 个标量 FMA，而是**一整块矩阵乘加**：Hopper 一条 `wgmma` 可到 m64×n256×k16 级别。
- **内部是脉动阵列吗？**——诚实回答：**NVIDIA 不公开内部微架构**。公开信息与逆向研究表明它更接近**并行点积树阵列**（每拍做一组 4 元/8 元乘加树，多组并行铺开），而非教科书式"数据逐拍流过邻居"的脉动阵列。**但在本库的分析框架里这不重要**：它具备空间阵列的全部本质特征——**固定功能的 MAC 阵列、数据流经专用连线、复用在阵列内部免费发生、时序对一条指令而言完全确定**（§02-01/02 的判据全中）。说它是"小空间矩阵引擎"最准确，日常说"小脉动引擎"也无妨。

### 1.2 fragment：为什么矩阵在寄存器里是"打散"的——"两套词"的根源

Tensor Core **没有自己的输入存储**（Blackwell 前），操作数直接来自**warp 的寄存器堆**。但一个 16×16 的 tile 装不进任何单个线程的寄存器——于是：

> **矩阵 tile 被切碎、按固定模式分摊到 32 个线程的寄存器里**——每个线程持有 tile 的几个特定元素，这份"每线程持有哪几个元素"的映射就叫 **fragment（片段）布局**。执行 `mma` 时，32 条 lane 的寄存器**联合**构成完整操作数，Tensor Core 从这个"分布式寄存器"里读数。

这就是"两套词混用"的物理根源：
- **你写/读代码时**：看到的是 warp、线程、寄存器（SIMT 词汇）——因为操作数管理靠 SIMT 机制；
- **指令执行时**：发生的是 tile、fragment、累加（矩阵引擎词汇）——因为算的是一整块矩阵。
- **`ldmatrix`（§04）就是两个世界的摆渡人**：从 shared 按 fragment 布局把 tile 摆进 32 个线程的寄存器；**swizzle（§04 §1.3+）存在的意义就是让这次摆渡无 bank 冲突**。

### 1.3 编程模型四代演化：一条"逐步挣脱 SIMT 束缚"的轨迹

| 代 | 指令 | 粒度/发起者 | 解决什么 |
| --- | --- | --- | --- |
| Volta (2017) | `wmma` API | **1 warp** 协作，同步 | 首次暴露；固定 16×16×16，笨重 |
| Turing/Ampere | `mma.sync` | 1 warp，同步 | 更灵活形状（m16n8k16 等）、更薄的抽象 |
| **Hopper** | **`wgmma`** | **1 warpgroup（4 warp=128 线程）**，**异步** | tile 大到 warp 装不下 → 4 warp 拼寄存器；异步 → 与搬运/softmax 重叠（§02 §2.6、A2 FA-3 的基石）；**操作数可直接来自 shared**（省寄存器搬运） |
| **Blackwell** | **`tcgen05.mma`** | **单线程发起**，异步，操作数/累加器在 **TMEM** | 彻底与 warp 寄存器解耦：矩阵不再打散进 32 线程寄存器，而是住进专用 TMEM——**fragment 时代的终结（进行中）** |

> 🔑 **看清这条轨迹**：Volta 时矩阵引擎完全寄生在 SIMT 的资源里（warp 的寄存器、warp 的同步）；每一代都在**给它松绑**——tile 更大、发起更独立、存储更专用（TMEM）。**Tensor Core 正在从"SIMT 的一个执行单元"长成"SM 里半独立的矩阵协处理器"**——SIMT 核越来越像它的"控制平面 + DMA 平面"。这正是 §02-02 光谱上"SIMT 向右挪"的硬件版。

### 1.5 为什么塞进 SM，而不是像 TPU 做独立大阵列

这是两条路线的正面对决（收 §02-05 的"阵列粒度"线）：

| | TPU 路线（独立大阵列） | Tensor Core 路线（小引擎 × 内嵌） |
| --- | --- | --- |
| 峰值能效 | **更高**（控制摊薄到 128×128×全时） | 略低（每个小引擎都带 SIMT 外围） |
| 碎/怪形状 | 形状税重（§02-05 的悬崖） | **税轻**：小 tile + SIMT 动态调度拼装 |
| 非矩阵部分（softmax/norm/采样） | 甩给旁边的 VPU，**跨单元往返** | **同一个 kernel 里无缝混编**（FA 的 online softmax 直接夹在两次 MMA 之间——A2） |
| 灵活性来源 | 编译器（XLA 静态排） | **运行时 SIMT 调度 + 软件流水** |
| 一句话 | 把矩阵乘做到极致，其余靠编译器兜 | 牺牲一点峰值，换"矩阵与非矩阵水乳交融" |

> 🔑 **本质**：Tensor Core 的赌注是——**真实负载永远不是纯矩阵乘**（attention 里夹 softmax、MoE 里夹路由、训练里夹 norm/dropout）。把矩阵引擎嵌进通用核，让"矩阵的 87%"和"杂活的 13%"在同一片寄存器/shared 上零距离协作，总吞吐反而赢。**FlashAttention 系列在 GPU 上开花而非 TPU，不是偶然**——它需要的正是"MMA 与 softmax 在一个 kernel 里精细交织"的能力（A2 §1.7 的 ping-pong）。

## 2. 关键机制 / 补几个硬细节

- **精度阶梯与吞吐倍增**：FP16(Volta) → +BF16/TF32(Ampere) → +FP8(Hopper, Transformer Engine) → +**FP4/FP6（Blackwell, 微缩放格式 MXFP）**。位宽每砍半，同硅片吞吐近翻倍——**Tensor pipe 的 AI 平衡点随之抬高**（A1：FP8 要 AI>590 才 compute-bound），反过来逼算法侧降精度、逼 kernel 侧提复用。（量化本身你是专家，此处只记"硬件吞吐阶梯"这一面。）
- **结构化稀疏 2:4**：Ampere 起支持"每 4 个权重存 2 个非零"，硬件跳零 → 稠密吞吐 ×2。落地一般：约束太死、精度恢复训练成本高——收 §02-05 稀疏之问的一半。
- **累加精度**：低精度输入 + **FP32（或更高）累加器**——OS 数据流让累加器不动（寄存器/TMEM），保证长 K 求和不烂掉。这是"OS 血统"最实际的好处。

## 4. 最新架构落点（时效锚点 · 知识截至 2026-01）

- **Blackwell 第 5 代**：`tcgen05` + **TMEM**（§01 已记）+ FP4/FP6（MXFP 微缩放）；双 die 下每 SM 的矩阵吞吐继续爬。**单线程发起 MMA** 是范式信号：矩阵引擎进一步"去 warp 化"。
- **AMD Matrix Core（MFMA/WMMA 指令，CDNA3/4）**：思路同源（SIMD 内嵌矩阵单元、寄存器供数），MI350X 上 FP4/FP6 对标；无 TMEM 等价物（累加在 VGPR/AccVGPR）。
- **Intel XMX**（GPU Max/Arc）：同类内嵌矩阵引擎。
- **行业收敛判断**：**"通用核 + 内嵌小矩阵引擎"已成 GPU 侧标准答案**；纯大阵列路线固守推理/云上可控负载（TPU/昇腾）。两条路线的争夺点正是 §02-05 说的"形状不齐常态化"。

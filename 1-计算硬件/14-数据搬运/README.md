# 模块 14 · 数据搬运

模块 10～13 讲计算部件，本模块讲数据搬运。乘加电路只能从片上的寄存器和几块专用存储中取操作数。显存的一次往返要几百拍，在这段时间内，矩阵单元本来能算完一整个分块。所以数据必须提前搬到片上。搬运机制还要满足两个要求：不占用计算资源，并且把这几百拍隐藏在计算后面。

> **本模块与其它章节的关系**：全库此前在多处讲过搬运机制的一部分，包括 10-01 §4.4 LSU、10-04 §3 与 §6 的访存合并和 TMA、10-05 §4.5 mbarrier、10-08 §5.3 TMA 的汇编、11-04 §5 双缓冲与 MTE、13-04 §7 与 13-06 §5 的电路形态、50-01 §4～5 搬运指令矩阵、50-03 §3 主机侧 DMA。那些地方保留简要说明，并链接到本模块。本模块给出完整的讲解。

## 主线：每一种搬法都要回答三个问题

1. **谁发起**：谁发出搬运指令？可能是每个线程各自发出，可能是一个线程替所有线程发出，也可能完全不需要计算核上的线程。
2. **地址从哪来**：一个二维分块在显存中不连续。谁来计算每一段的起点？
3. **完成怎么知道**：使用数据的一方怎么知道数据已经到达？完成记录存放在哪里？哪些线程能读到它？

传输本身是给定条件：延迟是几百拍，带宽由 HBM 决定。搬运机制只能做两件事：把延迟隐藏在计算后面，以及让足够多的数据同时在路上。

GPU 每一代改变的就是这三个问题的答案：

- 最早，每个线程自己搬，靠记分牌知道数据已经到达。在途数据只能存放在寄存器中。
- Ampere 让数据不经过寄存器，直接写进 shared memory。
- Hopper 让一个线程发出搬运请求，由搬运引擎计算地址。完成记录放在 shared memory 中的 mbarrier 上，按字节记录，任何线程都能等待。
- Blackwell 让搬运引擎多负责一段路径：把数据从 shared memory 继续搬进矩阵单元的专用存储。

NPU 的硬件条件不同，从一开始就只有一种做法：由专用搬运引擎搬运，用显式标志同步。跨出芯片的搬运（到主机、其它卡、其它节点）由另一组发起者负责。另外，搬运引擎掌握着地址，所以它还能在搬运途中完成一些附加功能。这些附加功能单独成为一部分。

# 模块 14 · 数据搬运

模块 10～13 讲的是"算"的部件，这个模块讲"搬"。乘加电路只能从片上的寄存器和几块专用存储取操作数，显存一个来回要几百拍——等一次的工夫，矩阵单元本来能算完一整个分块。所以数据必须提前搬到片上，而且要搬得不占计算的资源、藏得住那几百拍。

> 📍 **这个模块是搬运机制的正式归宿。** 全库此前在多处讲过它的片段（10-01 §4.4 LSU、10-04 §3 与 §6 合并和 TMA、10-05 §4.5 mbarrier、10-08 §5.3 TMA 的汇编、11-04 §5 双缓冲与 MTE、13-04 §7 与 13-06 §5 的电路形态、50-01 §4～5 搬运指令矩阵、50-03 §3 主机侧 DMA）。那些地方保留简述并链接到这里。

## 主线：每一种搬法都在回答三个问题

1. **谁发起**：每个线程各发各的，一个线程替大家下单，还是根本不需要计算核上的线程？
2. **地址从哪来**：一个二维分块在显存里不连续，每一段的起点由谁算？
3. **完成怎么知道**：要用数据的人怎么知道数据到了？这本账记在哪、谁能看？

传输本身（延迟几百拍、带宽由 HBM 决定）对搬运机制是给定条件；机制能做的，是把延迟藏进计算、让足够多的数据同时在路上。

GPU 一代代改的就是这三个答案：最早每个线程自己搬、靠记分牌知道到货（在路上的数据只能停在寄存器里）；Ampere 让数据不过寄存器；Hopper 让一个线程下单、引擎算地址、账本放进谁都能看的 shared memory；Blackwell 让引擎再多管一跳。NPU 的硬件条件不同，一开始就只有"专用引擎 + 显式标志"这一条路。跨出芯片的搬运（主机、别的卡、别的节点）又是另一套发起者。最后，搬运引擎既然掌握着地址，还能顺手做些别的事——这些附加功能单独成一部分。

## 目录

### 第一部分 · GPU 的数据搬运（显存 → 计算单元）

- 🟨 [01 · 为什么要搬，以及最朴素的搬法：线程自己搬](./01-为什么要搬·线程自己搬与记分牌.md)
  - 乘加电路为什么只能从片上取数；等一次显存值多少计算。
  - 线程自己搬：代码、一条读取走过的路、合并。
  - 记分牌讲透：硬件里的 6 个计数器，谁加、谁减、谁查；它和寄存器到底是什么关系。
  - 哪里疼：完成挂在寄存器上，在路上的数据只能占寄存器；计算一代比一代快，要提前的级数越来越多，寄存器装不下。
- ⬜ 02 · Ampere：`cp.async`，数据不过寄存器
  - 在路上的数据改停在 shared memory，流水能排 3～4 级。
  - `wait_group` 其实还是记分牌（`DEPBAR`），变的是从"自动扣住用数的指令"变成"程序员指定等待点"；账本仍是每线程私有，所以全员发、全员等。
- ⬜ 03 · Hopper：TMA 与 mbarrier，一个线程下单
  - 张量描述符写了什么、引擎怎么算地址；mbarrier 按字节记账、由引擎记、谁都能等。
  - 生产者 / 消费者分工为什么从这里才成立。
- ⬜ 04 · Blackwell：TMEM 与 `tcgen05.cp`，引擎多管一跳
  - 矩阵单元的操作数和累加器搬进专用存储；gather 把一点不规则访问收进引擎。
- ⬜ 05 · 回头看：同一块数据的几种搬法并排算账，以及怎么选

## 和其它模块的接口

- **模块 10（SIMT 核）**：LSU、合并、记分牌、mbarrier 的基础在那里；本模块把它们串成完整的搬运机制。
- **模块 11（空间脉动架构）**：第 4 节的双缓冲是"搬运藏进计算"的原型；本模块第二部分讲 NPU 上执行这件事的引擎。
- **模块 13（微架构与物理实现）**：第 4 节讲记分牌、TMA 与 mbarrier 的电路形态，第 6 节讲 NPU 搬运引擎的硬件；本模块讲它们对外的行为和用法。
- **模块 21（封装与堆叠存储）**：HBM 为什么带宽高、延迟不低。
- **模块 30（互连）**：搬运走的路。本模块讲发起方，模块 30 讲链路。
- **模块 40（软件优化栈）**：第 4 节的软件流水、附录 B2 与 B4 的代码精读，是本模块机制在代码里的样子。
- **模块 50（数据视角）**：第 1 节的搬运指令矩阵是全景地图；第 2 节讲数据为什么要那样摆，本模块第四部分讲由谁、在哪一跳把数摆成那样。

# 空间 vs SIMT：两种范式的分水岭

> **所属模块**：模块 00 · 两种范式地图（定盘星）
> **状态**：✅ 已完成（学完模块 01–03 后回填——此时写它水到渠成）
> **一句话主旨**：两种范式的分水岭只有一个问题——**"谁先谁后"在什么时候被决定**。SIMT 说：**运行时**决定（动态调度、谁就绪跑谁），换来灵活，代价是同步/发散/调度的税；空间/脉动说：**设计期**决定（时序写进连线和时钟），换来能效，代价是死板。其余一切差异（要不要 barrier、要不要 cache、形状挑不挑剔）都是这一个选择的推论。

## 1. 分水岭：时序在何时被决定

| | **SIMT / GPU**（模块 01） | **空间 / 脉动**（模块 02） |
| --- | --- | --- |
| 谁先谁后 | **运行时**：调度器每拍挑就绪 warp | **设计期**：到达拍数 = 闭式公式 f(下标, 坐标) |
| 应对延迟 | **忍**：海量并发填满等待（车轮战） | **躲**：把不可预测的东西挡在门外（流水线工厂） |
| 同步 | 必须显式（barrier/fence/mbarrier 全家桶，§01-05） | **不需要**——同步被编译进连线和时钟（§02-02） |
| 片上存储 | cache + 记分牌（为"不可预测"买保险） | scratchpad（访存编译期全知，保险纯属浪费，§02-04） |
| 复用 | 显式搬进 shared/寄存器（coalescing/swizzle 伺候） | **在电线里免费发生**（§02-01） |
| 控制开销 | 摊到 32 lane（warp 团购） | 摊到整个阵列 × 全部时间（趋近零） |
| 形状 | 什么都吃（动态调度兜底） | **计算迁就硬件**（对齐阵列边长，否则 padding 空转，§02-05） |
| 失效模式 | 发散/低占用/访存不齐（按拍收费） | 形状不整/fill-drain 摊不平（按 tile 收费） |
| 性能分析 | 运行时 profiler 下钻（A1 三级） | 编译报告看利用率（九成问题在形状与映射） |
| 一句话 | **硬件迁就计算** | **计算迁就硬件** |

## 2. 光谱：真实芯片都活在两极之间

纯粹的两极几乎不存在，真实设计都在这条光谱上选位置：

```
全动态 ◄──────────────────────────────────────────────► 全静态
纯 SIMT ─── 异步流水/warp专化 ─── Tensor Core ─── 脉动阵列 ─── Groq
(老CUDA)   (FA-3/CUTLASS:软件     (小空间引擎嵌   (TPU MXU:    (连指令和
            把时序半排死)          进SIMT核)       大阵列)      网络都排死)
◄─ 灵活、同步多、能效低              确定、零同步、能效高 ─►
```

- **两派在互相靠近**：SIMT 在最重的负载上主动向右挪（TMA+mbarrier+warp 专化 = 软件模拟静态时刻表，§01-02 §2.6）；矩阵引擎向左嵌（Tensor Core 用 SIMT 当喂料系统和控制平面，§03-01）。
- **争夺的焦点**：负载的"形状确定性"。稠密大 GEMM → 右边赢；夹杂 softmax/路由/变长的真实负载 → 左边赢——**FlashAttention 在 GPU 开花、MoE 逼大阵列低头，都是这场拔河的战报**（A2、§02-05）。

## 3. 快速判词法：听到一个词，先问它属于哪派

- 带"等/问"味的词（barrier、fence、scoreboard、stall、occupancy、调度）→ **SIMT 派**——存在理由都是"运行时不确定"。
- 带"排/钉"味的词（systolic、stationary、tiling 到阵列、静态调度、确定性延迟）→ **空间派**——存在理由都是"编译期已知"。
- 两套词混着出现（fragment、wgmma、TMEM、warp 专化）→ **交汇区**（模块 03）——矩阵引擎的里子、SIMT 的面子。

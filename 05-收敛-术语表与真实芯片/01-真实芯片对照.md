## 2. 总对照表（全库概念 → 三块硅片）

| 本库概念（出处） | **NVIDIA Hopper/Blackwell** | **Google TPU (v5p/v6/v7)** | **昇腾 DaVinci (910B/C)** |
| --- | --- | --- | --- |
| 计算核（§01-01） | SM（H100 132 个，含 4 子分区） | TensorCore*（每芯 1–2 个大核，*注意：TPU 的 "TensorCore" 指整个计算核，与 NV 的 Tensor Core 完全不是一回事——**著名撞名**） | AI Core（Da Vinci 核，数十个） |
| 矩阵引擎（§03-01/02-01） | **Tensor Core**（每子分区 1 个，小 tile：MMA/wgmma/tcgen05） | **MXU**（128×128 脉动阵列，每核多个） | **Cube**（16×16×16 立体 MAC 阵列） |
| 矩阵引擎的数据流（02-03） | **OS**（累加器驻寄存器/TMEM） | **WS**（权重钉在 PE） | 块级 OS（L0C 累加） |
| 向量/标量伴生（02-02 代价#1） | CUDA core（同一 SM 内无缝混编） | **VPU**（向量处理单元，与 MXU 并列） | **Vector 单元 + Scalar 单元**（与 Cube 并列于 AI Core 内） |
| 线程/执行模型（§01-02） | warp/warpgroup 动态调度 | 无线程概念——XLA 静态排 | 核内静态流水，核间任务队列 |
| 片上快存（§01-04/02-04） | shared memory/L1（228KB，软硬两用） | **CMEM/VMEM**（scratchpad，编译器管理） | **L0A/L0B/L0C**（贴 Cube 三块）→ **L1** → **UB**（Unified Buffer）——**层级全显式**，最"手动挡" |
| 搬运引擎（§01-04/02-04） | **TMA**（+cp.async） | 编译器排定的 DMA | **MTE**（Memory Transfer Engine） |
| 同步（§01-05/02-02） | 全家桶（mbarrier/命名屏障/cluster.sync） | 基本不需要——静态时刻表 | 核内流水同步指令（pipe barrier），比 GPU 简单、比 TPU 多一点 |
| 主内存 | HBM3/3e（80–288GB，~3.35–8TB/s） | HBM（代际递增） | HBM |
| scale-up 互连（03-02） | **NVLink5 + NVSwitch（NVL72 域）** | **ICI + OCS 光交换**（pod 数千芯片，静态可重构） | **HCCS**（CloudMatrix 384 超节点） |
| 图编译层（04-01/02） | torch.compile/Inductor、TensorRT（可选加速器） | **XLA**（必经之路，全图静态） | **CANN/GE**（必经之路） |
| kernel 层（04-03） | CUDA/Triton/CUTLASS（全民可写） | Pallas（受限的 kernel DSL，例外通道） | **Ascend C / TIK**（可写，placement 手动） |
| ISA 策略（§01-06） | PTX 虚拟层 + SASS 不公开（卖时间兼容） | 无用户可见 ISA（编译器直出） | 不公开，经 CANN |
| 性能分析（A1/02-02） | Nsight 运行时下钻（stall/SOL） | 编译报告 + XProf（九成看形状与映射） | CANN Profiling（Cube 利用率 vs MTE 占比） |
| 最新代际（时效） | Blackwell B200/B300（FP4/TMEM/NVL72）；Rubin 路线图 | v6 Trillium / v7 Ironwood（推理导向） | 910C（双 die）；CloudMatrix 拼大域 |

## 3. 每颗芯片一段"人设速写"

### Google TPU：教科书的空间架构，赌"云上负载可控"
- **本体**：大 MXU（128×128 WS 脉动阵列）+ VPU 伴生 + 大 scratchpad + 无 cache 无线程——模块 02 每一节的直接实体。
- **成立条件**：负载形状可控（Google 自家训练/推理，凑批、对齐都由服务层保证）→ 形状税可控 → 大阵列能效红利吃满。
- **听到就定位**：MXU→02-01；XLA/HLO→04-01②层；ICI/OCS→03-02；Pallas→04-03 例外通道；**"TPU 的 TensorCore"→ 是整个核，别和 NV 混**。

### NVIDIA GPU：动态为体、静态为用，赌"真实负载永远混杂"
- **本体**：SIMT 底盘（模块 01 全部）+ 每子分区一个小矩阵引擎（03-01）+ 逐代把常用映射固化成器件（TMA/TMEM/cluster）。
- **成立条件**：负载混杂多变（attention 夹 softmax、MoE 夹路由、生态百家）→ 灵活性溢价 > 能效折损。
- **听到就定位**：warp/occupancy/stall→模块 01；wgmma/TMEM→03-01；NVL72→03-02；Triton/CUTLASS→04-03。

### 昇腾 DaVinci：三合一异构核 + 手动挡存储，走"显式暴露"路线
- **本体**：一个 AI Core 里 **Cube（矩阵）+ Vector（向量）+ Scalar（标量）三种引擎并列**——把 GPU"同一批 lane 混编"和 TPU"MXU+VPU 分立"折中成"一核三引擎"；存储 L0A/L0B/L0C→L1→UB 全显式，MTE 搬运——**比 TPU 更暴露、比 GPU 更静态**。
- **成立条件**：软硬一体自控（CANN 必经）+ 国产生态位。
- **听到就定位**：Cube/L0/UB/MTE→02-01/02-04；Vector/Scalar→02-02 代价#1 的"伴生核"；AscendC/TIK→04-03 手动挡 placement；HCCS/CloudMatrix→03-02。

### （第四参照）AMD MI300X/MI350：SIMT 阵营的另一半
- CU/wavefront(64)/Matrix Core(MFMA)/LDS/Infinity Cache/Infinity Fabric——模块 01/03 各节已逐点对照过，词不同、除法全同。定位时全部按"NV 概念的 AMD 名"处理即可。

## 4. 实战：三句"混合黑话"的秒翻译（验收全库）

1. *"这个 kernel 在 H100 上 Tensor pipe 只有 30%，主要 stall 在 mbarrier wait"* → NV 坐标；03-01 引擎没喂饱 + §01-05 生产者-消费者握手在等——**查 TMA 流水深度/形状对齐**（A1 四步）。
2. *"TPU 上这个形状 MXU 利用率只有 40%，XLA 报了大量 padding"* → TPU 坐标;02-05 形状税——**查哪个维度不整除 128**，服务层能否凑批。
3. *"910C 上 Cube 空转，MTE 通道打满"* → 昇腾坐标;02-04 的"喂料不足"——**tile 太小复用不够**，查 tiling/UB 驻留。

> 三句话来自三块芯片，但翻译动作完全一致：**定坐标 → 挂概念 → 走 A1/02 的定位流程**。这就是全库要交付的能力。

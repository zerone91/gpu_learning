# 模块 20 · 存储器件：一个比特怎么存、怎么接出来

封装与 HBM 那几节（模块 21）反复出现"DRAM 电容缩不动""闪存擦写有寿命""PHY 又大又费电"这类结论，但没有打开器件本身。这个模块补上这一层：SRAM、DRAM、NAND 闪存三种存储器各自**用什么器件存一个比特、怎么读写、因此带来哪些独有的约束**，以及它们各自**通过什么接口接到系统上**。没有器件背景的读者建议先读这个模块，再读模块 21。

## 五节怎么分工

划分框架是"三种存储器 ×（单元与阵列、接口）"。SRAM 做在逻辑芯片内部，接口只是存储宏的一组同步引脚，篇幅小，所以和单元合成一节；DRAM 和闪存是独立的芯片，接口各自是一个专门的工程领域，所以单元和接口各占一节。

| 存储器 | 单元与阵列 | 接口 |
| --- | --- | --- |
| SRAM | 01（§3～§7）：6T 单元、稳定性与最低工作电压、存储宏、漏电与软错误、微缩 | 01（§8）：存储宏的同步引脚与时序，独立 SRAM 芯片 |
| DRAM | 02：1T1C 单元、破坏性读出、刷新、row hammer、片内纠错、工艺微缩 | 03：控制器 / DFI / PHY 的分层、DQS 源同步、阻抗校准与端接、训练、DIMM 模组、DDR / LPDDR / GDDR / HBM 对照 |
| NAND 闪存 | 04：浮栅与电荷陷阱、编程 / 读 / 擦除、页 / 块 / plane、一个单元存多位、擦写寿命与各类干扰、3D NAND、纠错 | 05：朝 NAND 一侧的 ONFI / Toggle 接口、控制器与 FTL、寿命的系统账、朝主机一侧的 eMMC / UFS / SATA / NVMe |

| 节 | 这种器件最要紧的一条约束 |
| --- | --- |
| 01 | 一位要六个晶体管，读稳定与可写互相牵制，所以面积大、电压降不下去 |
| 02 | 电荷存在电容上，读一次就破坏、不读也会漏，所以必须回写和刷新，电容也难以缩小 |
| 03 | 几十根并行线各自的延迟不相等，速率越高越必须逐根训练对齐 |
| 04 | 电荷靠高压隧穿进出，氧化层每次都受损，所以只能整块擦、擦写次数有限 |
| 05 | 闪存不能原地覆盖写，必须由控制器做地址映射和垃圾回收，寿命和性能都取决于这一层 |

01 的 §2 是整个模块的总览，把三种存储器并排放在一张表里对照；只想先建立全貌的读者可以只读那一节。

## 和其它模块的接口

- **模块 21（封装与堆叠存储）**：那里讲 HBM 怎么把 DRAM 叠起来、3D-DRAM 怎么叠到逻辑上；本模块第 2、3 节是它的器件与接口底子。
- **模块 13 第 03 节（片上存储的物理实现）**：和本模块第 1 节讲的是同一种器件的两个方向。13-03 从 6T 单元往上搭到寄存器堆和 cache，关心它在 GPU 微架构里怎么用；本模块第 1 节关心器件本身——稳定性、最低工作电压、漏电、微缩和接口。
- **模块 30 第 2 节（互连的物理实现）**：本模块第 3 节的并行 PHY 与那里的 SerDes 是两种接口路线，能耗与引脚账在那里对照。
- **模块 50 第 3 节（数据进 GPU 之前）**：那里把闪存盘当成一个带宽数字来用（NVMe 盘经 PCIe 到显存）；本模块第 4、5 节打开这个盒子，讲这个数字背后的器件和控制器。

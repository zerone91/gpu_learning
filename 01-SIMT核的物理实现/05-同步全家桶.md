# 同步全家桶

> **所属模块**：模块 01 · SIMT 核的物理实现（收官）
> **状态**：🟨 学习中（第一版：本质/费曼 + 开发者视角 + 最新架构，知识截至 2026-01）
> **一句话主旨**：**同步是「异步」的账单**。SIMT 为藏延迟把一切做成异步（warp、线程、拷贝引擎、tensor core 各自推进），于是必须在会合点**显式等齐（barrier）+ 对表可见（fence）**；脉动阵列选了相反的路——时序设计期定死，每个数据哪一拍到都确定，**没有"要不要等"这回事**，所以不需要同步。同步全家桶越长，正说明这颗核越异步。

## 1. 核心概念

### 1.1 费曼起点：同步是异步的账单

回看整个模块：SIMT 的高性能**建立在异步之上**——
- warp 各自被调度、谁就绪跑谁（§01/§02）；
- 线程（Volta ITS 后）有独立 PC，各自推进（§03）；
- 拷贝引擎（cp.async/TMA）与计算解耦（§04/§02）；
- tensor core（wgmma）异步，发了不等（§02）。

**每一样都是为了藏延迟。** 但异步带来一个必然问题：当线程 A 要读线程 B（或 TMA 引擎）写的数据时，**怎么保证 B 真的写完了、而且写的结果 A 看得见？** 答案就是同步——**在特定会合点，让快的等慢的、让写的对读的"对表"。**

> 🔑 **同步不是 SIMT 的额外功能，而是它选择异步所必须付的税。** 记住这句，全家桶每个成员都是"某种异步"对应的那张账单。

### 1.2 两件必须分清的事：等齐（barrier）vs 可见（fence）

同步要保证两件**正交**的事，新手常混：

| | barrier（屏障） | fence（内存栅栏） |
| --- | --- | --- |
| 保证 | **到达**："大家都跑到这一点了" | **可见/有序**："我之前的写，别人之后能看到" |
| 管的是 | 控制流会合 | 内存可见性顺序 |
| 单独用会漏 | 只等齐不保证看到对方的写 | 只保证可见但没人在等 |

真实原语常把两者**合体**：`__syncthreads()` = block 内 barrier **+** shared/global 的 fence。理解这个拆分，才知道某个 bug 是"没等齐"还是"没对表"。

> 底层前提：GPU 是**弱内存模型（weak/relaxed）**——没有 fence 时，一个线程的多个写**以什么顺序被别人看到没有保证**。CUDA 9 起有了正式的**内存一致性模型**：操作带 **memory order**（relaxed/acquire/release/acq_rel/seq_cst）+ **scope**（thread/warp/block/cluster/device/system）。全家桶本质是这套模型的语法糖。

### 1.3 全家桶逐个点名（保证什么 · 什么 scope · 对应哪种异步）

| 原语 | 保证 | scope | 为哪种异步买单 |
| --- | --- | --- | --- |
| **`__syncwarp(mask)`** | 命名 lane 重收敛 + warp 内内存序 | warp | **ITS**：每线程独立 PC（§03）打破了隐式锁步 |
| **`__syncthreads()`** | block 内全员到达 + shared/global fence | block(CTA) | warp 各自异步推进（§01/§02） |
| **`__threadfence[_block/_system]()`** | 纯 fence（**无**到达语义） | block/device/system | 无锁算法、"最后一个 block 收尾"模式 |
| **atomics（+scope）** `atomicAdd/CAS` | 不可分割的读-改-写 | block/device/system | 多线程争同一地址（计数器、锁、工作队列） |
| **命名屏障** `bar.sync id,cnt` | 每 block 最多 16 个独立屏障，各带参与数 | block 子集 | **warp 专化**：生产者/消费者各守一个屏障（§02 ping-pong 的硬件基础） |
| **mbarrier（事务屏障）** | arrive/wait + **按字节计数** `expect_tx` | block/cluster | **与硬件引擎同步**：TMA 搬完"到达并报字节数"（§04） |
| **`cp.async` 组** commit/wait_group | 异步拷贝完成追踪 | 线程 | Ampere 异步拷贝（§04） |
| **wgmma 组** commit/wait_group + fence | 异步 tensor core 完成 + 寄存器依赖栅栏 | warpgroup | 异步 MMA（§02） |
| **Cooperative Groups** | 统一 API：`this_thread_block/tiled_partition<32>/coalesced_threads/this_grid/this_cluster` | 任意粒度 | ITS 后"显式化"的总接口 |
| **cluster.sync()** | 跨 block 簇（SM-to-SM）屏障 | cluster | Hopper 分布式共享内存 DSM（§04） |

### 1.4 演化：为什么全家桶越来越长

**每当机器多一样异步能力，就得配一个新同步原语**——这就是全家桶膨胀的规律：
- 早期 CUDA：`__syncthreads()` + **隐式 warp 锁步**，简单。
- **Volta ITS**：隐式 warp 同步失效 → `__syncwarp` + `*_sync`（§03）。
- **Ampere 异步拷贝**：内存解耦 → `cp.async` commit/wait。
- **Hopper**：TMA + wgmma + warp 专化 + 簇 → **mbarrier（与引擎同步、按字节）**、命名屏障、`cluster.sync`、`elect.sync`（选一个 leader 线程发 TMA）。

> 🔑 **本质**：**同步的复杂度，是异步性能的影子。** 你在 §02 §2.6 看到的"越重的负载越靠显式异步流水"，代价就是这里越来越细的显式同步。

### 1.5 生产者-消费者流水的同步骨架（接 §02 §2.6，用 mbarrier 实现）

```
生产者(TMA 引擎)：
    TMA_load(smem[k]) 并 mbarrier.arrive.expect_tx(full[k], 字节数)   # 搬完自动到达
消费者(warp)：
    mbarrier.try_wait(full[k])     # 等这块的字节全部落地
    compute(smem[k])               # 用（wgmma 异步）
    mbarrier.arrive(empty[k])      # 报告"用完，缓冲可回收"
生产者：mbarrier.try_wait(empty[k]) 后再重装 smem[k+N]
```

**注意**：这里消费者不是在等另一个线程，而是**在等 TMA 硬件引擎**——mbarrier 的 `expect_tx` 让"同步对象"从"线程"扩展到"引擎 + 字节数"。这是异步时代同步最本质的一次升级。

## 2. 关键机制 / 为什么这样设计

### 2.1 收模块主线：为什么 SIMT 必须同步、脉动阵列不用

这是模块 01 一路铺垫的正面回答。

**SIMT（动态、异步）：**
- 为藏延迟，采用**动态调度 + 超额并发**：谁就绪跑谁、线程独立 PC、引擎解耦。**没有任何一处的时序是编译期确定的。**
- 正因时序不定，"B 写完没、A 能不能读"**只能运行时判断** → 必须有 barrier/fence/atomic 这些**运行时会合机制**。
- 换来的是**灵活**：任意程序、数据相关的控制流、用占用率藏任意延迟。

**脉动阵列（静态、同步于时钟）：**
- 数据随时钟一拍一拍"泵"过阵列，**时序在设计/编译期就定死**：每个 PE 在第几拍拿到哪个数，是**构造保证**的。
- 因此**永远不需要"等一下、看数据到没到"**——它在被调度的那一拍**必然**到。同步被"编译进了连线和时钟"里。
- 代价是**死板**：形状/维度要对齐（模块 02 §5）、控制流几乎没有、padding 浪费阵列。

> 🔑 **一句话对照**：**SIMT 用「静态确定性」换「动态灵活性」，于是必须付显式同步的税；脉动阵列反过来，用死板换来"零同步"。** 而 §02 §2.6 的 warp 专化流水，正是 SIMT 在最重负载上**主动向静态调度靠拢**——同步全家桶越接近"把生产-消费时序排死"，就越像一个软件模拟的脉动流水。这条线到模块 02、03（Tensor Core = 塞进 SIMT 的小脉动引擎）会闭合。

### 2.2 同步的代价：等齐、争用、过度同步

- **barrier 的尾部代价**：所有参与者必须到达 → 快的等慢的；热循环里一个 `__syncthreads()` 可能主导耗时（Nsight `Barrier` stall）。**发散的 `__syncthreads()` 是未定义/死锁**——所有线程必须到达**同一个**屏障（呼应 §03）。
- **atomic 争用**：打同一地址的 atomic **在全机串行**。解法：先做 shared 内 atomic / 归约树，再一次性提交到 global（把争用限制在 block 内）。
- **过度同步**：多余的 `__syncthreads()` 掐死重叠；**欠同步**：竞争 → 结果非确定、极难调。
- 🔑 **优化方向 = 少同步、晚同步、窄 scope**：mbarrier/命名屏障之所以是进步，就因为它们让你**解耦**（生产者消费者不必全员对齐，只在字节就绪时点对点会合），把"全局等齐"降级成"局部握手"。

## 3. 开发者视角：代码/工具里怎么摸到它

| 想控制/观察 | ① 源码拨盘 | ② 编译器回执（SASS） | ③ Profiler 探针（Nsight Compute） |
| --- | --- | --- | --- |
| block 等齐 + 可见 | `__syncthreads()` / CG `block.sync()` | `BAR.SYNC` + `MEMBAR` | stall **`Barrier`** |
| warp 内同步（ITS 必需） | `__syncwarp(mask)`、`*_sync` | `WARPSYNC`、`BSSY/BSYNC` | stall `Short Scoreboard`/`Barrier` |
| 纯可见性 | `__threadfence*` | `MEMBAR.GPU/SYS` | stall `Membar` |
| 原子/无锁 | `atomicAdd_block/_system`、CAS | `ATOM`/`RED` | shared/global atom 指令数、争用停顿 |
| 异步拷贝/流水 | `cuda::pipeline`、`cuda::barrier`、`cp.async.wait_group`、mbarrier | `LDGSTS`、`mbarrier.*`、`elect.sync` | async copy 相关、stall 结构 |
| 网格/簇级 | `cooperative_groups::this_grid().sync()`（需 cooperative launch）、`cluster.sync()` | `BAR`/cluster 指令 | — |

**读法**：`Barrier` stall 高 → 要么负载不均（快 warp 空等）、要么同步太频；先看能不能**放宽 scope 或减少屏障**。Race 类 bug 用 `compute-sanitizer --tool racecheck/synccheck` 抓。

### 站位阶梯

| 站位 | 拨盘 | 感官 |
| --- | --- | --- |
| PyTorch | 无感（库内处理） | — |
| **Triton** | **几乎全隐式**：编译器在 shared 用法前后自动插屏障；`num_stages` 背后就是 mbarrier 流水；`tl.debug_barrier()` | autotune 时"流水深度换同步开销" |
| CUDA C | 全家桶全在手里 | 上面那张大表 + `compute-sanitizer` |
| SASS/PTX | 只读 | `BAR.SYNC`/`MEMBAR`/`mbarrier.*` 密度 |

> 对算法侧的你：Triton 把同步几乎全隐藏了，你主要通过 **`num_stages`**（流水深度）间接付同步成本——深流水藏更多延迟，但更多 mbarrier 握手 + 更多 shared。

## 4. 最新架构落点（时效锚点 · 知识截至 2026-01）

- **Hopper**：mbarrier（事务/字节计数）、**命名屏障**、`cluster.sync` + DSM、TMA/wgmma 异步组、`setmaxnreg`、`elect.sync`——warp 专化流水的整套同步底座。
- **Blackwell**：tcgen05（TMEM）异步、延续簇——**越异步 → 同步越显式越细**，趋势不变。
- **AMD（CDNA/RDNA）**：workgroup 屏障 `s_barrier`；**内存序靠显式计数器 `s_waitcnt`**（`vmcnt` 向量访存、`lgkmcnt` LDS/常量）——编译器插 `s_waitcnt N` 等到"未完成访存 ≤ N"。这是**软件管理的异步内存序**，和 NVIDIA 的硬件记分牌是**两种不同哲学**（AMD 把等待计数暴露给软件，NV 藏在硬件屏障里）。无直接 mbarrier 等价物。
- **内存模型**：CUDA 的 scoped 一致性模型（thread→system 七级 scope）是写正确同步的正式依据，最新架构都遵循。

# 分支发散（branch divergence）

> **所属模块**：模块 01 · SIMT 核的物理实现
> **状态**：🟨 学习中（第一版：本质/费曼 + 开发者视角 + 最新架构，知识截至 2026-01）
> **一句话主旨**：分支发散是 §01"SIMT 团购控制开销"那笔便宜买卖的**账单**——32 线程共用一个指令流，一旦它们意见不一，硬件只能把各条路径**串行跑一遍、用掩码关掉不该参与的 lane**，被关的 lane 白占吞吐。Volta 的独立线程调度改的是**正确性与死锁**（每线程独立 PC、显式同步），**没改**发散的吞吐代价。

## 1. 核心概念

### 1.1 费曼起点：发散是"团购"的账单

回到 §01 §4.3：SIMT 之所以高能效，是把**取指/译码/调度**这套昂贵控制硬件，让 **32 个线程团购摊薄**——一条指令，喂 32 条 lane。这笔买卖的前提是**32 个线程走同一条路**。

现在问：`if (threadIdx.x % 2) { A } else { B }`——16 个线程想走 A，16 个想走 B。可整个 warp **只有一个程序计数器（PC）**，它不可能同时指向 A 和 B。硬件怎么办？

> **唯一的办法：把两条路都跑一遍，各跑时用一个 32 位的「活动掩码（active mask）」关掉不该参与的 lane。** 跑 A 时，想走 B 的 16 条 lane 被掩码关闭（它们照样"走完"这些指令周期，但结果被丢弃）；跑 B 时反过来。**两条路串行，被关的 lane 白占吞吐。**

这就是分支发散。**它是 SIMT 折扣的代价**：平时省了 32 倍控制开销，一旦发散，就得为"路径串行 + lane 空转"还账。

### 1.2 代价模型：发散只在"warp 内部意见不一"时才收费

关键量是 **warp 执行效率 = 平均每条发射指令里真正活跃的 lane 数 / 32**。

- 一个 warp 里**所有 32 lane 都走同一条路** → 分支是"**一致的（uniform / coherent）**" → **零发散、免费**。
- warp 内出现分歧 → 代价 = **该 warp 里任意 lane 走过的所有路径之和**。
  - 50/50 的二分支 → A、B 都要跑 → **~2× 时间、效率降到 50%**。
  - 最坏：一个 32 路 `switch`，每条 lane 各走一支 → **~32× 慢、效率 1/32**。

> 🔑 **判据（极其实用）**：发散**只看 warp 内部是否分歧**，不看 block、不看 grid。所以同一个 `if`，发不发散取决于**分支条件是否在 32-lane 边界上对齐**：

| 分支条件 | 每个 warp 内 | 是否发散 |
| --- | --- | --- |
| `if (threadIdx.x % 2)` | 16/16 劈开 | **最大发散** |
| `if (threadIdx.x < 32)`（block=256） | warp0 全 true、warp1~7 全 false | **零发散**（每 warp 一致） |
| `if (threadIdx.x / 32 == k)` | 按 warp 号分 | **零发散** |
| `if (data[tid] > 0)` | 看数据分布 | 随机→发散；聚簇/排序→一致 |

**同一段逻辑，把分歧对齐到 warp 边界，就能把发散消掉**——这是所有反发散优化的总纲。

### 1.3 谓词化 vs 真分支：编译器的两种实现

- **小分支体 → 谓词化（predication）**：编译器干脆**不跳转**，把 `if` 体编译成**带谓词的指令**（SASS 里的 `@P0 IADD ...`）。每条 lane 都执行这条指令，但只有谓词为真的 lane 写回结果。省掉了分支/重收敛的开销，但**两"边"仍都占周期**（只是没有跳转成本）。适合几行的短 body。
- **大分支体 → 真分支 + 掩码 + 重收敛**：body 大到"让全员都跑一遍两边"不划算时，编译器生成真正的跳转，配合 active mask 与下面的重收敛机制。编译器按 body 大小在两者间权衡。

### 1.4 重收敛与 SIMT 栈（Volta 之前的模型）

发散之后，线程得在某处**重新聚回锁步**才能恢复效率，这个点叫**重收敛点（reconvergence point）**，通常是分支的**直接后支配点（immediate post-dominator）**——if/else 之后第一条大家都会执行的指令。

Volta 之前，硬件用一个**每 warp 的 SIMT 栈**管理：遇到发散，把 {掩码, 恢复 PC} 压栈，先跑一条路，跑到重收敛点弹栈，再跑另一条，两条都到齐后继续锁步。

**这个栈模型有个致命缺陷——warp 内死锁**：它**一条路跑到底才跑另一条**。若走 A 的线程自旋等待走 B 的线程释放一把锁，而 B 的线程要等 A 跑完重收敛才有机会执行 → **互相等，死锁**。所以在 Volta 前，**warp 内做细粒度线程间同步是不安全的**。

## 2. 关键机制 / 为什么这样设计

### 2.1 Volta 独立线程调度（ITS）：改了正确性，没改吞吐代价

这就是 §01/§02 一直预告的大变化。**Volta（2017, SM70）给每个线程配了自己的 PC 和调用栈**（program counter per-thread，而非 per-warp）。后果分两面：

**改变了的（正确性 / 编程模型）：**
- 调度器现在能在**指令粒度上交错推进**不同路径的线程 → 自旋等待的线程可以让步，另一条路得以前进 → **warp 内死锁消失**，可以写细粒度的 intra-warp 生产者-消费者、无饥饿算法。
- **重收敛不再自动**。老模型在后支配点自动聚回；ITS 下**不保证**，需要程序员**显式**要求。于是引入了 `__syncwarp()` 和一整套带掩码的 `*_sync` intrinsic（`__shfl_sync`、`__ballot_sync`、`__any_sync`…）——你必须**显式写明哪些 lane 参与**。
- ⚠️ **这就是为什么大量老代码在 Volta 上崩**：过去很多 warp-level reduction / shuffle 隐式依赖"warp 天然锁步、自动重收敛"，不写 `__syncwarp`。ITS 下这个假设不再成立，结果错乱。**"warp-synchronous programming"从此必须显式化。**

**没有改变的（吞吐）：**
- 发散**仍然要串行跑各条路径、仍然浪费被掩码的 lane**。ITS 让每条 lane 有独立 PC，但硬件**每拍仍只发射一条指令给一部分 lane**——它**没让发散变免费**。
- NVIDIA 为弥补效率，加了**收敛优化器（convergence optimizer）**，在可能时仍把线程聚回一起发射以保吞吐。

> 🔑 **本质一句话**：**Volta ITS 用"每线程独立进度 + 显式同步"换来了正确性与免死锁；发散的吞吐账单（路径串行、lane 空转）一分没减。** 所以优化上的铁律没变——**热点路径里别发散，把分歧对齐到 warp 边界**（§1.2）。

### 2.2 别混淆：控制发散 vs 访存发散

"发散"有两个含义，机制不同，常一起出现：
- **控制发散（本节）**：warp 内走不同**控制流路径** → 路径串行、lane 掩码浪费。
- **访存发散（memory divergence，§01 §4.5 / §04）**：warp 内 32 lane 访问**分散地址** → 无法 coalescing → 访存事务被串行化，最坏 1/32 带宽。

两者都源于"warp 内不齐"，但一个卡在**执行 pipe**、一个卡在**访存 pipe**。用 A1 的话说：控制发散压低 `Warp Execution Efficiency`，访存发散压低 `Global Load Efficiency`。

### 2.3 真实场景里发散/不齐在哪咬人（接 A2）

- **MoE 路由**：不同 token 去不同专家 → 若在一个 warp 里混着处理，权重地址、甚至控制流都不齐。**A2 的 Group GEMM「按专家排序/分组」正是"把分歧对齐到 warp/tile 边界"这条总纲的落地。**
- **Attention 因果掩码 / 变长序列**：对角线块上，warp 内有的位置被 mask、有的没有 → 边界块发散。FA 的做法是只算三角部分、只在对角块做 mask，把发散限制在少数块。
- **采样 / beam search / 稀疏算子 / ragged batch**：经典发散源。
- **通用套路**：**排序让 warp 内一致**（如 wavefront path tracing 把光线按材质排序）——本质都是 §1.2。

## 3. 开发者视角：代码/工具里怎么摸到它

| 想控制/观察 | ① 源码拨盘 | ② 编译器回执（SASS） | ③ Profiler 探针（Nsight Compute） |
| --- | --- | --- | --- |
| 是否发散 / 发散多重 | 分支条件对齐 warp 边界（`tid/32` 而非 `tid%2`）；按 key 排序/分组数据 | `@P` 谓词指令；`BRA`/`BSSY`+`BSYNC`（Volta+ 收敛屏障）；分支目标 | **`Warp Execution Efficiency`**（平均活跃 lane%，100%=无发散）；**`Branch Efficiency`**（一致分支占比）；`Avg. Divergent Branches` |
| 谓词化浪费 | 短 body 交给编译器谓词化；`tl.where` | 谓词指令数 vs 有效写回 | `Thread Instructions Executed` vs `Instructions Executed` 的差 |
| warp 内正确同步 | `__syncwarp(mask)`、`__shfl_sync`、`__ballot_sync`、Cooperative Groups `coalesced_threads()` | `WARPSYNC` | stall `Barrier` / `Membar` |
| 发散造成的停顿 | 减少分支/循环 trip 不齐 | — | stall `Branch Resolving` |

**读法**：`Warp Execution Efficiency` 是发散的**直接体温计**——掉到 60% 就说明平均四成 lane 在空转。先看它，再回代码找"warp 内不齐的那个条件/循环"，把分歧对齐到 32 边界或排序聚簇。

## 4. 最新架构落点（时效锚点 · 知识截至 2026-01）

- **Volta 起 ITS 已是通用模型**（Turing / Ampere / Ada / Hopper / Blackwell 全有）——所以"独立线程调度 + 显式 `*_sync`"是**当前的默认现实**，写 warp-level 代码必须带掩码。SASS 里 `BSSY/BSYNC` 的收敛屏障、收敛优化器都是这套的一部分。
- **warp 专化 / 异步流水（§02 §2.6、A2 FA-3）刻意保持控制流一致**：生产者/消费者各自路径 uniform，把发散关在门外——高性能 kernel 的共性就是"几乎不发散"。
- **AMD（CDNA / RDNA）**：wavefront **64 宽**，用一个显式的 **EXEC 掩码寄存器**管活动 lane；发散靠改 EXEC 实现，若某路径无 lane 活跃则 `s_cbranch_execz` 跳过。**wave 更宽（64）意味着发散潜在更贵**；传统上更接近"掩码模型"而非 per-lane PC。定位用 rocprof/Omniperf 的对应指标。
- **Blackwell**：延续 ITS + 收敛优化器；FP4/大 tile 的 kernel 更依赖 uniform 控制流。

## 5. 和其它模块的挂钩

- **收掉 §01 §4.3 / §02 的"锁步"引子**：发散是团购的账单；ITS 是"逻辑锁步、物理可独立推进"的完成态。
- `__syncwarp` / `*_sync` / mbarrier / 命名屏障 → **§05 同步全家桶**（ITS 之后同步为何必须显式）。
- 访存发散 / coalescing → **§01 §4.5、§04 访存通路**。
- 按 key 排序对齐 warp = MoE Group GEMM 分组、attention 掩码 → **A2**、**模块 04**。
- 脉动阵列**没有控制流发散**（时序静态、无 per-lane 分支）→ **模块 02 强对照**。

# 配图规范（全库）

> 本规范来自模块 20 存储器件五节的配图实践（2026-09，79 张图：26 张取自 Wikimedia Commons，53 张自绘 SVG）。给其它模块补图时照此执行。写作本身仍遵守 [`写作规范.md`](./写作规范.md)。工具是同目录的 [`figtools.py`](./figtools.py)。

## 一、原则：先找现成的图，找不到再自己画

图的来源分三类，处理方式不同：

| 来源 | 怎么处理 | 典型例子 |
| --- | --- | --- |
| **自由许可的图**：公有领域、CC0、CC BY、CC BY-SA | 首选。下载进仓库，图注写作者、许可、来源页链接 | Wikimedia Commons 上的电路图、结构剖面、实物照片、真实眼图 |
| **受版权保护或许可不明的图**：厂商官网、JEDEC、IEEE 论文、新闻稿、教材、技术媒体 | 不下载、不嵌入。确实讲得好的，在图注末尾加一句"延伸看图"文字链接，写清那张图画了什么、看它能看到什么 | ONFI 规范里的时序图、SemiAnalysis 文章里的工艺图 |
| **找不到合适的现成图** | 自己画 SVG | 波形与时序、电压配置、训练扫描、自定义的对照图 |

判断许可只看来源页上写明的许可；页面没写许可的一律按第二类处理。

**Commons 页面上的许可也可能不可信**：如果作者或出处写的是厂商或官方文档（例如"作者 NVIDIA，出处 CUDA Programming Guide"、"作者 HuggingFace"），而页面标的是公有领域或 CC 许可，多半是上传者把别人有版权的图搬了上来，按第二类处理，不入库。实际遇到过两例：CUDA 编程指南里的存储空间图、FlashAttention 的显存读写示意图，最后都换成了自绘图。可信的通常是上传者自己画的图、自己拍的照片，或者明确以 CC 许可发表的论文里的图。CC BY-SA 的图原样使用（包括只加白底）时，署名即满足要求。

**实践中的比例**：结构、电路、实物这类图在 Commons 上常能找到；波形、时序、流程、带具体数字的示意图几乎都要自绘。模块 20 五节里现成图约占三分之一，DRAM 接口这种以时序为主的章节，自绘占七成。

## 二、放在哪里、怎么命名

- 每个模块一个图片目录：`<模块目录>/figures/`，Markdown 里用相对路径 `./figures/xxx` 引用。
- 文件名：`<模块号>-<节号>-<简短英文名>`，全小写、连字符分隔，例如 `20-02-dram-cell-1t1c.svg`。目录名是中文没关系，文件名保持 ASCII。
- 大小：位图宽度 1000～1600 像素，单个文件尽量不超过 500 KB（`figtools.py get` 默认取 1400 宽的缩略图）。照片存 JPG，线条图存 PNG 或 SVG。

## 三、在 Commons 上找图

```bash
python3 _模板/figtools.py search "NAND flash cell" -n 20
python3 _模板/figtools.py get "File:NAND_levels.png" 2-存储与封装/20-存储器件/figures/20-04-vth-levels.png
```

`get` 会自动做三件事：透明背景的位图填白；SVG 最底层加白色矩形；打印一行可直接粘进图注的"来源："（作者和许可取自 Commons 的元数据）。许可不是自由许可时会给出警告。

**检索经验**：
- 用英文关键词，多试同义词：`DRAM cell`、`stacked capacitor`、`sense amplifier`、`eye pattern`、`floating gate`、`NAND flash structure`、`SSD controller`、`RDIMM`、`NVMe`。
- 实物照片搜型号或品类加 "Computex"、"internal"、"PCB" 等词，常能找到拆机照和展会照。
- 同一作者往往画了一整套风格统一的图（例如 NAND 那一组来自同一作者），找到一张好图后顺着作者的其它上传看一遍。
- 外语维基百科条目里的图注常能补上 Commons 页面缺的图例说明（例如某张 4F² 结构图的编号含义取自日文维基的图注）。

**以下几类图，模块 20 实际遇到过，下载后都放弃了**：
- 标注是法语、德语、土耳其语、西班牙语的图。
- 结构或参数过时的图：老式 12 V 热电子注入的闪存单元、4 KiB 页与 64 页一块的 NAND 示意、早期沟槽电容。
- 分辨率太低的图（几百像素宽）、黑底图、有水印的图、AI 生成的图。
- 没有任何标注、无法与正文对应的图。
- 与已选图重复、信息量更少的图。

## 四、每张图都必须亲眼看过

下载的图用 Read 工具打开看；SVG 先渲染成 PNG 再看：

```bash
python3 _模板/figtools.py render 2-存储与封装/20-存储器件/figures/20-04-self-boost.svg --out <临时目录>
```

看三件事：
1. **画的确实是正文讲的那个东西**，代际和结构都对得上（例如平面衬底擦除的图不能拿来讲 3D NAND 的 GIDL 擦除；图注要说明差别，或者不用）。
2. **图里的标注与正文不冲突**。图里的符号和正文叫法不一致时，在图注里逐个对上。例如 6T 电路图里的 M1～M6 分别对应正文的哪只晶体管，图里 Q 画在右边而正文画在左边。
3. **清晰可读**，没有文字重叠、出界、被裁掉，箭头指向正确。

**同类信号不是同一个接口时，必须在图注里说明。** 例如真实眼图来自千兆以太网或车载以太网，不是 DDR 或 GDDR7；示意分布不是实测数据。

## 五、自己画 SVG

- 手写 SVG，写明 `viewBox`，宽度 800～1000。
- **第一层画白色背景矩形**。GitHub 深色主题下，透明背景上的黑线看不见。
- 字体用 `font-family="sans-serif"`，字号不小于 14，标注用中文；线宽不小于 1.5。
- 颜色克制：黑和深灰为主，两三种强调色；不单靠颜色区分，配文字、图例或线型。
- 数值要和正文一致：波形图的时间点、电压值、网格的通过/失败格，都要对着正文的表格逐个核对。示意性的数据在图上或图注里标明"示意"。
- 画完必须渲染出来看；有问题就改到没有问题为止。模块 20 修过的典型问题：文字与曲线重叠、标签压在填充区上、数字出界、虚线穿过文字、箭头方向画反、图例与图不一致。

**适合自绘的内容**：时序波形（写读操作、命令序列）、电压配置（每条线加多少伏）、分布与偏移（阈值电压分布）、扫描结果网格、分层框图、前后对比（有无某项机制）、按真实比例画的结构（例如 30 nm × 1500 nm 的电容柱）。

**正文里已有的 ASCII 示意图**：画得勉强的换成 SVG；本身很清楚的保留，旁边加图。

## 六、Markdown 写法

```markdown
![一句话说明画了什么（替代文字）](./figures/20-03-dfe-block.svg)

> **图 6-8**　一句话：……（这张图的核心结论。用平实的书面语，不用比喻，不超过 3 句）
>
> **先知道一件事**：……（读懂这张图需要、但读者可能不知道的那一个前提）
>
> **按这个顺序看**：
> 1. ……
> 2. ……
>
> **打个比方**：……（可选）
>
> **看懂的标志**：……
>
> **与正文的对照**：……（可选）
>
> 来源：[文件名](来源页 URL)，作者 XXX，许可 CC BY-SA 4.0（本库把透明背景填成了白色）。
```

- 图注的每一块之间、以及图注与"来源"之间，都要空一行 `>`。否则相邻两行会被合成一段，GitHub 上显示为同一行。
- 自绘图写 `来源：本库自绘。`；有延伸外链时接在后面：`来源：本库自绘。延伸看图：[标题](URL) 有……`。
- 图号按章内顺序编：第 7 节的第 10 张图是"图 7-10"。一个图号对应两张照片（例如同一块内存条的正反面）时，两个 `![]()` 连写，共用一个图注。
- 图紧跟在它解释的那段文字之后；正文第一次用到它的地方写"见图 7-10"或"图 7-10 把这个差别画了出来"。
- 补图后更新文首状态行和文末"最后更新"，写明补了几张、其中现成几张、自绘几张。

## 六之一、图注怎么写：用费曼法，写给没有硬件背景的人

**读者是谁**：有算法和软件背景、没有学过电路和器件的人。他不知道晶体管的栅极是什么、不知道 P 型和 N 型的区别、不知道为什么线长了信号会变形。图注要让他**只看这张图和这段图注**就能明白图在说什么。

**费曼法在图注里的含义**：假设你要把这张图讲给一个聪明但外行的朋友听，他随时会问"这是什么意思""为什么"。把他会问的问题提前答掉，并且用他已经懂的东西来讲。写完后自问：删掉所有术语，这段话还讲得通吗？讲不通，说明是在用术语代替解释。

**图注的句子同样遵守写作规范第二部分的行文风格 STE-80**：句子短，一句一事，主语清楚，不用口语和破折号插入语。

**图注的六块，按顺序写**：

| 块 | 写什么 | 要点 |
| --- | --- | --- |
| **一句话** | 这张图说明了什么 | 平实的书面语，不用术语，不用比喻。不超过 3 句，第一句给出核心结论（写作规范风格第 13 条）。读者只读这一块也有收获 |
| **先知道一件事** | 读懂这张图所需的那一个前提 | 只挑一个最关键的：例如"晶体管在这里就是一个受电压控制的开关"。前提多于一个，说明图太复杂，考虑拆图 |
| **按这个顺序看** | 引导视线，编号列出先看哪、再看哪 | 每一步说清"看到了什么"和"它意味着什么"。图里出现的每个符号、缩写、颜色，第一次出现时就地解释 |
| **打个比方** | 一个日常类比 | 可选。**必须放在机制讲完之后**，删掉它图注仍然完整（写作规范规则二）。比方要和机制一一对应，不能只是气氛。这是图注中唯一可以用比喻的块 |
| **看懂的标志** | 读者看懂后应该能回答的一个问题，并给出答案 | 这是费曼法的"自检"：把图的要点变成一个可复述的结论 |
| **与正文的对照** | 图里的符号与正文叫法的对应、图与正文的差异 | 可选。放在最后，给需要对照正文的人；不要把它放在开头挡住外行读者 |

**几条具体要求**：
- 术语在图注里第一次出现必须就地解释，哪怕正文前面讲过（写作规范规则一）。"栅极""位线""UI""抽头"这些词都不能直接用。
- 数字要讲出它的意思，而不只是报出来：不写"压差 11.5 伏"，写"只剩 11.5 伏，不够把电子推进去"。
- 电路图、波形图、剖面图这三类最需要"先知道一件事"：电路图先讲开关，波形图先讲横轴是时间、纵轴是电压，剖面图先讲这是"把芯片竖着切开看"。
- 实物照片要指出每个部件在照片的哪个位置（左上、中间、底部的金手指旁），并说明它是干什么的。
- 篇幅不设上限，讲清楚优先；但每一句都要为"看懂这张图"服务，与图无关的扩展放回正文。

### 范例一：电路图（现成图）

> **图 4-2**　一句话：SRAM 的一个比特存在这六个晶体管组成的电路中。中间四个晶体管互相维持一个值。两边两个晶体管控制外部能否读写这个值。
>
> **先知道一件事**：在这张图中，晶体管就是一个受电压控制的开关。每个晶体管旁边的短竖线是它的控制端，叫栅极。栅极加高电压时，开关接通。栅极加低电压时，开关断开。带小圆圈的两个晶体管（M2、M4）正好相反：栅极加低电压时接通。
>
> **按这个顺序看**：
> 1. 先看中间的四个晶体管。左边上下两个（M2、M1）是一组，右边上下两个（M4、M3）是一组。每一组都把输入反相后输出：输入高电压时，输出低电压；输入低电压时，输出高电压。
> 2. 再看两组之间的交叉连线。左组的输出（Q̄ 点）接到右组的输入，右组的输出（Q 点）接回左组的输入。如果 Q 是高电压，左组就把 Q̄ 输出为低电压。Q̄ 是低电压，右组又把 Q 输出为高电压。两个点互相维持，只要不断电，这个状态就不变。这样，电路就存住了一个比特。
> 3. 最后看最外侧的 M5、M6 和顶部的横线 WL（字线）。两侧的竖线 BL、BL̄ 叫位线，是数据进出的通道。字线为低电压时，M5、M6 断开，中间的电路与位线隔开。字线为高电压时，M5、M6 接通，外部电路才能读出或改写中间的值。
>
> **打个比方**：中间的四个晶体管像两个人背靠背互相顶住，谁也不会倒下。M5、M6 像两扇门，平时关着。字线下令开门时，外面的人才能看到他们的姿势，或者用力把他们推成另一个姿势。
>
> **看懂的标志**：能回答"SRAM 为什么不需要刷新"。原因是：接通的晶体管把 Q 和 Q̄ 一直连在电源或地上。如果漏掉一点电，电源或地马上把它补回来。DRAM 不同：它的电容是孤立的，漏掉的电没有来源补充。
>
> **与正文的对照**：M6、M5 是正文的访问管 PG1、PG2。M4、M3 是上拉管 PU1、下拉管 PD1。M2、M1 是上拉管 PU2、下拉管 PD2。图中的 Q 画在右边，正文走查中画在左边，但连接关系相同。
>
> 来源：[SRAM Cell (6 Transistors).svg](https://commons.wikimedia.org/wiki/File:SRAM_Cell_(6_Transistors).svg)，作者 Inductiveload，许可 Public domain（本库添加了白色背景）。

### 范例二：框图（自绘）

> **图 6-8**　一句话：判决反馈均衡器用刚刚读出的前几个比特，算出它们叠加在当前比特上的干扰，再把这部分干扰减掉。
>
> **先知道一件事**：导线上的比特不会彼此干净地分开到达。一个比特的电压在它自己的时间段结束后不会立刻消失，残余的电压会叠加到后面几个比特上，这种残余叫拖尾。拖尾的大小由线路本身决定，基本固定，可以事先测出。图中的"系数"就是测出的拖尾大小：前 1 个比特留下 30 毫伏，前 2 个比特留下 12 毫伏，依此类推。
>
> **按这个顺序看**：
> 1. 从左边的输入开始看。收到的电压是 −25 毫伏。一个干净的 0 应该在 −80 毫伏，前面几个比特的拖尾把它抬高了。它离 0 与 1 的分界线（0 毫伏）只剩 25 毫伏，所以很容易判错。
> 2. 看右边的判决器。判决器只做一件事：电压高于 0 时判为 1，低于 0 时判为 0。
> 3. 看下方的四个方框。它们按顺序记录刚判出的前 1、2、3、4 个比特。每个比特乘以自己的系数，就是它留下的拖尾：比特为 1 时取正，为 0 时取负。四项相加是 +55 毫伏。
> 4. 回到输入端的 Σ（求和点）。−25 毫伏减去 +55 毫伏，得到 −80 毫伏，这正是干净的 0 应在的位置。Σ 把这个电压交给判决器。
>
> **打个比方**：在有回声的房间里听人说话。你知道自己刚听到了哪几个字，也知道这个房间的回声有多响，所以可以在心里把回声减掉。剩下的就是这个字本身。
>
> **看懂的标志**：能说出这个电路最紧的时间限制。信号从判决器出来、乘以系数、回到 Σ，这一圈必须在一个比特的时间内走完。DDR5-6400 下，一个比特的时间是 156 皮秒。如果走不完，下一个比特到达时，电路还不知道该减多少。
>
> 来源：本库自绘。

## 七、交稿前检查

```bash
python3 _模板/figtools.py check 2-存储与封装/20-存储器件
```

检查项：图片链接是否指向存在的文件、`figures/` 里有没有闲置文件、每张图下面是否有"来源："、章内图号是否重复、SVG 是否有白底、图注与来源是否分成两段、文件是否偏大。不带参数时检查所有模块。

## 八、流程经验

- **一节一个任务，最好由写这一节的人来配图**。他知道哪里文字最难懂，也知道每个数字的来历，核对图与正文的一致性最快。多节可以并行。
- **数量按需**：以"哪里文字最难懂"挑位置，不凑数。经验值：两三百行的节 3～6 张，四五百行的节 6～10 张，千行以上的节 10～15 张。适合配图的是空间结构（剖面、版图、堆叠、阵列）、波形与时序、数据流动的逐拍过程、分层框图、流程、前后对比。已经用表格讲清楚的走查不必再配图。
- **图号与文件名的特殊情况**：附录节（A1、B2 等）的图号写"图 A1-3"，文件名前缀写 `10-A1-`；模块 00 的文件名前缀是 `00-01-`。
- **中途被打断时不要重做**。已下载和已画好的文件都在 `figures/` 里，先用 `check` 和 `ls figures/<前缀>*` 看进度，再从断点继续。模块 20 被打断过两次，图片都保留了下来，只是正文还没插图。
- **下载后没用上的图要删掉**，否则 `check` 会报闲置文件。
- 每张现成图的来源页、作者、许可要在下载时就记进图注，不要事后再补，事后很难回忆是哪一页。

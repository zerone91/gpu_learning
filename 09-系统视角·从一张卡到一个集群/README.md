# 模块 09 · 系统视角：从一张卡到一个集群（纵向串线）

前八个模块把"一张卡"讲透了：从一个 6T 存储单元（模块 08）到一个 SM（模块 01），到片上的数据流（模块 06）、封装里的 HBM（模块 07）、以及把负载映射上去的软件栈（模块 04）。**但真实的大模型训练和推理都不是"一张卡"的事**——训练是几千张卡在每一步都要同步的紧耦合计算，推理是几百个请求随时到达随时结束的动态服务。

**这个模块补的是全库此前最大的一块空白：从"一个 kernel"到"一万张卡"之间的那整个系统层。** 它是纵向串线（和模块 06、07、08 一样不占主线顺序），主题轴是**规模**——不问"这个 kernel 快不快"，只问四个问题：

> **装不装得下？通信扛不扛得住？延迟守不守得住？坏了怎么办？**

四节按"训练 → 推理 → 底座 → 现实"排：先讲训练系统的显存账与并行组合（01），再讲推理服务的请求生命周期与延迟取舍（02），然后把两者共用的通信底座打开（03），最后面对一个前三节都假装不存在的事实——**这些卡会坏，而且比你想的频繁得多**（04）。

## 四节怎么分工

| 节 | 打开的黑盒 | 收束点（一句话） |
| --- | --- | --- |
| 01 | "分布式训练"这四个字 | 训练每个参数要 **16 字节**，70B 就是 1120 GB；五种并行各砍账本的不同行；一切损失最后折算成 **MFU** |
| 02 | "推理服务"这四个字 | **KV cache 的大小就是并发数，也就是单位成本**；prefill 与 decode 性质相反、互相伤害，业界一路解到了两种芯片 |
| 03 | all-reduce 这个黑盒 | **环形算法每卡发送量与卡数无关**——这是大规模数据并行成立的全部数学基础；拓扑是并行嵌套在布线上的镜像 |
| 04 | "这些卡会一直好好跑" 这个假设 | 单卡 MTBF 五年，**一万张卡每三小时坏一次**；最可怕的不是崩溃而是**算错了却不报错** |

## 一条贯穿全模块的主线

四节看起来在讲四件不相干的事，但它们反复验证同一句话：

> **规模不是把单卡的问题放大 N 倍，而是制造出一批单卡上根本不存在的新问题。**

- **01**：单卡上没有"并行策略"这个概念，也没有气泡；到了集群，**怎么切**成了第一决策。
- **02**：单卡跑 benchmark 时没有排队，所以"利用率越高越好"；到了服务，**利用率超过七成延迟就开始雪崩**——同一句直觉，两个相反的结论。
- **03**：单卡内部的数据搬运是确定的一跳；到了集群，**同一个 all-reduce 有环形和树形两种走法，选错在千卡规模上差一个数量级**。
- **04**：单卡的 MTBF 是五年，你一辈子可能遇不到一次；一万张卡凑在一起，**它变成了每天要处理好几次的日常**。

**所以这个模块和前八个模块的关系不是"更上层"，而是"换了一个量级之后，很多结论要重新推导"。** 这也是它值得单独成模块的理由。

## 和其它模块的接口

- **模块 01 附录 A2（FlashAttention 与 MoE 的瓶颈剖析）**：那里算出 prefill 与 decode 的算术强度差三个数量级。**本模块第 2 节讲这个差异在服务系统里造成了什么麻烦，以及它最终怎么变成了机柜里的两种硅片。** 另外那里只算了 FlashAttention 的时间收益，本模块第 1 节补上显存收益——**而显存这一笔决定了长上下文训练能不能成立。**
- **模块 03 第 2 节（四层互连地图）**：那一节给的是"哪种并行住哪一层"的定性判据，本模块第 1、3 节给出定量的通信账本与物理拓扑。
- **模块 04 第 5 节（与算法侧的接口）**：那一节讲算法决策沿栈传导，本模块给出它传导到系统层之后的具体形态——**GQA 在 kernel 层是"少读四分之三的字节"，在服务层是"并发数乘以八"。**
- **模块 04 附录 A1（藏延迟在每层各现一次身）**：那张表在本模块又多了两行——**流水线气泡里塞另一个方向的计算（DualPipe）、以及 chunked prefill 把算力受限与带宽受限的活混在同一批**。
- **模块 06（数据视角）**：本模块第 2 节的 PagedAttention 是那里"布局"这条线的服务层延伸；第 3 节的通信量最终落在模块 08 第 5 节那张每比特能量表上。
- **模块 08（微架构与物理实现）**：**第 4 节是模块 08 的下游**——分档、良率、温度降频、电压跌落这些物理现实，在集群里以 Xid、ECC 计数、落后者和静默数据损坏的形式出现。

## 阅读建议

- **做训练的**：01 → 03 → 04。这条线是"怎么切、怎么通、怎么不崩"。
- **做推理的**：02 → 04（§7 落后者与 §3 错误分类），03 可以只读 §2 的原语表。
- **做算法的**：先读 01 的 §2（显存账本）和 02 的 §2（KV 换并发），**这两笔账是你的每一个结构决策在系统层的定价单**。
- **和 infra 同事对话前**：读 01 的 §6（MFU）与 02 的 §8（四个指标的取舍）——**它们提供的是双方能共用的度量衡**，而没有共用的度量衡是绝大多数跨团队争论的真正原因。

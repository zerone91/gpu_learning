# 模块 08 · 微架构与物理实现（从 RTL 到硅）

前面的模块都停在**架构**这一层：SM 里有几个执行单元、脉动阵列怎么流数据、软件栈怎么把负载映射下去、封装怎么把硅片叠起来。但每一张框图落到硅片上，最终都变成同一种东西——**一堆标准单元连成的组合逻辑，中间被触发器切成一段一段，靠一棵时钟树同步，用金属线连起来，在一个固定的瓦数预算里工作**。

这个模块就讲这一层。它是**纵向串线**（和模块 06、07 一样不占主线顺序），但主题轴是**电路与工程约束**：不问"这个部件干什么"，只问三个问题——

> **它占多少面积？它的关键路径多长？它每次动作花多少能量？**

八节按"从小到大、从静到动"排：先把度量衡立起来（01），再拆两类最基本的器件（02 算术、03 存储），然后是把它们组织起来的两套系统（04 控制、05 互连），接着算总账（06 能量），最后是两个收束——当控制被彻底交给编译器时硬件长什么样（07 NPU），以及这一切是怎么被造出来的、造的过程又如何反向决定了架构（08 流程）。

## 八节怎么分工

| 节 | 打开的黑盒 | 收束点（一句话） |
| --- | --- | --- |
| 01 | "架构框图"与"硅片"之间那一层 | 频率被最长的一条组合逻辑路径定死；面积就是钱；同构复制是物理设计流程的产物 |
| 02 | 一个乘加单元 | 乘法器面积随尾数位宽**平方**下降——这是整个低精度浪潮的物理根源；矩阵单元省的是被 K 次乘法摊薄的"浮点税" |
| 03 | 一块 SRAM | bank 冲突是"一套外围电路服务一整块子阵列"的必然后果；**读一次寄存器比算一次乘加还贵** |
| 04 | warp 调度器与记分牌 | GPU 把依赖分析一半交给编译器（stall 控制位）、一半交给 6 个硬件屏障，砍掉了 CPU 的乱序机器 |
| 05 | 点与点之间的连线 | crossbar 面积随两端数量的**乘积**增长；搬运能量随距离跨越三个数量级 |
| 06 | 瓦数预算 | 现代 GPU 是功耗受限而非面积受限；真正"在算"的部分只占三成；频率是电流台阶的函数 |
| 07 | NPU 的 PE 与它的周边 | 控制责任交给编译器之后，控制逻辑只占 2% 面积——能效与灵活性是同一根杠杆的两头 |
| 08 | 制造流程 | 三到四年的周期、五成的良率、几千万的掩模，共同决定了架构必须同构、可屏蔽、渐进演化 |

## 一条贯穿全模块的主线

八节看起来在讲八个不相干的器件，但它们其实在反复验证同一件事：

> **在现代芯片上，"算"是便宜的，"把数据搬到能算的地方"和"决定该算什么"是贵的。**

- 第 02 节：一次 FP16 乘加的纯算术能量在零点几 pJ 量级。
- 第 03 节：从寄存器堆读一个操作数的能量与它同量级——**而一条 FMA 要读三个写一个**。
- 第 05 节：跨片到 L2 贵十倍，跨封装贵五十倍，跨节点贵三百倍。
- 第 06 节：整机口径下每次 FP16 乘加约 1.4 pJ，**真正的算术只占其中三成**；其余是搬运、时钟、漏电、接口。
- 第 04、07 节：控制的成本同样真实——GPU 用编译器提示和 6 个屏障把它压到很低，NPU 把它压到 2%。

**所以模块 02 讲的数据复用、模块 04 讲的算子融合、模块 06 讲的布局与搬运——它们不是"优化技巧"，它们是在直接操作这颗芯片的能量账本。** 这是本模块希望留下的最主要的一条直觉。

## 和其它模块的接口

- **模块 01（SIMT 核的物理实现）**：本模块 03、04 两节是它的电路版。occupancy 的物理定义（调度器手上就绪 warp 的个数、16 个槽位的时序来源）、bank 冲突的电路成因、SASS 控制位的硬件含义，都在这里。
- **模块 02（空间脉动架构）**：本模块第 07 节是它的电路版，补上了模块 02 没讲的三件事——累加器位宽怎么算、乒乓双缓冲的硬件形态、以及"不需要 barrier 但需要显式 flag"。
- **模块 03（两者交汇）**：第 02 节从电路角度补上了 Tensor Core 能效优势的另一半解释（浮点开销被 K 次乘法摊薄），与那里的数据流视角合起来才完整。
- **模块 04（软件优化栈）**：第 08 节给出了软件栈价值的经济学论证——硬件必然滞后算法两三年，中间的差距只能由软件填。
- **模块 06（数据视角）**：第 05 节的"每比特搬多远花多少能量"表，是模块 06 那条"数据的一生"的标价单。
- **模块 07（封装与存储的物理实现）**：两个模块在两处合流——第 06 节的功耗墙高度由模块 07 的热阻决定；第 08 节的良率账是模块 07 讲 chiplet 的经济学基础。

## 阅读建议

- **想补最缺的一块，按 01 → 03 → 06 读**。这三节合起来给出一套完整的度量衡（面积、延迟、能量），读完之后再看别的模块，很多"为什么这样设计"会自己浮出来。
- **只关心 GPU 的，读 01 → 02 → 03 → 04**；只关心 NPU 的，读 01 → 02 → 07。
- **和算法/框架同事讨论硬件时最有用的两节是 06 和 08**：一个给能量账，一个给时间账与经济账。

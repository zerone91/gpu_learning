# NPU 侧的微架构：脉动阵列的 RTL 形态与它必须配的那几样器件

> **所属模块**：模块 08 · 微架构与物理实现
> **状态**：🟨 学习中（第一版。知识截至 2026-08）
> **本节主旨**：模块 02 从数据流角度讲了脉动阵列，第 04 节讲了 GPU 把控制责任推给编译器之后省下了什么。这一节把这条轴推到终点：**当一颗芯片彻底放弃动态调度，它的电路长什么样、又必须额外配上哪几样器件才能真的跑起来。** 拆开之后会看到一个很干净的结论：**脉动阵列本身简单到近乎平庸——一个 PE 就是一个乘法器、一个加法器、三个寄存器，只和上下左右邻居连线；难的全在它的周边**：累加器要多宽（一笔可以精确算出来的位宽账）、数据怎么在计算的同时被预取进来（乒乓双缓冲的物理形态）、地址由谁生成（地址生成单元这个 GPU 上不存在的部件）、以及**没有硬件记分牌之后，流水线之间的同步靠什么**（显式的置位/等待标志，昇腾的六条流水线就是这套机制的教科书例子）。最后用 TPU v1 的面积分解收尾：**控制逻辑只占 2%，而 GPU 和 CPU 在这一项上要花掉的比例高出一个数量级——这就是"专用"两个字在硅面积上的兑现形式。**

## 1. 基础词汇：先把本节要用的词讲清楚

**PE（processing element，处理单元）**。脉动阵列里的一个格子。模块 02 讲过它的功能：存一个权重，接收左邻居传来的数据和上邻居传来的部分和，做一次乘加，把结果传给下邻居、把数据传给右邻居。**本节讲它的电路形态。**

**累加器（accumulator）**。存放"部分和"的寄存器或存储。在脉动阵列里，一列 PE 走下来累加出一个输出元素，这个逐步累加的值就住在累加器里。**它的位宽是本节要算的第一笔账。**

**便签存储（scratchpad memory）**。软件显式管理的片上存储，与 cache 的区别是**没有 tag 阵列、没有命中判断**——数据在哪里完全由软件（编译器）决定和跟踪。TPU 叫它统一缓冲（Unified Buffer），昇腾叫 UB / L1 Buffer。第 03 节讲过它省掉的是什么电路。

**双缓冲 / 乒乓（double buffering / ping-pong）**。把一块存储分成两半，计算单元在读其中一半的同时，搬运单元往另一半写；一个 tile 处理完就交换角色。**它是掩盖搬运延迟的最基本手段**，在 GPU 上对应模块 01 讲的 `num_stages` 软件流水。

**地址生成单元（AGU，address generation unit）**。一个专门算地址的硬件模块，内部是一组嵌套的循环计数器和步长寄存器。给它"起始地址、每维长度、每维步长"，它就能自己按顺序吐出一长串地址。**GPU 上没有独立的 AGU（地址由通用算术指令算），但 TMA 内部有一个，见第 04 节。**

**DMA 引擎（direct memory access engine）**。独立于计算单元、专门搬运数据的硬件。它接受一个**描述符**（描述源地址、目的地址、形状、步长的一个结构体），自己完成整批搬运，完成后置一个标志。**它是 NPU 上最重要的配套器件，因为计算单元本身不会访存。**

**流水线（pipe）在 NPU 语境下的含义**。注意这个词在 NPU 文档里的用法和模块 08 第 1 节讲的"流水线级"不同：这里指的是**几条可以并行推进的功能通道**，比如"矩阵计算流水线""向量计算流水线""搬运流水线"。它们各有自己的指令队列，可以同时工作。**几条流水线之间的顺序，需要软件显式同步——这是本节 §6 的主题。**

**静态调度（static scheduling）**。所有指令的执行时刻在编译期就被排定，硬件不做任何动态决策。模块 02 讲过它的好处（省掉全部控制硬件）和前提（延迟必须完全可预测）。

## 2. 一个 PE 的 RTL：它真的就这么简单

**先看代码形态。** 一个权重固定的 PE，用 Verilog 写出来的核心逻辑大约是这样（简化到只剩骨架）：

```verilog
module pe #(parameter DW = 8, AW = 32) (
  input clk, rst,
  input  [DW-1:0] a_in,      // 左邻居传来的激活值
  input  [AW-1:0] psum_in,   // 上邻居传来的部分和
  input  [DW-1:0] w_load,    // 权重装载通路
  input           w_en,      // 权重装载使能
  output reg [DW-1:0] a_out, // 传给右邻居
  output reg [AW-1:0] psum_out // 传给下邻居
);
  reg [DW-1:0] w;            // 常驻的权重

  always @(posedge clk) begin
    if (w_en) w <= w_load;               // 装权重阶段
    a_out    <= a_in;                    // 激活值原样右传（打一拍）
    psum_out <= psum_in + a_in * w;      // 乘加，结果下传
  end
endmodule
```

**核心就是那三行。** 综合之后它包含：一个 8×8 的乘法器（按第 02 节的 n²/2 估算，约 32 个全加器，加最后的进位传播加法器，合计几百个门）、一个 32 位加法器（约 1000 个门）、以及三组触发器（8 + 32 + 8 = 48 位，约 300 个门）。**合计约两千个门。**

**对照一下 GPU 的一条 FP32 通道**：光是 FMA 单元就一万几千个门（第 02 节），再加上它背后必须分摊的操作数收集器、寄存器堆端口、调度器份额、访存单元份额——**每条通道的等效成本在几万个门量级**。

**所以一个 int8 PE 的成本，大约是一条 GPU FP32 通道的百分之几。** 这个比例就是"专用架构算力密度高一个数量级以上"这句话的全部内容。要注意它由两个因素相乘得到：**数据位宽（8 位对 32 位，乘法器面积差三十多倍）**和**控制开销（PE 没有任何控制，GPU 通道要分摊一整套）**。**两者缺一，优势都会大打折扣**——这也解释了为什么当 GPU 也支持 int8/fp8 之后，两条路线的能效差距明显缩小了。

**物理设计上的优势，比逻辑上的优势更值得讲。** 脉动阵列在布局布线流程里几乎是最理想的结构：

1. **只有邻居连线。** 每个 PE 只连上下左右四个邻居，线长等于一个 PE 的尺寸（几十微米）。**没有任何长线**，因此没有第 05 节讲的 RC 平方律问题、不需要中继缓冲器、关键路径极短（就是一个乘法器加一个加法器，十几级门）。
2. **完美的规则性。** 一个 PE 做成一块小版图（甚至可以做成定制的紧凑布局），然后**直接边对边拼接（abutment）**成 256×256 的阵列——不需要布线工具去连，因为相邻 PE 的输出引脚和输入引脚位置就是对齐的。**这在物理设计上省掉的工作量是巨大的**（对照模块 08 第 1 节讲的 SM 硬核，那还要跑完整的布局布线）。
3. **面积利用率极高。** 规则阵列几乎没有布线拥塞造成的空隙，而复杂逻辑块的实际面积往往比标准单元面积之和大三到五成（那部分是布线占的）。

**关键路径短带来的选择权。** 既然关键路径只有十几级门，理论上这个阵列可以跑得很快。但真实的 TPU v1 只跑 700 MHz，后续代际也在 1 GHz 上下——**因为按第 06 节那张每瓦性能表，低频低压的工作点划算得多，而算力可以靠"摆 65536 个 PE"补回来。** 这是一次典型的"用并行度换频率"的取舍，而**脉动阵列的规则性正是让这种取舍成为可能的前提**：它的面积效率高到能摆下这么多单元。

**一个必须处理的物理问题：时钟怎么送到 65536 个 PE。** 一个 256×256 的 int8 阵列大约几个平方毫米，边长两三毫米。时钟从中心送到边角，光是线延迟就有几百皮秒，远超允许的偏斜。**处理办法是让时钟树和数据流方向一致地"斜"过去**——既然数据本来就是一拍传一格地流动，那么让时钟也按同样的方向逐级延迟（这叫"时钟随数据流"或斜时钟），相邻 PE 之间的相对偏斜就被控制住了。**这是一个只有在"数据流方向固定"的结构里才成立的技巧，通用逻辑用不了。**

## 3. 累加器位宽：一笔必须精确算的账

模块 02 讲过部分和沿着列往下累加，但没说累加器要多宽。这笔账很具体，而且算错了就是数值错误。

**设定**：int8 × int8 的乘法，阵列高度 K = 256（也就是一列有 256 个 PE，要累加 256 个乘积）。

1. **一次乘法的结果范围**：有符号 int8 的范围是 −128 到 +127。最大绝对值的乘积是 (−128) × (−128) = 16384，需要 **16 位**（有符号）表示。
2. **累加 256 次的最坏情况**：256 × 16384 = 4194304。表示这个数需要 **23 位**（有符号则 24 位）。**规律是：累加 K 次，位宽增加 log₂K 位。**
3. **所以理论下限是 24 位。** 实际设计通常取 **32 位**——因为 32 是一个存储与数据通路都对齐的宽度，多出来的 8 位余量还能容纳多个 tile 之间的再累加（当 K 大于阵列高度时，要分多轮累加，见模块 02 第 4 节的 tiling）。

**如果累加器只有 16 位会怎样：不是精度下降，是直接溢出出错。** 这是定点运算和浮点运算的一个关键区别——浮点溢出会变成无穷大或饱和，定点溢出会**回绕**（大正数变成负数），结果完全错乱且没有任何提示。**所以累加器位宽在定点 NPU 上是一个正确性参数，不是性能参数。**

**这笔账的两个连锁后果**：

**后果一：累加器存储的面积不小。** TPU v1 有 4 MiB 的累加器存储（对照它的统一缓冲是 24 MiB）——**累加器占了片上存储的六分之一**。原因就是位宽：输出结果如果是 int8，那么 256×256 的输出 tile 是 64 KB；但累加过程中它们都是 32 位，就是 256 KB，**四倍**。

**后果二：浮点阵列的累加器更麻烦。** 如果输入是 bf16 或 fp8，累加器通常用 fp32。这时"累加"不再是简单的整数加法，而是要走第 02 节讲的对阶-加-归一化-舍入那一整套。**所以浮点脉动阵列的 PE 比定点 PE 复杂得多**，这也是为什么早期 NPU（TPU v1、很多推理芯片）清一色是定点的——**定点阵列的 PE 简单到极致，是它能摆下几万个单元的前提。**

**一个对照：GPU 的 Tensor Core 也是 fp32 累加**（第 02 节讲过原因相同），但它的 K 只有 16 或 32，而脉动阵列的 K 是 128 或 256。**K 越大，累加器需要的额外位宽越多，但摊薄的浮点开销也越多**——这是同一枚硬币的两面。

## 4. 双缓冲与地址生成：让阵列不停下来的两样器件

脉动阵列本身不会停：只要每拍有数据从左边和上边进来，它就一直算。**问题是数据从哪来。**

**乒乓双缓冲的物理形态。** 把便签存储分成两个 bank（或者一块存储的两个地址区间），加一个由"当前相位"信号控制的多路选择器：

```
                ┌──────────┐
   DMA 写入 ───►│ Buffer A │──┐
                └──────────┘  │   ┌─────┐
                              ├──►│ MUX │──► 送进脉动阵列
                ┌──────────┐  │   └─────┘
   DMA 写入 ───►│ Buffer B │──┘      ▲
                └──────────┘         │
                                  相位信号（每个 tile 翻转一次）
```

**逐 tile 的时间线**，假设计算一个 tile 要 256 拍、搬运一个 tile 要 200 拍：

| 阶段 | Buffer A | Buffer B | 阵列在干什么 |
| --- | --- | --- | --- |
| 拍 0~199 | DMA 写入 tile 0 | 空闲 | **空转（流水线填充期）** |
| 拍 200~455 | 阵列读 tile 0 | DMA 写入 tile 1 | 算 tile 0 |
| 拍 456~711 | DMA 写入 tile 2 | 阵列读 tile 1 | 算 tile 1 |
| 拍 712~967 | 阵列读 tile 2 | DMA 写入 tile 3 | 算 tile 2 |

**从第二个 tile 起，搬运完全被计算盖住，阵列不再有空转。** 前提是"搬运时间 ≤ 计算时间"（这里 200 < 256，成立）；如果反过来，阵列就会等数据——**这就是模块 02 讲的"喂不饱"，在硬件上的精确含义是"乒乓的一侧还没填满，另一侧已经算完了"。**

**相位切换由谁控制？** 这是 NPU 和 GPU 的一个分水岭。GPU 上是运行时的（mbarrier 的到达触发消费者 warp 的唤醒，第 04 节）；**NPU 上通常是编译期就排定的**——编译器算准了"第 456 拍切换"，把切换动作作为指令序列的一部分发出去。**代价是编译器必须精确知道 DMA 的完成时间**，而这在真实系统里并不总是可预测（显存带宽会被别的请求抢占），所以实际设计里往往还是要有一个"等 DMA 完成标志"的同步点，见 §6。

**地址生成单元（AGU）：GPU 上不存在的部件。** 阵列每拍要吃进 256 个激活值，这些值在便签存储里的地址是什么？如果用通用指令算，光是地址计算就要占掉大量算力——**而 NPU 根本没有"通用指令"这个东西可用**。

所以 NPU 里配一个 AGU：内部是**一组嵌套的循环计数器和步长寄存器**。给它配置一个描述（比如"外层循环 64 次、步长 1024；中层循环 16 次、步长 64；内层循环 256 次、步长 1"），它就自己按序吐出地址：

```
addr = base + i0 * stride0 + i1 * stride1 + i2 * stride2
```

**物理上就是三个计数器、三个乘法器（或者更省的做法：三个累加器，每次只做加法不做乘法）、一个加法树。** 几千个门，换掉了成千上万条地址计算指令。

**这个部件解释了 NPU 编程模型的一个显著特征**：所有的数据访问都必须能表达成"多维嵌套循环 + 固定步长"的形式。**能表达成这个形式的负载（规整的卷积、矩阵乘）跑得极好；表达不了的（稀疏、gather/scatter、动态形状）就没有硬件通路可走**——这正是模块 02 讲的"形状税"和模块 04 讲的"映射问题"在硬件上的根源。

**AGU 和 GPU 的 TMA 是什么关系？** 本质是同一类器件（第 04 节讲 TMA 是一个"可编程的地址生成状态机"）。区别在于定位：**NPU 上 AGU 是唯一的地址来源，是必需品；GPU 上 TMA 是一个加速器，绕过它还可以用通用指令逐线程算地址。** 这个差别就是"专用"与"通用"在同一个器件上的不同角色。

## 5. DMA 引擎：计算单元不会访存，所以必须有它

**一个容易被忽略的事实：脉动阵列没有访存能力。** 它只有"从便签存储读、往便签存储写"的通路，而便签存储和外部显存之间的搬运，完全由 DMA 引擎负责。**这与 GPU 完全不同**——GPU 的每条通道都能自己发访存请求（LSU 是 SM 的标配）。

**DMA 引擎的内部结构**：

| 部件 | 作用 |
| --- | --- |
| 描述符队列 | 存放一批待执行的搬运任务，每个描述符包含源地址、目的地址、各维长度与步长 |
| 描述符解析器 | 读出描述符，配置内部的 AGU |
| 源侧 AGU + 目的侧 AGU | 分别生成读地址和写地址（**两侧的步长可以不同，这就是"搬运时顺便转置/重排"的硬件基础**） |
| 请求发射与在途跟踪 | 同时保持几十到上百个在途请求，用来掩盖显存延迟 |
| 重排序缓冲 | 显存返回的数据顺序可能与请求顺序不同，要重新排好再写入便签存储 |
| 完成标志逻辑 | 整批搬完后置一个标志位，供计算侧等待 |

**"在途请求数"是 DMA 引擎最关键的设计参数。** 按小定律（Little's Law）：要用 N 拍的延迟支撑 B 的带宽，在途的数据量必须达到 N × B。假设显存延迟 500 拍、每拍要 128 字节，那么在途数据量必须有 64 KB——**如果 DMA 只能同时保持 8 个 512 字节的请求（共 4 KB），实际带宽只能达到峰值的 1/16。** 这是一个纯粹的硬件参数，软件无法弥补。**模块 01 讲的"在途请求数（memory-level parallelism）"在 GPU 上靠多 warp 堆出来，在 NPU 上则是 DMA 引擎里一个写死的数字。**

**"搬运时顺便重排"是 NPU 的一个重要能力。** 因为源侧和目的侧的 AGU 可以配不同的步长，DMA 在搬的过程中就能完成转置、维度重排、甚至简单的 padding。**这在 GPU 上要靠专门的 kernel 或 shared memory 里的 swizzle 来做（模块 06 第 2 节），在 NPU 上是搬运器件的内建功能——省掉的是一整趟数据往返。**

## 6. 没有记分牌之后：显式同步是什么电路

这是本节和第 04 节呼应最紧的一段。**GPU 用 6 个硬件屏障跟踪变长延迟的操作；NPU 连这 6 个都没有，那么"矩阵计算要等搬运完成"这件事靠什么保证？**

**答案是：靠软件显式发出的置位与等待指令，硬件只提供一组标志寄存器。**

**以昇腾 DaVinci 架构为例**（它是这套机制讲得最清楚的公开例子）。一个 AI Core 内部有多条并行推进的流水线：

| 流水线 | 干什么 |
| --- | --- |
| Scalar | 标量运算、循环控制、发出配置 |
| Cube | 矩阵计算（16×16×16 的矩阵单元） |
| Vector | 向量运算（激活函数、归一化、逐元素运算） |
| MTE1 / MTE2 / MTE3 | 三条搬运流水线，分别负责不同存储层级之间的数据传输 |

**这几条流水线各有自己的指令队列，各自独立推进——硬件不检查它们之间的数据依赖。** 如果 MTE2 正在把数据搬进 L1 Buffer，而 Cube 已经开始读同一块地址，**硬件不会拦，结果就是读到旧数据**。

**所以必须靠显式同步**，指令形式是一对：

- `set_flag(pipe_src, pipe_dst, flag_id)`：由源流水线发出，表示"我这一段做完了"。
- `wait_flag(pipe_src, pipe_dst, flag_id)`：由目的流水线发出，表示"等源流水线的那个标志置位"。

**物理形态极其简单**：一组标志寄存器（比如每个流水线对之间 4 个标志位）。`set_flag` 是把某一位置 1；`wait_flag` 是让这条流水线的指令发射逻辑挂起，直到那一位为 1，然后自动清零。**这就是全部——几十个触发器加一点使能逻辑，对比 GPU 那 6 个带计数器的屏障还要更简单。**

**一个具体的指令序列**，做"搬入一个 tile 然后矩阵乘"：

```
MTE2:  搬 tile 0 到 L1
MTE2:  set_flag(MTE2, Cube, 0)        ← 告诉 Cube：tile 0 到位了
Cube:  wait_flag(MTE2, Cube, 0)       ← Cube 挂起，直到标志置位
Cube:  矩阵乘 tile 0
MTE2:  搬 tile 1 到 L1（另一半乒乓）   ← 与上面的矩阵乘并行进行
Cube:  set_flag(Cube, MTE2, 1)        ← 告诉 MTE2：tile 0 的 buffer 我用完了
MTE2:  wait_flag(Cube, MTE2, 1)       ← MTE2 等着才能覆盖那半 buffer
```

**注意这段序列里有两个方向的同步**：搬运通知计算"数据到了"，计算通知搬运"buffer 空了"。**缺任何一个都会出错**——缺前者读到旧数据，缺后者搬运覆盖掉正在被读的数据。**这就是乒乓双缓冲在没有硬件保护时的完整代价：每个方向每一轮都要一对置位/等待。**

**这套机制的性质值得说清**：

- **硬件成本几乎为零**，这是它存在的全部理由。
- **正确性责任 100% 在软件**。少写一个 `wait_flag`，程序不会报错，会**偶发地算错**——而且因为时序依赖，这种错误极难复现和调试。**这是 NPU 编程最主要的一类事故。**
- **性能责任也在软件**。多写一个 `wait_flag` 不会错，但会把本可并行的两条流水线串起来。**所以 NPU 的算子开发有很大一部分工作量是在"同步够不够"和"同步是不是太多"之间调"。**

**这段内容让第 04 节那条轴走到了终点**：CPU 用硬件（乱序 + 记分牌）自动处理所有依赖；GPU 用软件处理固定延迟、用 6 个硬件屏障处理变长延迟；**NPU 全部交给软件，硬件只留几十个触发器。** 省下来的面积去了哪里，下一节的表会给答案。

**为什么必须配一个向量单元。** 一个纯矩阵阵列算不完任何一个真实网络——激活函数、归一化、softmax、逐元素加、量化与反量化，全都不是矩阵乘。所以 NPU 一定要在矩阵单元旁边配一个**向量单元**（SIMD 形态，宽度典型是几百比特到几千比特）。**两者之间的数据通路是关键设计点**：矩阵单元的输出（32 位累加值）要经过量化/缩放变成低精度，再交给向量单元或写回便签存储。**这条通路做得好不好，直接决定了"矩阵乘 + 激活"这种最常见的融合能不能不落盘完成。** 模块 03 讲 Tensor Core 时说的"NVIDIA 赌真实负载不是纯矩阵乘"，在 NPU 这边的对应答案就是这条通路——**不是不做，而是用一条专门的通路做，而不是像 GPU 那样让两类计算共享同一片寄存器。**

## 7. 面积去哪了：TPU v1 的分解，和它说明的事

前面每一节都在说"省下来的面积变成算力"。用一颗真实芯片的面积分解来验证。TPU v1（Google 在 2017 年 ISCA 论文里公开了 die 的面积构成）：

| 模块 | 面积占比 |
| --- | --- |
| 统一缓冲（24 MiB 便签存储） | 约 29% |
| 矩阵乘单元（256×256 的 int8 脉动阵列） | 约 24% |
| 累加器存储（4 MiB） | 约 6% |
| 激活流水线（向量单元） | 约 6% |
| 显存接口（DDR3 控制器与 PHY） | 约 3% |
| PCIe 接口 | 约 3% |
| 其它 I/O 与杂项 | 约 1% |
| **控制逻辑** | **约 2%** |

**最该盯着看的是最后一行：控制逻辑只占 2%。**

对照第 04 节那张 CPU/GPU 控制通路的表：CPU 高性能核要花掉相当大比例的面积在分支预测器、重排序缓冲、重命名表、调度窗口上；GPU 虽然砍掉了这些，但仍要为每个 SM 配调度器、指令缓存、操作数收集器、记分牌。**TPU 把这一项压到 2%，靠的正是本节讲的每一件事：没有动态调度、没有依赖检查、地址由 AGU 生成、同步由软件显式发出。**

**另外两个值得注意的数字**：

- **存储（统一缓冲 + 累加器）合计 35%，超过了计算阵列的 24%。** 这印证了模块 02 的核心论点——**脉动阵列的瓶颈从来不是算力，是喂数**。片上存储不够大，tiling 就要切得更碎、外部带宽压力就更大。
- **计算阵列只占 24%。** 也就是说，即使是一颗"把面积几乎全给计算"的芯片，真正做乘加的部分也只占四分之一。**这与第 06 节那张功耗表的结论一致：无论按面积算还是按功耗算，"计算"都只占三成上下，其余全是让计算得以发生的支持系统。**

**这张表的最终含义**：所谓"专用架构的能效优势"，**不是因为它的乘法器更好**（乘法器人人都一样），而是因为**它把支持系统的开销压到了极限**。而压缩的手段只有一个——**把不确定性从硬件里赶出去，交给编译器**。代价则是模块 02 和模块 04 反复讲的那些：形状税、动态形状难、新算子上线周期长。**能效和灵活性在这里是同一根杠杆的两头，没有第三种选择。**

## 8. 开发者视角：NPU 微架构在软件侧的三个通道

| 物理事实 | ① 源码拨盘 | ② 编译器回执 | ③ Profiler 探针 |
| --- | --- | --- | --- |
| 阵列尺寸固定（如 16×16×16 或 256×256） | 张量各维按阵列尺寸对齐；不齐就 padding | 编译器报告 tiling 方案与 padding 比例 | 矩阵单元利用率（有效 MAC / 总 MAC）——这项低就是形状税 |
| 累加器位宽固定 | 量化方案要保证累加不溢出（K 大时尤其注意） | 量化工具的溢出检查 | 数值异常（回绕导致的大误差），无专门计数器 |
| 乒乓双缓冲要求搬运时间 ≤ 计算时间 | 调 tile 大小：tile 越大计算越久、越容易盖住搬运，但便签存储装不下 | 编译器给出的缓冲分配报告 | 各流水线的时间线视图——看 Cube 是否有等待 MTE 的空窗 |
| 流水线之间靠显式标志同步 | 手写算子时的 `set_flag`/`wait_flag` 配对；用高层算子语言（如 TileLang 类）由编译器生成 | 编译器的同步插入日志 | **流水线时间线图是 NPU 调优的核心视图**——比 GPU 的计数器直观得多 |
| 地址必须是"嵌套循环 + 固定步长"形式 | 避免动态索引、gather/scatter；用规则的切分 | 无法表达时编译器直接报错或回落到低效路径 | 回落路径通常表现为标量流水线利用率异常高 |
| 计算单元不会访存，全靠 DMA | 显式的搬入搬出语句；搬运粒度要够大以摊薄启动开销 | 编译器生成的 DMA 描述符数量 | 搬运流水线的带宽利用率与在途请求数 |

**一个具体排查场景**：某算子的 Cube 单元利用率只有 30%，看时间线发现 Cube 有大量空窗，且空窗都紧跟在 `wait_flag(MTE2, Cube, ...)` 之后。**结论直接：搬运跟不上计算，乒乓失效。** 对策有三条，按代价从小到大：增大 tile 让计算时间变长（如果便签存储装得下）、减少搬运量（提高复用/换布局）、增加搬运并行度（用多条 MTE 流水线分担）。**注意第一条对策在 GPU 上的对应物是"提高 occupancy"，两者动机相同（掩盖延迟），但手段完全不同——GPU 靠多线程，NPU 靠大 tile。**

## 9. 最新架构落点（知识截至 2026-08）

- **纯脉动阵列越来越少，混合形态成为主流。** 现代 NPU 很少是一个巨大的单一阵列，而是**多个中等尺寸的矩阵单元 + 强大的向量单元 + 灵活的搬运引擎**。原因是 §7 那张表暴露的问题：单一大阵列的形状税太重（模块 02 第 5 节），而中等尺寸的多个单元可以并行处理不同的 tile，利用率高得多。昇腾的 AI Core（Cube 是 16×16×16 的小单元，一个芯片上有很多个 Core）就是这个路线。
- **向量单元的地位持续上升。** 大模型时代的算子里，注意力的 softmax、各种归一化、以及 MoE 的路由，都是非矩阵计算，且占比不低。**几年前"矩阵单元占绝对主导"的设计正在向"矩阵与向量能力更均衡"调整**——这在方向上是向 GPU 靠拢。
- **同步机制在向"半自动"演进。** 完全手写 `set_flag`/`wait_flag` 的门槛太高、事故太多，所以厂商都在推更高层的编程模型（昇腾的 Ascend C、以及各类基于 tile 抽象的领域语言），由编译器自动插入同步。**这不改变硬件，改变的是谁来承担那份责任。** 这条线和模块 04 讲的 Triton/TileLang 是同一个方向。
- **GPU 与 NPU 在微架构上持续相互靠近**：GPU 加了 TMA（专用地址生成状态机）、mbarrier（轻量同步）、TMEM（专用累加存储）、异步矩阵指令——**每一项都是在向 NPU 的做法学习**；NPU 则在加强向量单元、支持更灵活的形状、引入更多运行时弹性——**向 GPU 学习**。第 04 节那条"控制责任从硬件到编译器"的轴上，两边都在往中间移动。
- **一个观察窗口**：Google TPU 从 v1 到最新代际的面积分配变化（如果有公开数据），特别是控制逻辑和向量单元的占比——**这两个数字的走向，直接反映了"专用"这条路线在大模型时代还能守多严。**

## 11. 术语卡

### PE 的 RTL 形态与边对边拼接（abutment）
**定义**：一个脉动阵列的处理单元在代码上只有三行核心逻辑——权重寄存器、激活值打一拍右传、部分和加乘积后下传，综合出来约两千个门。因为只连上下左右邻居、引脚位置天然对齐，成千上万个 PE 可以直接边对边拼接成阵列，不需要布线工具去连。
**为什么存在**：这种极端规则的结构同时带来三个物理好处——没有长线所以关键路径极短、没有布线拥塞所以面积利用率高、不用跑布局布线所以工程量极低。这是脉动阵列能摆下几万个单元的根本前提。
**语境例句**："这个阵列是 abut 出来的，不走 P&R。" —— 意思是：物理实现上它是把一块小版图复制拼接，省掉了整套布局布线流程——这也是为什么它的面积效率远高于同等规模的通用逻辑。

### 累加器位宽账（K 次累加加 log₂K 位）
**定义**：定点脉动阵列里部分和寄存器的宽度必须容纳最坏情况的累加结果。int8 × int8 的乘积需要 16 位，累加 K 次再增加 log₂K 位，K = 256 时理论下限 24 位，工程上取 32 位。
**为什么存在**：定点运算溢出会回绕（大正数变成负数），是静默的正确性错误而不是精度损失。所以累加器位宽是正确性参数，不能按性能需要削减。这也是累加器存储占 TPU v1 片上存储六分之一的原因——它比输出数据宽四倍。
**语境例句**："K 开到 512，累加器位宽够不够？" —— 意思是：累加次数翻倍要多一位，要确认硬件的累加器还有余量，否则会静默溢出——量化方案设计时必须一起算这笔账。

### 乒乓双缓冲的硬件形态
**定义**：把便签存储分成两半加一个由相位信号控制的多路选择器，计算单元读一半时搬运单元写另一半，每个 tile 处理完交换角色。有效的前提是"搬运一个 tile 的时间不超过计算一个 tile 的时间"。
**为什么存在**：脉动阵列只要有数据就一直算，不会自动等待。要让它不空转，下一块数据必须在当前块算完之前就位。双缓冲是用两倍存储换取搬运与计算完全重叠的最简结构。
**语境例句**："乒乓没盖住，Cube 在等 MTE。" —— 意思是：搬运时间超过了计算时间，阵列出现空窗——对策是增大 tile（拉长计算时间）、减少搬运量、或增加搬运并行度。

### 地址生成单元（AGU）
**定义**：由一组嵌套循环计数器和步长寄存器构成的专用硬件，配置好每维的长度与步长后自动按序吐出地址。约几千个门，替代了成千上万条地址计算指令。NPU 上它是唯一的地址来源，GPU 上对应的是 TMA 内部的状态机。
**为什么存在**：脉动阵列没有通用指令可以用来算地址，而张量访问的地址模式恰好是规则的多维嵌套循环，做成专用计数器极其划算。副作用是：**表达不成"嵌套循环加固定步长"的访问模式，硬件上就没有通路**。
**语境例句**："这个 gather 在 AGU 上表达不了。" —— 意思是：访问地址不是规则步长，只能回落到标量流水线逐个算，性能掉一个数量级——这是稀疏和动态形状在 NPU 上难做的硬件根源。

### 显式流水线同步（set_flag / wait_flag）
**定义**：NPU 上几条并行流水线（矩阵、向量、多条搬运）之间没有硬件依赖检查，顺序完全靠软件发出的成对指令保证：源流水线做完置一个标志位，目的流水线挂起等待该位置位后自动清零。硬件形态只有几十个触发器。
**为什么存在**：硬件依赖跟踪（哪怕是 GPU 那种只有六个屏障的简化版）仍要付面积和关键路径。既然 NPU 的执行时序本来就在编译期排定，索性把这份责任完全交出去，把硬件成本压到接近零。
**语境例句**："这里少了一个 wait_flag，偶发算错。" —— 意思是：搬运还没完成计算就开始读，读到旧数据。这类错误不报错、依赖时序、极难复现——是 NPU 手写算子最主要的事故类型。

### 便签存储与统一缓冲（scratchpad / unified buffer）
**定义**：软件显式管理的片上存储，没有 tag 阵列也没有命中判断，数据放在哪里完全由编译器决定和跟踪。TPU 称统一缓冲，昇腾称 UB / L1 Buffer。TPU v1 里它占了 29% 的 die 面积，是最大的单一模块。
**为什么存在**：当数据流在编译期就能算准时，硬件的动态判断纯属浪费——省掉 tag 阵列、比较器和路选择逻辑之后，同样面积能装下更多数据。代价是软件必须自己管好每一块数据的位置和生命周期。
**语境例句**："片上就这么大 buffer，tile 只能切到这么大。" —— 意思是：便签存储容量直接约束了 tiling 方案，而 tile 大小又决定了搬运能不能被计算盖住——这是 NPU 算子设计的第一约束。

## 1. 基础词汇：先把本节要用的词讲清楚

**SRAM（static random-access memory，静态随机存取存储器）**。用逻辑工艺的晶体管做成的存储器，特点是**只要供电就一直保持数据**（不需要像 DRAM 那样周期性刷新），速度快（读一次几百皮秒到几纳秒），但单个比特要用 6 个晶体管，密度远低于 DRAM。**芯片上所有的"片上存储"——寄存器堆、shared memory、各级 cache、各种缓冲队列——底层全都是 SRAM。**

**位线与字线（bitline / wordline）**。SRAM 阵列是一个二维网格：**字线是横的**，一根字线控制一整行存储单元的"开关"；**位线是竖的**，一整列存储单元共用一对位线，用来把数据读出去或写进来。读一次的动作是：**选中一行（拉高一根字线）→ 这一行所有单元同时把自己的值送上各自的位线 → 从位线上读走想要的那几列**。记住这个结构，本节后面所有的约束——包括 bank 冲突——都是它的直接推论。

**灵敏放大器（sense amplifier）**。位线上挂着几百个存储单元，寄生电容很大；单元里那几个小晶体管驱动能力很弱，没法把这么大的电容迅速拉到满幅电压。所以实际做法是：读的时候单元只把位线拉低**几十毫伏**，然后用灵敏放大器——一个高增益的差分比较电路——把这个微弱差值放大成完整的 0 或 1。**它是 SRAM 读通路里最关键也最难设计的一块模拟电路。**

**外围电路（periphery）**。存储阵列本身之外的所有东西：行译码器（把地址翻译成"拉高哪一根字线"）、列多路选择器、灵敏放大器、写驱动器、预充电电路、时序控制。**在真实的 SRAM 宏里，外围电路往往占三到五成面积**——这个比例是本节很多结论的来源（比如"bank 数翻倍，面积涨两成"）。

**存储宏（memory macro / SRAM macro）**。晶圆厂或 IP 供应商提供的、参数化生成的一块完整存储器（比如"1024 字 × 128 位、单端口"），交付形式是一块尺寸固定、引脚位置固定的硬核（模块 08 第 1 节讲过硬核）。**芯片设计工程师不自己画 SRAM，而是从编译器（memory compiler）里"生成"一块**。这件事有个重要推论：**可选的配置是离散的、有限的**，所以架构里的存储尺寸往往是些看起来很整的数字，因为别的尺寸生成不出来或者代价很差。

**端口（port）**。一块 SRAM 每拍能独立进行几次访问。单端口（1RW）每拍只能读或写一次；双端口（1R1W）能同时读一个地址、写另一个地址；多端口以此类推。**端口数是 SRAM 成本的主要驱动因素之一**，§4 会算这笔账。

**bank（存储体）**。把一块大存储切成若干块**各自独立、各有一套外围电路**的小存储，每块叫一个 bank。切成多个 bank 的目的是提高并行度：不同 bank 可以在同一拍各做各的访问。**注意 bank 内部仍然是一拍只能开一行字线**——这就是冲突的来源。

## 2. 一个比特：6T 单元和读它的那 300 皮秒

**6T 单元的结构**。六个晶体管分成两组：

- **四个组成两个首尾相接的反相器**。反相器就是"输入 0 输出 1、输入 1 输出 0"的最简单逻辑门。把两个反相器的输出接到对方的输入上，就构成一个**双稳态电路**：如果 A 点是 1，它逼着 B 点是 0，而 B 点是 0 又逼着 A 点是 1——**互相锁死，只要不断电就一直保持**。这就是"静态"的含义，也是数据存放的地方。
- **另外两个是访问晶体管**，一边一个，把 A 点和 B 点分别接到两根位线（BL 和 BLB，互补的一对）上，它们的栅极接在字线上。**字线低电平时这两个开关关断，单元与外界隔绝；字线高电平时接通，可以读或写。**

```
        BL                     BLB
         │                      │
      ───┤ 访问管        访问管 ├───
         │                      │
         A ──┬──[反相器]──┬── B
             └──[反相器]──┘
         （A 与 B 恒为互补，锁死存 1 位）
             ▲
             │
          字线 WL（控制两个访问管）
```

**读一次的完整过程**，按时间顺序（数量级参考，先进工艺下的一次 SRAM 访问总共几百皮秒）：

| 阶段 | 发生了什么 | 大致耗时 |
| --- | --- | --- |
| 1. 预充电 | 把 BL 和 BLB 都充到电源电压，两根线电位相等 | 上一拍尾部完成 |
| 2. 地址译码 | 行译码器把地址翻译成"第几根字线"，这是一棵与门树 | 50~100 ps |
| 3. 字线驱动 | 把选中的那根字线拉高。字线要横跨整行（几百个单元的栅极），负载大 | 50~100 ps |
| 4. 位线放电 | 存 0 的那一侧通过访问管缓慢把位线拉低。**因为单元晶体管弱、位线电容大，只拉低 50~100 毫伏就得停** | 100~200 ps |
| 5. 灵敏放大 | 灵敏放大器被使能，把这几十毫伏的差值放大成满幅的 0/1 | 50 ps |
| 6. 列选与输出 | 从这一行的几百位里选出需要的那 32 或 64 位，驱动到宏的输出引脚 | 50~100 ps |

**两个必须记住的结论从这张表里掉出来**：

**第一，读 SRAM 的延迟主要不花在"存储"上，而花在译码、驱动长线、和放大微弱信号上。** 这解释了为什么小 SRAM 快、大 SRAM 慢——大阵列的字线更长、位线挂的单元更多，第 3、4 步都变慢。

**第二，第 4 步"只拉低几十毫伏就停"是一个刻意的设计选择。** 如果等位线完全放电到 0，不需要灵敏放大器，但那要多花好几倍时间和能量（因为要给整根位线的电容充放电一个满幅电压）。**用一块模拟电路换掉几倍的时间和能量**——这个取舍是所有 SRAM 的标准做法，也是为什么灵敏放大器是必需品而不是优化。

**为什么 6T 单元难以继续缩小。** 单元里的六个晶体管尺寸不能随便定，它们要同时满足两个互相打架的要求：**读的时候不能把存的值冲翻**（访问管不能太强，否则读操作本身会把单元的状态改掉，叫读扰动），**写的时候要能把值改过来**（访问管又不能太弱，否则写不进去）。这两个要求给晶体管的相对强弱定了一个越来越窄的窗口，而工艺越先进、晶体管之间的随机偏差越大，窗口越难满足。**结果就是 SRAM 单元面积在最近几代工艺上几乎停止缩小**（§8 给数字）。

**8T 单元：寄存器堆的选择。** 在 6T 基础上再加两个晶体管，构成一个**独立的读通路**：读的时候不通过访问管碰单元内部节点，而是由内部节点去驱动这两个新晶体管，再拉动一根单独的读位线。好处是**读操作完全不会扰动存储的值**，于是上面那个"读稳定 vs 可写"的矛盾解开了，电压可以压得更低。代价是每个单元多两个晶体管、多一根字线和一根位线，面积大约 **+30% 到 +40%**。**寄存器堆这种访问极其频繁、又需要低压运行的地方，通常用 8T 或更多端口的变体。**

## 3. 从一个单元到一块存储：为什么必须切成子阵列

**先算一笔账说明"一整块"为什么不行。** 假设要做一块 64 KB 的 SRAM，按 128 位一行组织，那就是 4096 行 × 128 列。

- **位线的长度**：每根位线要挂 4096 个单元。每个单元给位线贡献的寄生电容假设是 C₀，总电容就是 4096·C₀。位线放电时间正比于这个电容——**比挂 256 个单元的情况慢 16 倍**。
- **字线的长度**：每根字线要驱动 128 个单元的栅极，这个还好。但如果为了减少行数把它做成 512 行 × 1024 列，字线就要横跨 1024 个单元——**驱动这么大的负载又需要一整串越来越大的缓冲器**。

**结论是行数和列数都不能太大，所以真实做法是切成子阵列（sub-array 或 mat）**：把这块 64 KB 切成比如 16 块 4 KB 的子阵列，每块 256 行 × 128 列，各自带一套译码器、灵敏放大器和预充电电路。访问时先用高位地址选中某一块子阵列，只激活它，其余保持休眠。

**这个结构带来三个重要的连锁反应**：

1. **能量上的好处**：一次访问只激活一块子阵列，只有那 256 行里的一根字线被拉高、只有那 128 对位线在动，其余 15 块完全不耗动态功耗。**如果不切，一次访问要动 4096 行的位线，能量大十几倍。**
2. **外围电路的开销**：16 块子阵列就是 16 套译码器和灵敏放大器。**这就是"外围占三到五成面积"的由来**，也是模块 08 第 1 节那笔"bank 数翻倍、面积涨两成"的账的物理依据。
3. **并行访问的可能性**：既然每块子阵列有自己完整的外围电路，那么让不同子阵列在同一拍**各自访问不同的地址**，在物理上是现成的——只要给它们各自的地址通路和数据通路。**做到这一步，子阵列就变成了 bank。**

**bank 冲突的物理定义现在可以精确给出了**：一个 bank 是一块有自己译码器的子阵列，**它一拍只能拉高一根字线，也就是只能访问一行**。如果同一拍有两个请求落到同一个 bank 的**不同行**，硬件没有第二套译码器和灵敏放大器可用，只能把它们排成两拍做——**这就是冲突，它是"一套外围电路服务一整块子阵列"这个面积决策的直接后果，而不是设计疏忽。**

**同一个 bank 的同一行则不冲突**，因为那一行的数据本来就被整行读出来了，多个请求可以从同一次读出的结果里各取所需——这正是 shared memory 的"广播"行为（一个 warp 里多个线程读同一个地址时不冲突）的物理来源。**"同 bank 不同行才冲突，同 bank 同行是广播"这条规则，看电路结构就是自明的。**

**shared memory 为什么是 32 个 bank、每个 4 字节宽。** 现在这个数字不再是任意的：**一个 warp 是 32 个线程，如果它们各读一个 4 字节的 word，最理想的情况是这 32 个 word 落在 32 个不同的 bank 上，一拍全部完成**。bank 数少于 32，warp 的一次访问就注定要拆成多拍；bank 数多于 32，多出来的 bank 在这种最常见的访问模式下用不上，白付外围电路的面积。**32 这个数字是"硬件宽度对齐软件执行宽度"的典型例子——bank 数被 warp 宽度定死了。**

**一个可以逐拍跟踪的冲突例子。** 一个 warp 的 32 个线程访问 `float A[]`，线程 i 访问 `A[i * 33]`（模块 06 讲的经典 padding 技巧的反例，这里故意用 33 看会发生什么）。bank 编号 = 字地址 mod 32：

| 线程 i | 字地址 i×33 | bank 号 = 地址 mod 32 |
| --- | --- | --- |
| 0 | 0 | 0 |
| 1 | 33 | 1 |
| 2 | 66 | 2 |
| … | … | … |
| 31 | 1023 | 31 |

**32 个线程正好落在 32 个不同的 bank 上，无冲突，一拍完成。** 换成步长 32（即 `A[i * 32]`）：

| 线程 i | 字地址 i×32 | bank 号 |
| --- | --- | --- |
| 0 | 0 | 0 |
| 1 | 32 | 0 |
| 2 | 64 | 0 |
| … | … | … |
| 31 | 992 | 0 |

**32 个线程全落在 bank 0 的 32 个不同行上——32 路冲突，要 32 拍才做完，慢 32 倍。** 这就是"给二维数组的行加一个 padding 元素"这个老技巧的全部物理原理：把步长从 32 改成 33，让访问在 bank 之间转起来。**电路上的原因就一句话：bank 0 只有一套译码器，32 行只能一行一行地开。**

## 4. 寄存器堆：GPU 里最大的那块 SRAM

**先看规模，这个数字通常会让人吃惊。** Hopper 架构每个 SM 的寄存器堆是 **256 KB**（65536 个 32 位寄存器）。H100 有 132 个 SM，所以整片 GPU 的寄存器堆合计 **约 33 MB**。作为对照，H100 的 L2 cache 是 50 MB。**寄存器堆的总容量和 L2 是同一个量级**——它绝不是"几个小格子"，它是芯片上面积占比极高的一块存储。

**再看它要提供的带宽，这个数字更吓人。** 以一个 SM 子分区为例（32 条通道），要维持每拍发射一条 FFMA：

- **读**：每条 FFMA 要 3 个源操作数，每个 4 字节，32 条通道 → 3 × 4 × 32 = **384 字节/拍**。
- **写**：1 个结果 → 4 × 32 = **128 字节/拍**。

按 2 GHz 算，单个子分区的寄存器堆读带宽就是 384 B × 2 G = **768 GB/s**；一个 SM 四个子分区就是 3 TB/s；整片 GPU 是 **400 TB/s 量级**。**这个数字是 HBM3 带宽（约 3.35 TB/s）的一百多倍**——寄存器堆是全芯片带宽最高的存储，没有之一。

**现在是核心问题：怎么用一块 SRAM 同时提供 3 个读和 1 个写？**

**方案 A：真多端口。** 给每个存储单元做 3 套读通路和 1 套写通路。代价：每加一个端口，单元就要多几个晶体管、多一根字线、多一根（或一对）位线。**面积不是线性增长而是接近平方增长**，因为在先进工艺上单元面积主要由金属线的间距决定，而端口数直接决定线的根数：端口翻倍则横线和竖线都翻倍，面积约四倍。一个 3R1W 的单元大约是 1RW 单元的**三到四倍面积**。256 KB 变成 1 MB——**不可接受**。

**方案 B：分 bank + 操作数收集器（operand collector）。** 这是 GPU 的实际做法。把寄存器堆切成若干个（典型是 4 个或 8 个）**单端口**的 bank，然后：

1. 一条指令进入发射阶段后，先进入一个叫**操作数收集器**的缓冲结构，里面为这条指令预留了几个操作数槽位。
2. 一个仲裁器（arbiter）每拍检查所有等待中的指令需要哪些寄存器、这些寄存器在哪个 bank，给每个 bank 挑一个请求发出去。
3. 各 bank 各自读出一个值，通过一个交叉开关（crossbar）送到对应指令的对应槽位。
4. 某条指令的所有操作数槽位都填满之后，它才被放行去执行单元。

**这个方案的实质是：用"多花几拍"换掉"多端口的面积"。** 一条指令的三个操作数可能是分三拍从三个 bank 读出来的，但因为有几十个 warp 在等着发射，这些拍在不同指令之间是重叠的——**总吞吐仍然可以维持每拍一条，只是每条指令的延迟长了几拍**。这是模块 01 讲"用多 warp 掩盖延迟"的又一个具体落点。

**寄存器 bank 冲突：一个编译器要解决的物理问题。** 如果一条指令的三个源操作数恰好都在同一个 bank（比如 bank 编号 = 寄存器号 mod 4，而指令用了 R4、R8、R12，全是 bank 0），仲裁器一拍只能给这条指令读出一个，要三拍才凑齐。**所以 GPU 编译器在寄存器分配时，会刻意把常一起使用的寄存器分到不同 bank**——这是一个纯粹为了迁就物理结构而存在的编译优化，软件工程师看不到，但它真实影响性能。NVIDIA 的 SASS 里甚至有寄存器复用缓存（reuse cache）机制，把上一条指令读过的操作数暂存下来，供下一条指令直接用，进一步减少对寄存器堆的访问——**其动机同样是省掉一次昂贵的 SRAM 读。**

**能量视角：读一次寄存器比算一次乘加还贵。** 这是本节最反直觉、也最重要的一个事实。粗略的量级对照（同一工艺下）：一次 FP32 的乘加约 **1~2 pJ**；而从一块几十 KB 的 SRAM 里读出 32 位，大约 **1~5 pJ**。一条 FFMA 要读 3 个操作数、写 1 个结果，**光是访问寄存器堆的能量就和计算本身相当甚至更高**。

**这条事实是理解现代加速器设计的一把钥匙**：

- 它解释了 Tensor Core 为什么值得——一条矩阵指令用一次寄存器读支撑了几十次乘加，**把"访存能量 / 计算能量"这个比值改善了一个数量级**。
- 它解释了脉动阵列为什么能效高（模块 02）——PE 之间的数据直接从邻居的流水寄存器传过来，**根本不经过大寄存器堆**。
- 它也解释了寄存器复用缓存、累加器专用存储（TMEM）这类看起来很琐碎的特性为什么值得做进硬件。

## 5. Cache：tag 阵列、并行比较、和它们的物理代价

寄存器堆是"按编号直接访问"，不需要判断命中。cache 多了一件事：**给一个地址，判断它在不在里面、在哪一路**。这件事的电路实现决定了 cache 的几个关键参数。

**结构：两块 SRAM。** 一块 **data 阵列**存真正的数据，一块 **tag 阵列**存每条缓存行对应的高位地址。以一个 32 KB、128 字节缓存行、4 路组相联的 L1 为例：

- 缓存行总数 = 32768 / 128 = 256 条。
- 组数 = 256 / 4 = **64 组**，所以地址里要用 6 位来选组（index）。
- 缓存行内偏移用 7 位（128 = 2⁷）。
- 剩下的高位就是 tag，假设地址 48 位，tag 就是 48 − 6 − 7 = **35 位**。

**查一次的物理过程**：

1. 用地址的 index 位（6 位）去 tag 阵列里选中一组，**这一组的 4 个 tag 被同时读出来**（这就是为什么 tag 阵列的一行要存 4 个 tag——组相联的"组"在物理上就是 tag 阵列的一行）。
2. **4 个 35 位比较器同时工作**，把读出的 4 个 tag 和请求地址的 tag 位比对。比较器就是逐位异或再做一棵或非树，35 位的比较器约 6 级门延迟。
3. 4 个比较结果里最多有一个为真（命中），它同时充当**路选择信号**，去控制 data 阵列输出端的 4 选 1 多路选择器。
4. 若全部为假，就是缺失（miss），发请求到下一级。

**为什么路数不能无限加。** 从上面的过程看，**N 路组相联就需要 N 个比较器同时工作、以及一个 N 选 1 的多路选择器**。路数翻倍，比较器面积和功耗翻倍，多路选择器多一级延迟。而且**每次访问都要把整组 N 个 tag 全读出来**——哪怕最终只有一个命中，那 N 次 tag 读的能量都花掉了。所以路数是一个典型的 PPA 折中：路数多则冲突缺失少（性能好），但面积、功耗、命中延迟都涨。真实设计收敛在 **4 到 16 路**，全相联（N = 缓存行总数）只在极小的结构里出现，比如 TLB，那里会用**内容寻址存储器（CAM）**——一种每个存储单元自带比较器、能一拍并行比对所有条目的特殊 SRAM，**面积是普通 SRAM 的两三倍**，只有条目数很少时才划算。

**shared memory 和 L1 在物理上是同一块 SRAM。** 从 Volta 起，每个 SM 里有一块统一的片上 SRAM（Hopper 是 256 KB），运行时按配置切分成 shared memory 和 L1 两部分。**这在物理上很自然**：两者都是同样的子阵列，区别只在**外围有没有接上 tag 比较通路**——被划为 shared memory 的部分直接按地址访问（软件自己负责知道数据在哪），被划为 L1 的部分要经过 tag 查找。所以模块 01 讲的"shared memory 是软件管理的缓存"，在电路上的精确含义是：**它是同一块 SRAM 阵列，只是绕过了 tag 判断这条通路**——也因此它的访问延迟比 L1 短几拍，且没有缺失的可能。

**ECC：为什么开了会掉性能。** 片上 SRAM 会因为宇宙射线、α 粒子等造成随机的位翻转（软错误）。数据中心产品必须防护，标准做法是 **SECDED（单错纠正、双错检测）**：每 64 位数据附加 8 位校验码（一种扩展的汉明码），**存储开销 12.5%**。代价有三：

1. **面积**：多出 12.5% 的 SRAM。
2. **延迟**：读的时候要跑一遍校验矩阵的异或树（约几级门延迟），加在关键路径上。
3. **写的时候可能要"读-改-写"**：如果只写 64 位数据块中的一部分（比如只写 1 个字节），校验码必须基于完整的 64 位重新计算，所以硬件必须**先把整块读出来、拼上新数据、重算校验、再写回**。**一次部分写变成了一次读加一次写**——这就是"开 ECC 掉性能"最主要的机制，也是为什么细粒度的散乱写在开 ECC 的卡上代价更高。

## 6. 三者怎么连：SRAM 直接喂计算单元吗？

前面把 SRAM（§2、§3）、寄存器堆（§4）、cache（§5）逐个拆开了，但一直没回答一个看架构图时最容易犯迷糊的问题：**shared memory 和各级 cache，到底是接在寄存器堆上，还是直接接在计算单元上？**

**先给结论。** 在经典的 GPU 数据通路里，**算术单元的操作数只能来自三个地方：寄存器堆、指令里的立即数、常量存储体**。shared memory 和各级 cache **不直接连到算术单元**——它们的数据必须先由一条访存指令搬进寄存器堆，才能参与计算。

**为什么必须这样，模块 08 第 02 节 §4 那张接线图已经给了答案**：每条 lane 的 FMA 输入端口，物理上就接在自己那一片寄存器上。要让 shared memory 直接喂 ALU，就得再拉一整套"从 SRAM 分发到 32 条 lane"的交叉开关（面积按模块 08 第 05 节的平方律算），还要解决"寄存器和 shared 同时想用同一个操作数端口"的仲裁。**代价高于收益，所以经典设计让寄存器堆当唯一的操作数集散地。**

一次典型的 tile 计算，数据走的是这条链：

```
 HBM ─► 显存控制器 ─► L2 ─► L1 / shared memory
                                  │
                        [LDS / LDG 等访存指令]
                                  ▼
                              寄存器堆  ──►  操作数收集器 ──► FMA / Tensor Core
                                  ▲                                  │
                                  └──────────── 结果写回 ◄───────────┘
```

**注意这条链上寄存器堆被穿过了两次**：数据搬进来时写一次，计算时读一次。而 §4 算过，**读一次寄存器的能量和做一次乘加是同量级的**。于是"想办法绕开寄存器堆"就成了过去几代 GPU 硬件最持续的一条演进主线——下面按时间顺序看它是怎么被一步步绕开的。

**旁路零：常量存储体与统一寄存器（一直就有）。** 有一类数据天然不需要 per-lane 的分发网络——**整个 warp 的 32 条 lane 用的是同一个值**（kernel 参数、循环边界、张量的步长）。这种值只要用一根线广播给 32 条 lane 即可，不需要交叉开关。所以硬件允许指令的某个源操作数**直接写成常量存储体里的地址**，在 SASS 里长这样：

```
IMAD R2, R0, c[0x0][0x168], R3     ; 第二个源操作数直接取自常量存储体
```

这条通路完全不占寄存器。Turing 之后还增加了一小组**统一寄存器（uniform register）**，专门存 warp 内所有线程相同的值，同样是为了把这类数据从主寄存器堆里挪出去。**"把 kernel 参数放常量、把 warp 内一致的量交给编译器识别"这条老建议，省的就是主寄存器堆的容量和端口。**

**第一步（Ampere）：异步拷贝，全局显存直接进 shared memory。**

- **旧做法**：`LDG` 把数据从显存读进寄存器，再用 `STS` 从寄存器写进 shared memory。**数据在寄存器堆里穿了一个来回**，而且从发出 `LDG` 到 `STS` 完成的整段时间里，这些寄存器一直被占着——它们还压着 occupancy。
- **新做法（`LDGSTS`，即 `cp.async`）**：一条指令让访存单元把数据从 L2 或显存**直接写进 shared memory**，寄存器堆完全不参与。
- **省下的是三样**：一次寄存器写加一次寄存器读的能量、一批寄存器的占用（于是 occupancy 松了）、以及若干条指令的发射槽位。

**第二步（Hopper）：TMA，连地址都不用算。** 模块 08 第 04 节讲过 TMA 是一个地址生成状态机。从数据通路的角度看，它把"全局显存 ↔ shared memory"这一整段搬运彻底交给一个 DMA 引擎，**warp 只负责发起和等待**，寄存器堆和算术通道全程不参与。

**第三步（Hopper）：矩阵指令直接从 shared memory 取操作数。** `wgmma` 允许用一个**共享内存描述符**指定 A、B 操作数在 shared memory 里的位置，硬件自己去取——**这是计算单元的输入第一次不经过寄存器堆**。

**为什么矩阵单元能做到而普通 FMA 做不到？** 因为两者的取数模式性质不同：矩阵单元是一整块结构，一次要的是一个**形状规则、地址连续可推的 tile**，可以给它配一条专用的取数通路；而普通 FMA 的三个源操作数是**每条 lane 各自任意的寄存器号**，除了走寄存器堆没有别的办法。**规则性换来了旁路资格——这是本模块反复出现的那条规律的又一次出现。**

不过 Hopper 这一步只走了一半：**累加器仍然住在寄存器堆里**，所以模块 03 讲的"累加器是寄存器堆第一大户"在 Hopper 上依然成立。

**第四步（Blackwell）：TMEM，把累加器也搬出去。** 给 Tensor Core 配一块专属存储放累加值。至此，**一次矩阵乘的输入和输出都可以完全不碰通用寄存器堆。**

**把四步并成一张表，走向一目了然**：

| 数据通路 | 引入代际 | 过不过寄存器堆 |
| --- | --- | --- |
| 全局 → 寄存器 → shared（`LDG` + `STS`） | 一直有 | **过两次** |
| 全局 → shared（`LDGSTS` 异步拷贝） | Ampere | **不过** |
| 全局 ↔ shared（TMA） | Hopper | **不过** |
| shared → 矩阵单元（`wgmma` 描述符） | Hopper | **输入不过**，累加器仍过 |
| 矩阵累加值住 TMEM | Blackwell | **都不过** |
| 普通 FMA、向量运算、地址计算 | 一直 | **必须过** |
| warp 内一致的值（常量存储体 / 统一寄存器） | 一直有 | **不过** |

**这张表可以浓缩成一句话：能规则化、能批量化、或者全 warp 一致的数据流，正在被逐个挪出寄存器堆；留给寄存器堆的，是那些每条 lane 各不相同、编译期无法预测的标量操作数。**

**NPU 的对照：它根本没有这一级。** 脉动阵列的 PE 从便签存储直接取数（模块 08 第 07 节），中间没有"寄存器堆"这个集散地——每个 PE 自己只有一两个流水寄存器。**所以 GPU 花了四代硬件去做的"绕开寄存器堆"，NPU 从第一天起就不存在这个问题。** 反过来说，GPU 保留寄存器堆换来的是"每条 lane 可以取任意地址、算任意东西"的灵活性。**又一次是同一根杠杆的两头。**

**最后澄清一个看图时的常见误解：L1 不是"给 ALU 供数的缓存"，而是"给访存指令供数的缓存"。** 算术单元从不去查 L1，它只认寄存器。所以：

- L1 命中率影响的是**访存指令的完成时间**，进而影响 warp 什么时候能解除等待（模块 08 第 04 节的硬件屏障），**不直接影响算术指令的速度**。
- profiler 里的"L1 吞吐"量的是**访存单元与 L1 之间**那条通路的忙闲，不是"计算单元取数的速度"。
- 因此看到"L1 命中率很高但 kernel 还是慢"并不矛盾——瓶颈可能在访存指令的条数本身、在合并度、或者根本就在算术管线上。

## 7. 开发者视角：这些电路在软件侧的三个通道

| 物理事实 | ① 源码拨盘 | ② 编译器回执 | ③ Profiler 探针 |
| --- | --- | --- | --- |
| 一个 bank 一拍只能开一行字线 | shared memory 的 padding（数组行宽 +1）、swizzle 布局（模块 06） | 无直接回执；`cuobjdump` 能看到 `LDS`/`STS` 的地址计算方式 | Nsight Compute 的 **shared memory bank conflict** 计数器与 `wavefronts` 比值 |
| 寄存器堆分 bank，操作数要收集 | 无直接拨盘；`__launch_bounds__` 限制寄存器数会间接改变分配 | SASS 里的**寄存器复用标志**（`.reuse`）——编译器在告诉硬件"这个操作数上条指令刚读过" | 无专门计数器；表现为 issue stall 里的 "Short Scoreboard" 或发射效率下降 |
| 寄存器堆是全片最大的 SRAM，读它很贵 | 减少每线程寄存器数、用矩阵指令提高每次读的复用 | `-Xptxas -v` 打印每线程寄存器数 | occupancy 分析里的寄存器限制项 |
| shared memory 与 L1 是同一块 SRAM | `cudaFuncSetAttribute` 设置 shared 容量、`cudaFuncSetCacheConfig` 调整切分 | 编译器报告静态 shared 用量 | L1 命中率 与 shared 吞吐两项此消彼长 |
| 算术单元只认寄存器；shared/L1 不直连 ALU | 用异步拷贝 / TMA 让搬运绕开寄存器；把 warp 内一致的量放常量存储体 | SASS 里 `LDGSTS`、`UTMAPF`/`UTMALDG` 等指令，以及 `c[0x0][...]` 形式的常量操作数 | 寄存器用量（`-Xptxas -v`）与 achieved occupancy 一起看：搬运改成异步后寄存器应明显下降 |
| 组相联查找要并行比 N 个 tag | 无拨盘（硬件参数） | 无 | L1/L2 命中率、以及 sector 利用率（模块 01-04） |
| ECC 的部分写要读-改-写 | 尽量做整块的、对齐的写（一次写满 32 字节 sector） | 无 | 显存写吞吐低于理论值、且写放大明显时的第一嫌疑 |

**一个具体排查场景**：某个 kernel 的 shared memory 吞吐只有峰值的 1/8，但 bank conflict 计数器显示冲突率不高。**这时要怀疑的不是冲突，而是访问粒度**——如果每个线程只读 4 字节但访问模式让硬件必须发多个 wavefront，或者用了 `LDS.64`/`LDS.128` 却没对齐，实际的字线开启次数会远多于预期。**这类问题只有把"一次访问 = 开一根字线、读一整行、选出需要的列"这个物理图像放在脑子里，才能推出正确的对策。**

## 8. 最新架构落点（知识截至 2026-08）

- **SRAM 停止缩小，这是最近几年芯片架构最重要的一条底层趋势。** TSMC 的 SRAM 位单元面积：N5 约 **0.021 µm²**，N3 约 **0.0199 µm²**（仅缩小约 5%），**N3E 回到 0.021 µm²（相对 N5 零缩小）**。同期逻辑密度仍在提升。后果是**片上存储在 die 面积里的占比逐代上升，缓存变成了越来越贵的东西**。
- **业界的三条应对路线**都能在产品上看到：**（一）把缓存挪到另一颗 die 上**——AMD 的 3D V-Cache 把 SRAM die 用混合键合叠到 CCD 上（模块 07 第 1 节讲的纵向方向），让缓存用便宜的老工艺做、还不占逻辑 die 的面积；**（二）换单元结构**——CFET（把 N 管和 P 管垂直堆叠的晶体管结构）被寄望于打破 6T 单元的面积僵局，但 SRAM 里 N 管和 P 管数量不对称（典型 4N/2P），CFET 的收益打了折扣；IBM 在 2026 年 VLSI 上报告的堆叠沟道（nanostack）单元宣称单元高度可降 40% 以上，属于**研究阶段**；**（三）少用缓存**——把片上存储做成软件显式管理的便签存储（scratchpad）而不是 cache，省掉 tag 阵列和比较器，这正是 NPU 阵营（TPU 的 unified buffer、昇腾的 UB/L1）的一贯选择。
- **NVIDIA 主线的存储容量变化**：从 A100（每 SM 192 KB 统一 L1/shared、40 MB L2）到 H100（每 SM 256 KB、50 MB L2）到 Blackwell，**每 SM 的片上 SRAM 增长非常克制**，远慢于算力增长。这不是设计保守，正是 SRAM 不缩小这条物理约束的直接结果。同时 Blackwell 给 Tensor Core 加了专属的 **TMEM**，属于"与其做大通用存储，不如给最耗端口的那个用户单独开一块专用存储"的思路。
- **HBM 侧的对照**：模块 07 第 2 节讲的 HBM4 base die 改用逻辑工艺制造，其中一个动机正是可以在 base die 上放更多 SRAM 和逻辑。**存储与逻辑的边界正在被封装技术重新划分**，这是模块 07 和本模块交汇的地方。

## 10. 术语卡

### 6T 单元与灵敏放大器
**定义**：SRAM 存一个比特的最小电路，由两个首尾相接的反相器（四个晶体管，互相锁死保持数据）加两个访问晶体管构成。读取时单元只能把位线拉低几十毫伏，必须由灵敏放大器——一个高增益差分比较电路——放大成完整的 0 或 1。
**为什么存在**：位线上挂着几百个单元、寄生电容很大，而单元里的小晶体管驱动能力很弱。等位线完全放电要多花几倍时间和能量，所以用一块模拟电路把这个过程截断在几十毫伏处。
**语境例句**："这块 SRAM 的读延迟主要在字线驱动和灵敏放大上。" —— 意思是：延迟花在把地址翻译成字线、驱动长线、以及放大微弱电压差上，而不是"存储"本身——所以小阵列快、大阵列慢。

### bank（存储体）与 bank 冲突
**定义**：一块大 SRAM 被切成的、各自带一套译码器和灵敏放大器的独立子阵列。每个 bank 一拍只能拉高一根字线，即只能访问一行。同一拍里两个请求落到同一 bank 的不同行就必须排队，这就是 bank 冲突；落到同一 bank 的同一行则可以广播，不冲突。
**为什么存在**：不切分会让位线过长、访问又慢又费电；切分后每块可以独立访问，天然获得并行度。但给每块配一套完整外围电路已经很贵（外围占三到五成面积），不可能再给每块配第二套，所以"一拍一行"是面积决策的必然后果。
**语境例句**："这个访问模式 32 路 bank 冲突。" —— 意思是：一个 warp 的 32 个线程全落在同一个 bank 的 32 个不同行上，硬件要串行 32 拍——通常靠给数组行宽加一个 padding 元素让访问在 bank 之间转起来。

### 操作数收集器（operand collector）
**定义**：位于寄存器堆和执行单元之间的一组缓冲槽位与仲裁逻辑。指令发射后先进入收集器，仲裁器每拍给各个寄存器 bank 各挑一个请求，读出的值经交叉开关送进对应槽位；某条指令槽位填满后才放行去执行。
**为什么存在**：一条 FFMA 要同时读三个源操作数，而做成真三读端口的 SRAM 面积会涨三到四倍（端口数决定金属线根数，面积近似平方增长），完全不划算。收集器用"多花几拍"换掉了多端口的面积，靠众多待发射 warp 之间的重叠把吞吐补回来。
**语境例句**："这条指令三个操作数撞同一个 bank，收集器要三拍才凑齐。" —— 意思是：寄存器分配没把常一起用的寄存器分散到不同 bank，编译器本该避免——这是一个纯粹迁就物理结构的编译优化。

### tag 阵列与并行比较
**定义**：cache 里与数据阵列并列的另一块 SRAM，存每条缓存行的高位地址。查找时用地址的中间位选中一组，把这一组的 N 个 tag 同时读出，用 N 个比较器并行比对，命中信号同时充当数据阵列输出端的路选择信号。
**为什么存在**：cache 与便签存储的唯一结构差别就在这里——cache 允许软件不知道数据放在哪，代价是每次访问都要用硬件判断"在不在、在哪一路"。这块判断电路（tag 阵列 + N 个比较器 + N 选 1 多路选择器）就是 cache 相对便签存储多付的面积和延迟。
**语境例句**："NPU 用便签存储不用 cache，省掉 tag 那一套。" —— 意思是：因为负载的数据流是编译期就能算准的，不需要硬件动态判断，于是把 tag 阵列和比较器的面积全省下来变成更多存储容量。

### 8T 单元与读扰动
**定义**：在 6T 基础上增加两个晶体管构成独立读通路的 SRAM 单元。读操作不再通过访问管碰到存储节点，因而不会扰动存储的值（读扰动），代价是面积增加三到四成。寄存器堆等高频访问、需要低压运行的结构常用它。
**为什么存在**：6T 单元的访问管要同时满足"读时别把值冲翻"和"写时改得动"两个互相矛盾的强弱要求，这个窗口随工艺推进越来越窄，也限制了工作电压的下探。8T 把读通路解耦，直接消掉这个矛盾。
**语境例句**："寄存器堆用的是 8T，能压到更低电压。" —— 意思是：多花的面积换来的是电压下探空间，而功耗与电压平方成正比，所以在访问最频繁的结构上这笔账划算。

### 绕开寄存器堆的通路（异步拷贝 / 描述符取数）
**定义**：一类让数据不经过通用寄存器堆的数据通路。代表是 Ampere 的异步拷贝（`LDGSTS`，全局显存直接写进 shared memory）、Hopper 的 TMA（整段搬运交给 DMA 状态机）、Hopper 矩阵指令的共享内存描述符（计算单元自己去 shared memory 取操作数）、以及 Blackwell 的 TMEM（累加值住专用存储）。
**为什么存在**：读一次寄存器的能量与做一次乘加同量级，而经典通路里数据要穿过寄存器堆一进一出；被占用的寄存器还压着 occupancy。凡是取数模式规则、可批量化、或全 warp 一致的数据流，都值得单独拉一条专用通路把寄存器堆绕开。
**语境例句**："这块用异步拷贝搬，寄存器压力能降一大截。" —— 意思是数据不再从显存经寄存器中转到 shared memory，省下的寄存器直接换成更高的驻留 warp 数——省的不只是能量，还有 occupancy。

### SECDED 与读-改-写
**定义**：单错纠正、双错检测的纠错码，每 64 位数据附加 8 位校验位，存储开销 12.5%。当软件只写这 64 位中的一部分时，硬件必须先把整块读出、拼上新数据、重算校验位、再写回，一次部分写因此变成一读一写。
**为什么存在**：片上 SRAM 和显存会因粒子撞击发生随机位翻转，数据中心规模下这是必然事件而非小概率。纠错是必需品，读-改-写则是"校验码基于整块计算"这一数学性质的必然代价。
**语境例句**："开 ECC 之后这个散乱写的 kernel 慢了三成。" —— 意思是：每次不满一整块的写都触发了读-改-写，写请求数翻倍——对策是把写合并成对齐的整块写。

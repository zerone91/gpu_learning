# 数据流复用分类（weight / output / row-stationary）

> **所属模块**：模块 02 · 空间/脉动架构
> **状态**：🟨 学习中（第一版：本质/费曼 + 开发者视角 + 最新架构，知识截至 2026-01）
> **一句话主旨**：矩阵乘有三种数据（权重 W、激活 A、部分和 psum），但 PE 的本地寄存器只装得下一种——**"让谁钉在原地不动（stationary）、让谁流动"是脉动/空间架构的第一设计决策**。钉住谁，谁的复用就免费（零搬运）；流动的两方则付搬运费。三种经典选择（WS/OS/RS）没有绝对优劣，**最优解取决于负载里"谁的复用机会最大"**——这正是 §04 访存"复用放大器"思想在空间架构上的版本。

## 1. 核心概念

### 1.1 费曼起点：三种货物，一个仓位

矩阵乘 `C = A·B` 里每个 MAC 涉及三样数据：
- **W（权重）**：`B` 的元素——每个权重被 **M 个不同的行**用到（M 次复用机会）；
- **A（激活）**：`A` 的元素——每个激活被 **N 个不同的列**用到（N 次复用机会）；
- **psum（部分和）**：`C` 的中间累加值——每个输出要被累加 **K 次**（K 次复用机会）。

而一个 PE 的本地寄存器**极小**（§01），只装得下其中一种。于是必然要选：

> **谁"住"在 PE 里（stationary，零搬运成本），谁"流"过阵列（每拍搬一格）。** 住下的那个，它的全部复用都发生在原地、完全免费；流动的两个，复用靠"流经一排 PE 顺路被各用一次"（§01 的"复用在电线里"）实现，但进出阵列的边缘带宽要为它们买单。

这和 §04 的"复用放大器"是同一个问题的空间版：GPU 里问"数据放寄存器还是 shared 还是 L2"，空间架构里问"数据钉在 PE、流过电线、还是回全局 buffer"。**记这一层对应，两个世界就通了。**

### 1.2 三种经典数据流

**① Weight-Stationary（WS，权重驻留）—— TPU 的选择**

- **钉住**：每个 PE 存一个 `w[k][j]`，整个阵列装下 B 的一个 K×N 块。
- **流动**：激活从左流入、部分和向下流出（§01/§02 画的就是它）。
- **免费的复用**：**权重**——加载一次，被流过的 M 行激活反复使用 M 次。
- **付费**：激活要横穿阵列，psum 要竖穿阵列。
- **最优场景**：**权重复用机会大**（batch/M 大）且权重换得少（大 K×N 块、推理场景权重恒定）。
- ⚠️ **短板**：M 小（如 decode，A2！）时权重装填的开销摊不掉——**又一次遇到 A2 的"小 M 问题"**，同一个病在 WS 上表现为"权重刚钉好没用几次就得换"。

**② Output-Stationary（OS，输出驻留）**

- **钉住**：每个 PE 负责一个 `c[i][j]`，psum **在原地累加 K 次不动**。
- **流动**：A 从左流入、W 从上流入，二者在 PE 处相遇相乘。
- **免费的复用**：**部分和**——K 次累加零搬运，且**精度友好**（累加器不必在低位宽的电线上来回跑）。
- **付费**：A 和 W 都要流。
- **最优场景**：**K 很大**（深度累加多），psum 搬运/读写是主要成本时。
- 典型：许多早期 NPU、以及 GPU tensor core 的累加器语义（accumulator 常驻寄存器/TMEM——**Blackwell 的 TMEM 本质就是把 OS 思想做进 SIMT**，模块 03 会点破）。

**③ Row-Stationary（RS，行驻留）—— Eyeriss（MIT）提出**

- **钉住**：不钉单一数据，而是把**一行卷积计算的"1D 原语"**映射到一个 PE——让 W 行、A 行、psum 的复用**在 PE 内部及近邻同时兼顾**。
- **动机**：卷积有比 GEMM 更丰富的复用（滤波器复用、输入滑窗复用、psum 累加），单钉一种都浪费其余；RS 是**总搬运能量最小化**的折中解。
- **代价**：控制/映射复杂得多，需逐层用 mapper 搜最优映射。
- **地位**：学术标杆（能效分析框架的起点），产品中纯 RS 少见，但它建立的**"按能量算账选数据流"方法论**成了整个领域（含 Timeloop 等 mapper 工具）的地基。

### 1.3 复用账怎么算：一张表

设 GEMM 为 M×K×N，阵列 P×P。各数据总搬运量（量级，忽略边界）：

| 数据流 | W 搬运 | A 搬运 | psum 搬运 | 免费项 |
| --- | --- | --- | --- | --- |
| **WS** | **K·N（一次）** | M·K ×(N/P 次重流) | M·N ×(K/P 次进出) | W |
| **OS** | K·N ×(M/P) | M·K ×(N/P) | **M·N（原地累加）** | psum |
| **RS** | 介于其间，逐层 mapper 搜 | | | 折中 |

> 🔑 **判读法**：看负载里**哪个矩阵/量的"体积×复用次数"最大**，就钉谁。
> - 推理 decode（M 小、W 大）：W 的搬运是天文数字 → **钉 W**（但 M 小又摊不平——所以真正的答案是 batch，回到 A2 的 M*≈300）。
> - 训练/大 K 深累加：psum 进出最贵 → **钉 psum（OS）**。
> - 卷积（多种复用并存）：**RS/mapper 搜**。

### 1.4 和 GPU GEMM tiling 是同一个问题

对照 §02/§04/A2 的 CUTLASS GEMM：累加器 C-tile **常驻寄存器**（=OS），A/B tile 流经 shared（=流动数据），权重在 shared 里被 block 内反复读（=WS 的影子）。**GPU 的"tiling + 谁放哪级存储"，就是软件版的数据流选择**——只是 GPU 用存储层级（寄存器/shared/L2）表达"驻留深度"，空间架构用物理位置（PE 内/电线上/边缘 buffer）表达。**模块 04 的"映射问题"会把这两个说法统一成一个**。

## 2. 关键机制 / 为什么这样设计

- **为什么必须三选一（或折中）**：PE 本地存储是纳秒级/字节级的，装不下两种；且"流动方向"由连线物理决定，一旦选定数据流，**连线就为它优化**（WS 阵列的竖向线是 psum 专用的）——这就是"数据流=架构"的含义：**选择数据流不是软件配置，而是硅片的形状**（可重构数据流架构如早期 SambaNova 试图打破这一点，代价是互连面积）。
- **能量视角（Eyeriss 的核心论证）**：搬运一个 32b 数据的能量：本地寄存器 ~1×，跨 PE ~2×，全局 buffer ~6×，DRAM ~200×。**计算本身（MAC）只占个位数**。所以数据流选择本质是**能量优化问题**——把最大宗的搬运压到最便宜的层级。这个论证和 §01"算得起、取不起"完全同源，只是从"时间/带宽"换成了"能量"记账。

## 3. 开发者视角

- **用 TPU/NPU 时**：数据流已被硅片焊死（TPU=WS），你的拨盘是**让负载贴合它**——加大 batch（凑 M）、让 K×N 块对齐阵列、推理时权重量化以装下更大的块。XLA/CANN 的编译报告里"权重装填次数 / 阵列利用率"就是 WS 贴合度的直接读数。
- **写 GPU kernel 时**：你在**软件里**做同样的选择——`BLOCK_M/N/K` 和"谁驻寄存器谁走 shared"就是你的数据流决策（§1.4）；Triton autotune 搜的就是这个空间。
- **做架构评估/读论文时**：**Timeloop/Accelergy、MAESTRO** 这类 mapper 工具，输入负载形状+硬件描述，输出各数据流的能量/延迟账——就是 §1.3 那张表的自动化版本。听到"dataflow / mapping space exploration"，指的就是这件事。

## 4. 最新架构落点（时效锚点 · 知识截至 2026-01）

- **TPU（v4→v7）**：坚持 WS + 大阵列；靠编译器（XLA）和超大 batch 场景把 WS 的账做平。
- **NVIDIA Tensor Core**：**OS 血统**——累加器驻留（寄存器→Blackwell 的 TMEM），A/B 流经 shared/寄存器；TMEM 等于把"psum 钉住"做成了专用 SRAM（模块 03 详）。
- **昇腾 DaVinci Cube**：16³ 立体阵列，一次吃 16×16×16 的 GEMM 块，数据流上接近"块级 OS"。
- **Eyeriss/RS 的遗产**：产品少用纯 RS，但 **mapper 方法论**（Timeloop 等）成了所有 NPU 设计/编译器的标配环节。
- **可重构数据流**（SambaNova RDU、Tenstorrent）：试图让数据流成为**编译期可选项**而非硅片定死——灵活性与面积/频率的新权衡。

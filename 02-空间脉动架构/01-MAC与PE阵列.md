# MAC / PE 单元与二维阵列

> **所属模块**：模块 02 · 空间/脉动架构（NPU 本体）
> **状态**：🟨 学习中（第一版：本质/费曼 + 开发者视角 + 最新架构，知识截至 2026-01）
> **一句话主旨**：脉动阵列是 SIMT 的"反面范式"——不是一堆各自取指、靠海量并发藏延迟的可编程核，而是**一片只会做乘累加的极简格子（PE），用直连的电线把数据像心脏泵血一样一拍一拍传过去**。复用发生在**电线里**、控制被摊薄到**整个阵列 + 所有时间**，于是它把几乎全部晶体管都给了 MAC——这是稠密矩阵乘能效之王的根源，代价是死板。

## 1. 核心概念

### 1.1 MAC：深度学习计算的原子

**MAC = Multiply-ACcumulate（乘累加）**：`acc += a * b`。矩阵乘、卷积本质都是**一堆乘积求和**，所以 MAC 是 DL 算力的原子操作。一个 MAC 单元 = 一个乘法器 + 一个加法器。

### 1.2 PE：阵列的格子，以及它"缺"什么

**PE（Processing Element，处理单元）** = 阵列里的一个格子，内部只有：
- 一个 **MAC 单元**；
- 几个**极小的本地寄存器**（存一个权重，或一个部分和 partial sum）；
- 输入/输出端的**流水寄存器**（把数据传给邻居）。

**关键在于它「缺」什么**——对照 §01 的 SIMT lane，PE **没有**：取指、译码、warp 调度器、大寄存器堆、访存单元。它不"执行指令"，它**每一拍就做同一件事：把流经它的两个数相乘、累加、传出去**。

> 🔑 **PE vs SIMT lane 的根本区别，在"谁喂操作数、谁定时序"**：
> - **SIMT lane**：由 warp 调度器每拍从**大寄存器堆**里取操作数喂给它（§01）；时序**运行时动态**决定。
> - **PE**：操作数来自**上/左邻居的电线**，按**设计期定死的节拍**流入；不需要任何调度。**控制被"编进了连线和时钟"。**

### 1.3 二维阵列与"泵"数据

PE 排成二维网格（TPU 的 MXU 是 **128×128**、昇腾 DaVinci 的 Cube 是 16×16×16、Tensor Core 内部是个更小的阵列）。每个 PE 只和**相邻** PE 连线（通常向右、向下）。数据**从边缘流入**，横着/竖着穿过阵列。

以**权重固定（weight-stationary，TPU 式）**的矩阵乘 `C = A·B` 为例：

```
          激活 A 从左边流入（每拍进一列，逐行错开 skew）
          a20  a10  a00 →┌─────┬─────┬─────┐
          a21  a11  a01 →│ w00 │ w01 │ w02 │  ← 权重预先"钉"在每个 PE 里
          a22  a12  a02 →│ w10 │ w11 │ w12 │
                         │ w20 │ w21 │ w22 │
                         └──┬──┴──┬──┴──┬──┘
                       部分和向下累加、流出 → C 的各列
```

**每个 PE 每拍同时做三件事**：① 从左邻居收一个激活、从上邻居收一个部分和；② 做一次 MAC（`psum += a * w_local`）；③ 把激活传给右邻居、把新部分和传给下邻居。数据像波纹一样**斜着**涌过阵列。

### 1.4 systolic = 心脏搏动；skew = 让数据"准点相遇"

**"systolic（脉动）"取自心脏收缩（systole）**——数据随时钟一拍一拍被"泵"过阵列，全阵列同步搏动。

因为一个数据要**逐级**传过一排 PE，第 i 行的输入必须**比第 i-1 行晚一拍进入（skew，错峰）**，才能保证"某个激活和某个权重在正确的 PE、正确的那一拍相遇"。所以你看脉动阵列的输入总是排成一个**斜三角**喂进去的——这不是巧合，是为了让所有乘法在时空上对齐。

## 2. 关键机制 / 为什么这样设计

### 2.1 复用发生在"电线里"，不在内存里

这是脉动阵列对 SIMT 最本质的超越。回忆 §04：SIMT 要复用一个数据，必须**显式搬进 shared/寄存器再反复读**（还得操心 coalescing、bank conflict、swizzle）。脉动阵列不用：

> 一个激活/权重**一旦从边缘进入阵列，就沿着一整行/列 PE 流过去，途中被每个 PE 各用一次**——**复用是在互连电线上"顺路"发生的，免费、零额外访存。**

### 2.2 控制被摊薄到"整个阵列 × 所有时间"

§01 说 SIMT 把控制开销在 **32 条 lane** 上团购。脉动阵列更极端：**整个 128×128 = 16384 个 PE 共享同一套固定数据流控制，而且每一拍都在做同一件事**——控制开销被摊薄到**整个阵列乘以全部运行时间**，趋近于零。

> 🔑 **结果**：几乎 100% 的晶体管和能量都花在 MAC 上，没有取指/译码/调度/大寄存器堆的开销。**这就是脉动阵列稠密矩阵乘 FLOPS/W 碾压 SIMT 的根源。**

### 2.3 访存需求极低（高算术强度被"结构性"内建）

数据从边缘的本地 SRAM/buffer 进入一次，在阵列里被大量复用，结果从另一边流出。**阵列本身不需要 cache、不需要大寄存器堆**——只要边缘缓冲。用 A1 的话说：脉动阵列把**高算术强度直接焊进了硬件结构**，所以它对 HBM/SRAM 带宽的相对需求很低（这也解释了为什么 TPU 能用相对朴素的内存系统喂饱巨大的 MXU）。

### 2.4 代价：死板（为后续小节埋点）

这套优雅有明确代价，后面几节展开：
- **只会做稠密矩阵乘式的数据流**，没有分支、没有任意程序（对照 §03 SIMT 的控制流灵活性）。
- **形状刚性**：128×128 的阵列想要 128 对齐的维度，小/不整的形状会 padding 浪费 PE（→ 本模块 §05）。
- **时序设计期定死** → 正因如此**不需要任何 barrier**（→ 本模块 §02 正面展开，收 §01-05 的引子）。

> 🔑 **一句话对照**：SIMT 是"**可编程 + 动态调度 + 靠并发藏延迟**"；脉动阵列是"**固定功能 + 静态时序 + 靠结构省一切**"。前者灵活但要付同步/访存/发散的税，后者高效但死板。

## 3. 开发者视角：你怎么"碰"到脉动阵列

和 SIMT 最大的不同：**你几乎从不直接编程一个 PE**。脉动阵列对开发者是"一块加速积木"，你在**更高层**与它打交道：

| 站位 | 你的拨盘 | 感官（观测） |
| --- | --- | --- |
| 框架层（JAX/TF on TPU、PyTorch on Ascend） | 算子选择、**形状对齐**（凑成阵列边长的整数倍）、dtype | XLA/CANN 的 profile、**MXU/Cube 利用率** |
| 编译器/映射层（XLA、CANN、mapper） | tiling、数据流选择（weight/output-stationary，§03）、layout | 编译报告：阵列利用率、padding 浪费、内存搬运量 |
| 极少数：手写 microkernel | 直接排数据流（如 Tenstorrent 低层） | 逐 PE 时序 |

> 🔑 对算法侧：**你能给脉动阵列帮的最大忙，就是"喂对形状"**——维度对齐到阵列边长（TPU 上凑 128 的倍数）。形状不整 → padding → 阵列空转（这是 A2 里 tile 量化的硬件版，模块 02 §5 深讲）。这也是"算法侧需求如何沿栈传导到硬件"的最直接一例（→ 模块 04 §05）。

## 4. 最新架构落点（时效锚点 · 知识截至 2026-01）

- **Google TPU**：脉动阵列的教科书实现，核心是 **128×128 的 MXU（矩阵乘单元）**，一个核里多个 MXU。代际：v5e/v5p → **v6 Trillium（2024）→ v7 Ironwood（2025 公布，推理导向）**。→ 模块 05 对照。
- **华为昇腾 DaVinci**：**Cube 单元 = 16×16×16 的三维 MAC 阵列**，配 Vector/Scalar 单元。910B/910C。→ 模块 05。
- **NVIDIA Tensor Core**：本质是**一个小脉动/矩阵引擎被塞进 SIMT 核**——这正是两范式的交汇点，单开 **模块 03** 讲。
- **其它数据流芯片**：**Groq LPU**（静态调度、更偏 VLIW/数据流）、**Cerebras WSE**（晶圆级、SRAM 就近）、**Tenstorrent**（Tensix 核网格）、**Graphcore IPU**——都是"空间/数据流"家族的不同变体（→ §01 定盘星、模块 05）。
- **AMD Matrix Core（MFMA）**：SIMD 驱动的矩阵单元，**不是纯脉动**——提醒"矩阵引擎 ≠ 一定是脉动阵列"。

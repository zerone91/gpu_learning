# 脉动阵列怎么"泵"数据、时序为何设计期定死

> **所属模块**：模块 02 · 空间/脉动架构（本模块题眼）
> **状态**：🟨 学习中（第一版：本质/费曼 + 开发者视角 + 最新架构，知识截至 2026-01）
> **一句话主旨**：脉动阵列的每一个数据、每一个部分和，**在第几拍出现在哪个 PE，是设计/编译期就能写成公式的**——`时空坐标 = f(数据下标)` 是一个静态映射。于是"B 写完没有、A 能不能读"这类问题**在硬件存在之前就已经被回答了**，运行时无需任何询问与等待——**同步被"编译"进了连线和时钟**。代价：这个公式只对规则的稠密计算成立，一旦形状不整、控制流数据相关，公式失效，范式就得让位。

## 1. 核心概念

### 1.1 费曼起点：工厂流水线 vs 车轮战

回到 §01 的车轮战类比——那是 SIMT：大师动态挑"就绪"的棋盘，谁的对手想好了就走谁。脉动阵列是**另一种工厂**：

> **一条装配流水线**。传送带以固定速度走，每个工位（PE）每一拍对经过的半成品拧同一颗螺丝。工位从不问"上一站做完了吗"——**传送带的速度和工位的间距在建厂时就定了**，半成品到达时**必然**已带着上一站的结果。没有对讲机（barrier）、没有任务看板（scoreboard）、没有"谁就绪跑谁"的调度——**因为根本没有不确定性需要处理**。

两种工厂各自的立身之本：
- **车轮战（SIMT）**：应对**不可预测**的延迟（访存几百拍、分支、数据相关）→ 靠冗余并发 + 运行时调度兜底。
- **流水线（脉动）**：把问题限定在**完全可预测**的计算上（稠密矩阵乘）→ 把时序全部前置到设计期，运行时零决策。

### 1.2 时序的精确含义：时空坐标是数据下标的公式

以 §01 那张 weight-stationary 阵列算 `C = A·B`（N×N）为例，可以**逐字面**写出：

- 激活 `a[i][k]` 在**第 `k + i` 拍**进入第 `i` 行的左边缘（这就是 skew 的来源）；
- 它在**第 `k + i + j` 拍**到达 PE`(i,j)`，与常驻权重 `w[k][j]` 相乘；
- 部分和 `c[i][j]` 沿列向下累加，在**第 `i + j + N` 拍**从底边流出。

> 🔑 **"设计期定死"的精确含义**：存在一个**闭式公式** `到达拍数 = f(数据下标, PE 坐标)`，对每个数据、每个 PE 成立。整个计算就是这组公式的物理执行。硬件里没有任何一处需要在运行时"判断数据到没到"——**到达时间是构造保证（correct by construction），不是运行时事件**。
> 对照 §02-01 的记分牌：SIMT 里"load 何时回来"是**变长、不可预测**的，所以要 scoreboard 记账；这里每条"传输"都是**定长 1 拍**（到邻居），根本没有变长事件可记。

### 1.3 三阶段：fill → steady-state → drain

数据斜着涌过阵列，必然有"波前"和"波尾"：

```
拍数 →   fill（灌入）      steady（满载）        drain（排空）
        ▲ 利用率
        │        ╱────────────────────╲
        │      ╱                        ╲
        │    ╱                            ╲
        └──────────────────────────────────────→
         ~2N 拍           主体              ~2N 拍
```

- **fill**：第一批数据从左上角进入，波前尚未扫过全阵列 → 右下角 PE 空转。约需 **2N 拍**（对 N×N 阵列，波前斜穿对角线）。
- **steady-state**：阵列满载，**每拍 N² 个 MAC 全部有效**——这是脉动阵列的"巡航状态"，效率峰值。
- **drain**：最后一批数据的波尾扫出阵列，左上角先空。约 **2N 拍**。

**摊销账**（128×128 阵列）：fill+drain ≈ 数百拍固定开销。若矩阵 K 维（流经的深度）只有 128，满载时间与 fill/drain 同量级 → 利用率 ~50%；K=4096 → 开销占比 <10%。

> 🔑 **推论**：脉动阵列天生喜欢"**深**"的计算（大 K、长批次）——固定的 fill/drain 要靠足够长的 steady-state 摊薄。**这是"脉动阵列不擅长小矩阵"的第一个结构性原因**（第二个是形状 padding，→ §05）。和 A2 的 MoE 结论同构：小 M 喂不饱的问题，换到脉动阵列上表现为 fill/drain 摊不平。

## 2. 关键机制：为什么不需要 barrier（正面收 §01-05 主线）

§01-05 的结论是：**同步是异步的账单**——SIMT 里 barrier/fence/scoreboard 存在，是因为"谁先谁后"只能运行时才知道。现在逐项对账，看脉动阵列为什么一张账单都不用付：

| SIMT 需要它，因为…（§01-05） | 脉动阵列不需要，因为… |
| --- | --- |
| **scoreboard**：load 延迟变长、结果何时就绪不可预测（§02 §1.1+） | 所有"传输"都是**到邻居的定长 1 拍**，没有变长事件 |
| **`__syncthreads`**：warp 各自异步推进，先后不定（§01） | 全阵列共享**同一个时钟**，没有"各自推进"——所有 PE 天然同拍 |
| **fence**：弱内存模型下写的可见顺序无保证（§05 §1.2） | PE 之间**没有共享内存**，数据走点对点专用电线，"可见性"就是电线上的电平，无顺序问题 |
| **mbarrier + 字节计数**：要和异步 DMA 引擎对表（§05 §1.5） | 边缘 buffer 的读写节拍也在编译期排定，引擎与阵列**共享同一张静态时刻表** |
| **atomic**：多线程争写同一地址（§05） | 每个部分和有**唯一的、预定的**流动路径，永远不存在两个写者 |

> 🔑 **本质（全模块最重要的一句）**：SIMT 的同步原语，本质都是**运行时的"询问"机制**——"到了吗？写完了吗？轮到我了吗？"。脉动阵列把所有这些问题的答案**在设计期就写死在了连线和时钟树里**，运行时**无问可问**。**同步没有被"优化掉"，而是被"编译"进了硬件结构。**
>
> 由此得到贯穿全库的光谱：
> **纯 SIMT（全动态）——异步流水/warp 专化（软件把时序半排死，§02 §2.6）——Tensor Core（局部脉动，模块 03）——脉动阵列（全静态）——Groq（整颗芯片乃至互联全静态）**
> 越往右，确定性越强、同步越少、能效越高，**灵活性越低**。SIMT 在重负载上"主动向右挪"（FA-3/CUTLASS 的流水），正是这个光谱上的移动。

### 2.1 确定性的代价清单（老实列出）

零同步不是免费的，它付了四样东西：

1. **只能算"可静态化"的计算**：时序公式要求访存模式、迭代次数、数据流向全部**不依赖数据的值**。稠密 GEMM/卷积完美符合；数据相关的控制流（beam search、稀疏跳零、动态路由）**没有公式可写** → 要么退化处理，要么交还给伴生的通用核（DaVinci 的 Vector/Scalar、TPU 的 VPU 就是干这个的，→ 模块 05）。
2. **形状刚性**：公式按阵列物理尺寸（128×128）写死，矩阵维度不整除 → padding 空转（→ §05）。
3. **时钟即命门**：全阵列一个时钟同步搏动，频率受最长连线/最慢 PE 限制；工艺偏差、降频都作用于全局。
4. **无弹性容错**：SIMT 里一个 warp 慢了调度器绕开它；脉动阵列一个 PE 慢一拍 = 全局时序错乱——所以它必须用**同步数字电路的硬保证**（这也是它做不大到"整晶圆一个阵列"的原因之一，Cerebras 用的是"许多小阵列 + 片上网络"而非一个巨阵列）。

> 🔑 **一句话**：脉动阵列用"**回答问题的能力**"换了"**不需要问问题的效率**"。它不是比 SIMT 聪明，而是把聪明花在了编译期。

## 3. 开发者视角：静态时序在工具链里长什么样

时序全静态的直接后果：**性能分析从"运行时测量"大幅前移到"编译期预测"**——这是和 SIMT 生态最大的体感差异。

| 你想知道 | SIMT 世界（§01-05 的方式） | 脉动/静态世界 |
| --- | --- | --- |
| 这个算子多快 | 跑 ncu 测（stall、SOL） | **编译器直接算出来**（cost model 就是那组时序公式）：XLA 的 HLO cost、Groq 编译器给出**精确到拍**的耗时 |
| 瓶颈在哪 | 三级下钻定位（A1） | 编译报告：阵列利用率 %、padding 浪费 %、fill/drain 占比、边缘带宽是否喂满 |
| 优化什么 | 访存模式/占用率/流水深度 | **喂对形状**（对齐+够深）、选对数据流（§03）、tiling 让边缘带宽跟上（§04） |
| 不确定性来自哪 | 硬件动态调度 | **几乎只剩输入形状**——同形状跑一万次，拍数一致（Groq 直接以此卖点：确定性延迟，利于 SLA） |

> 对算法侧：在 TPU/NPU 上，**profile 的第一眼不是 stall 分解，而是"编译器把你的图切成了什么形状的 matmul、利用率各多少"**。性能问题九成在"形状与映射"，一成在运行时——和 GPU 正好倒过来。

## 4. 最新架构落点（时效锚点 · 知识截至 2026-01）

- **TPU（v5p/v6 Trillium/v7 Ironwood）**：MXU 脉动阵列 + 静态编译（XLA）路线不变；代际主要变化在阵列数量、HBM 带宽、互联（ICI/OCS 光交换）——**核心时序模型 20 年未变**，说明这个范式在稠密负载上已近最优。
- **Groq LPU**：把"静态确定"推到极限——**不仅阵列，整颗芯片的每条指令、每次 SRAM 访问、乃至多芯片间的网络传输全部编译期排定**（软件调度硬件，无 cache、无动态仲裁），换来确定性低延迟推理。它是本节思想的"完全体"。
- **Tenstorrent / Cerebras**：走"许多小核 + 片上网络"的数据流路线，时序**局部静态、全局弹性**（NoC 有握手）——介于两极之间，印证 §2 的光谱。
- **NVIDIA 侧的镜像**：Blackwell 的 tcgen05/TMEM 让 MMA 流水更"排定"；CUTLASS/FA-3 的 warp 专化本质是**软件模拟静态时刻表**——两个范式在互相靠近（→ 模块 03 正面缝合）。

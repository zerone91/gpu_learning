# 模块 06 · 数据视角：存储、搬运与布局（纵向串线）

前面的模块按**部件**组织知识（SM 一章、脉动阵列一章、软件栈一章）；这个模块换一根轴，**跟着数据走**：住在哪（层级的物理切分）、怎么搬（指令与三个搬运引擎）、怎么摆（布局 = 硬件约束下的解）、怎么切（tiling 与布局在 tile 边界相遇）。

定位和模块 05 对称：05 是横向收敛（把概念钉到芯片上），06 是纵向串线（把概念串到数据的一生上）。已有机制在这里只做够自洽的复述并指路原文，篇幅花在**串线**（约束传导链、指令矩阵、引擎半径）和**增量内容**（HBM 通道/行缓冲、L2 slice、paged KV、NZ 分形布局、张量格式家族）上。

## 小节

- ✅ [01 · 数据的一生：存储层级的物理切分与搬运指令全图](./01-存储层级与搬运指令全图.md) —— 通道/行缓冲/slice/bank 逐级解剖 + 层级×层级搬运指令矩阵 + TMA/copy engine/RDMA 三引擎按半径分工
- ✅ [02 · 摆数的学问：布局与切分](./02-摆数的学问·布局与切分.md) —— 立论"布局是硬件约束的解"：mma→ldmatrix→swizzle→TMA→全局布局的约束传导链 + 布局动物园（NHWC/paged KV/NZ 分形）+ 布局与切分的两个相遇点 + 块缩放格式的第二条约束链
- 🟨 [03 · 数据进 GPU 之前：从存储到显存的上游通路](./03-数据进GPU之前·从存储到显存的上游通路.md) —— 把"数据的一生"往上游接一段：锁页内存为什么是必要条件而非优化项 + PCIe 这道最窄的坎与 NUMA 亲和性 + GPUDirect Storage + "数据加载会不会成为瓶颈"的动手前判据 + C2C 让主机内存成为层级新一级

**三节的关系**：01 讲数据**住在哪、怎么搬**（片内），02 讲它**怎么摆**（布局是约束满足问题的解），03 讲它**怎么进来的**（片外的上游通路）。合起来才是完整的一生——**从磁盘上的一个字节，到 Tensor Core 里的一次乘加。**

# 与算法侧的接口

> **所属模块**：模块 04 · 软件优化栈（收官节 · 直接服务日常工作）
> **状态**：🟨 学习中（第一版，知识截至 2026-01）
> **一句话主旨**：算法侧的每个设计决策（形状、精度、结构、动态性）都会**沿栈往下传导**，在某一层落地成硬件后果——而传导是**单向衰减**的：算法侧一行代码就能决定的事（d_model 选 4096 还是 4100），到了 kernel 层要付出巨大代价才能补救、到了硬件层无药可救。**所以算法侧是全栈杠杆率最高的位置**。本节给出传导链、帮忙/添堵清单、和一张"方案评审提问单"——把全库知识压缩成日常可用的工作方法。

## 1. 传导链：算法决策的下行轨迹

四条主传导链，每条从算法侧一个决策出发，标注它在哪层落地成什么（全是前文内容的反向串联）：

```
① 形状链：d_model=4096 (而非 4100)
   → ②层: 无需 padding/layout 抖动
   → ③层: tile 整除、autotune 有现成最优点
   → 硬件: 无形状税(02-05)、Tensor Core 满编(03-01)
   ⚠️ 反之 4100: 每层都在为 4 个多余元素买单

② 精度链：bf16→fp8
   → 目标 pipe 平衡点抬高一倍(A1: 300→590)
   → ③层: 必须更大 tile/更多复用才 compute-bound
   → ②层: scale 张量的读写要 prologue/epilogue 搭车(04-02)
   ⚠️ 降精度省的带宽，会被管理开销部分吃回

③ 结构链：算子怎么连
   → 决定②层的融合机会(04-02): elementwise 链可融、
     归约是分界、matmul-matmul 要改数学(FA)
   → 决定复用度即 AI(A2): attention 复用~N、MoE 复用~M_i
   ⚠️ 结构定了，AI 的上限就定了——kernel 工程师只能逼近它

④ 动态性链：shape/控制流是否数据相关
   → ②层: graph break、重编译、显存规划失效(04-01/02)
   → ③层: autotune 缓存爆炸(04-03)
   → 硬件: 发散(01-03)、形状税常态化(02-05)
   ⚠️ 动态性是全栈公敌，每一层都为它降级
```

> 🔑 **杠杆率排序**：**结构链 > 形状链 > 精度链 > 动态性链**（按"决定性能上限"排）——结构定 AI 上限（无法逾越），形状定实际利用率，精度定平衡点位置，动态性定全栈折损系数。**算法侧真正的权力是前两条：你在定 AI 和形状税的那一刻，已经替 kernel 工程师定了他能做到的最好成绩。**

## 2. 帮忙清单（正向设计规则，附出处）

1. **维度全选硬件粒度的倍数**：d_model/FFN/头维 → 128 倍数（大阵列）或至少 16/8（MMA 形状）；词表 pad 到 64/128 倍（02-05"形状文化"）。
2. **让复用有处可寻**：能合的 GEMM 合起来（QKV 合投影=横向融合素材）；decode 场景攒 batch（A2 M*≈300/专家）；MoE 专家粒度别细到永远喂不饱。
3. **给融合留窗口**：可融算子之间别插 data-dependent 控制流/打印/自定义黑盒算子（graph break，04-02）；新算子尽量表达成"GEMM+elementwise 尾巴"（epilogue 可吸收）。
4. **静态优先**：能固定的 shape 就固定；变长序列 bucket 化（02-05）；控制流上提到图外。
5. **降 KV/权重的字节数是 decode 的第一杠杆**（A2：decode 必 memory-bound）——GQA/MLA、KV 量化的收益直接乘在带宽上。
6. **对齐"当前硬件在赌什么"**：Blackwell 赌 FP4/大 NVLink 域 → 低精度友好 + TP 亲和的结构占便宜（03-02/03-01 落点）。

## 3. 添堵清单（反面模式，见了要警觉）

| 反面模式 | 疼在哪层 | 出处 |
| --- | --- | --- |
| 质数/不整维度（4097、头维 100） | 形状税+layout 抖动+autotune 失准 | 02-05 |
| 一堆 tiny GEMM（M/N/K<64）且不 batch | fill/drain 摊不平、tile 量化、launch 开销 | 02-02/A2 |
| token 级数据相关分支（每 token 走不同路径） | 发散+graph break+无法 batch | 01-03/04-02 |
| 长 elementwise 链不 compile | 全 memory-bound 往返 | 04-02 |
| 超细粒度 MoE + 小 batch decode | 权重带宽 bound 到死（M_i≪M*） | A2 §2.6 |
| 每步变 shape（不 bucket） | 全栈重编译/缓存爆炸 | 04-03 |
| 融合链中间夹自定义 CPU/黑盒算子 | 融合窗口拦腰斩断 | 04-01 |

## 4. 方案评审提问单（按 04-04 四维组织——"翻译术"的落地）

听任何 kernel/系统/芯片适配方案，五个问题问穿它：

1. **【bound】** "这个负载在目标硬件上是什么 bound？AI 多少，卡哪条 pipe/哪级带宽？"（A1 三步）——答不上来的方案先存疑。
2. **【placement】** "复用发生在哪一级？中间结果落不落 HBM？"（02-03/04-02）——融合方案的核心就这一问。
3. **【tiling/形状】** "tile 和我们的形状整除吗？边界/变长怎么处理？"（02-05/A2 tile 量化）。
4. **【binding/重叠】** "最贵的资源(Tensor/阵列/网络)空转吗？靠什么填（流水/专化/TBO）？"（A1(04)）。
5. **【动态性】** "shape/路由变化时，哪些优化失效？退化路径是什么？"——**方案吹性能时最常隐藏的就是这条**。

> 配套心法（04-04）：把对方的每个宣传点翻译回"改了四维里的哪一维"——translate 不出来的宣传点，多半是包装。

## 6. 最新架构落点：硬件感知的模型设计成例（时效锚点 · 知识截至 2026-01）

**"算法迁就硬件"已从潜规则变成显学**，成例都能用本库语言翻译：

- **MQA/GQA → MLA（DeepSeek）**：都在砍 decode 的 KV 字节（A2：decode=KV 带宽 bound）；MLA 用低秩压缩把 KV 缓存降一个量级——**为带宽墙重设计注意力结构**的代表作。
- **DeepSeek-V3 全套软硬协同**：FP8 训练（精度链）、128 倍数维度（形状链）、DualPipe/TBO（通信重叠）、细专家+冗余专家配 EP 域——一篇论文把四条传导链全走了一遍。
- **滑窗/混合线性注意力**（Mistral 滑窗、各类 linear attention 混合）：把 attention 的 O(N²) 结构性砍掉——**改结构链抬 AI 上限**。
- **投机解码**：把"每步 1 token"的 decode 变成"每步验证 k token"——**人为制造 M，对抗 A2 的小 M 宿命**。
- **Llama 系维度全是 2 的幂/128 倍**：形状文化的默认体现。

# 图层优化：融合、排布与显存规划

> **所属模块**：模块 04 · 软件优化栈
> **状态**：🟨 学习中（第二版：按《写作规范》全文重写。知识截至 2026-08）
> **本节主旨**：上一节讲过，②层（图编译层）手里的独家信息是**算子之间的关系**——谁连着谁、中间结果活多久。本节讲它用这份信息干的三件大事：**算子融合**（把"写出去再读回来"变成寄存器里直接传递，全栈性价比最高的优化）、**数据排布**（让张量以硬件喜欢的姿势存放）、**显存规划**（用生命周期分析让不同张量复用同一块显存）。三件事的价值尺子是同一把：模块 01 第 4 节的访存账——**图层优化的本质，是在"整张图"的尺度上减少数据搬运**。

## 1. 基础词汇：先把本节要用的词讲清楚

**中间结果（intermediate）**。图里一个算子的输出、下个算子的输入——用完即弃的临时张量。未经优化时，每个中间结果都要**完整地写进显存再读出来**，这个往返是图层优化的头号打击对象。

**融合（fusion）**。把相邻的几个算子合并成一个 kernel，让中间结果**不落显存**、直接在寄存器里从前一个计算流到后一个。上一节的五层走查里②层做的那个决定就是它。

**数据排布（layout）**。多维张量在一维内存里的存放顺序——比如一张图片按"行×列×通道"还是"通道×行×列"排。数学上等价，访存效率天差地别（模块 01 第 4 节：地址连续才能合并访问）。

**生命周期（liveness）**。一个中间张量从"被算出来"到"最后一次被读"的存活区间。区间结束后它占的显存就可以给别人用——显存规划的基本原料。

**重计算（recomputation / checkpointing）**。训练时不保存某些中间结果，反向传播需要时**重新算一遍**——用算力换显存的标准手段。

## 2. 融合：图层的头号武器

### 2.1 省的是什么：一笔算得出的账

**例子：`y = relu(x + b)`，x 有一亿个元素（bf16，约 200 MB）。** 不融合时是两个 kernel：加法 kernel 读 x（200 MB）、写中间结果（200 MB）；relu kernel 再读中间结果（200 MB）、写 y（200 MB）——显存流量共 **800 MB**。融合成一个 kernel：读 x、加法和 relu 在寄存器里一气呵成、写 y——流量 **400 MB，恰好减半**。这类逐元素运算是典型的访存受限（模块 01 第 1 节：每个数只算一两下），流量减半就是时间减半。链条越长省得越多：三个逐元素算子串联，融合把流量从 6 份砍到 2 份。**中间结果的"落地税"，是融合要消灭的全部对象。**

### 2.2 三种融合形态

- **纵向融合**（最常见）：生产者-消费者直连，如上例。适用于逐元素运算、归一化的链条。
- **横向融合**：几个互不依赖、形状相同的算子并成一个 kernel——省启动开销、共享输入的读取。典型：注意力里 Q、K、V 三个投影矩阵乘并成一个大矩阵乘。
- **epilogue 融合**（搭便车）：把矩阵乘**后面**的零碎（加偏置、激活、缩放）塞进矩阵乘 kernel 的收尾阶段。它有一个独特的经济学：矩阵乘是计算受限的（Tensor Core 满负荷），它写回结果的那段时间**访存通道本来就闲着**——零碎操作在写回的路上顺手做掉，**几乎零成本**。"让访存受限的零活搭计算受限的车"是②层调度的第一原则。

### 2.3 融合的边界：什么融不动

融合不是万能胶，两条硬边界：

**边界一：两个矩阵乘之间融不动（一般情况）。** 原因有二：中间结果是一整个大矩阵（比如注意力里 QKᵀ 的结果是"序列长×序列长"），寄存器和 shared memory 装不下；而且两个矩阵乘各自的最优分块方式冲突。**著名的例外是 FlashAttention**——但它不是靠编译器：它**改写了 softmax 的数学**（分块在线更新），让中间矩阵可以一块一块地算完就扔。这划出了一条重要的能力边界：**编译器只能重排计算，不能改写算法**——需要改数学的融合，永远是人的工作（上一节"人肉跨层"的精确含义）。

**边界二：归约是天然的分界线。** softmax 的分母要等所有元素加完才有——后续计算依赖**全部**前序结果，朴素融合会把并行度掐死。要跨过归约做融合，同样得改数学（在线化），回到边界一。

此外还有工程性的断点：图里夹着 print、数据相关的 if、自定义黑盒算子，都会切断抓图（上一节的 graph break），融合机会随之丢失。

## 3. 数据排布：全图统筹的"摆放"问题

单看一个算子，它只是"偏好"某种排布（比如卷积在 Tensor Core 上偏好通道维连续的 NHWC 格式，因为那样访存能合并、能喂进矩阵指令）。但排布是**全图**的问题，原因看一个例子：

**例子：转置在图里的传染。** 图中有 10 个连续的算子，第 3 个偏好排布甲、其余偏好排布乙。如果只顺着第 3 个的意思，它前后各要插一次转置（重排整个张量，纯搬运开销）；如果让第 3 个将就用乙排布（性能略降），一次转置都不用。哪种划算？**取决于转置的成本与将就的损失之比**——这必须看着整张图算总账，一个算子一个算子地局部决定必然次优。图编译器做的"排布传播"就是这道全局账：目标是**全图转置总成本最小**。实际工程里的红旗信号也由此而来：性能时间线上出现大量转置/拷贝类 kernel，说明排布在图里"打架"，值得查。

## 4. 显存规划：让张量们错峰共住

②层看得见每个中间张量的生命周期（第 1 节词汇），于是可以做一件运行时做不到的事：**让生命周期不重叠的张量共用同一块显存**。

**例子：五个张量，两块显存。** 某段图产生五个中间张量，生命周期（以算子序号计）分别是：A 活在 1–3、B 活在 2–4、C 活在 4–6、D 活在 5–7、E 活在 6–8。朴素分配要五块显存。看重叠关系：A 和 C 不重叠（A 在第 3 步就死了，C 第 4 步才生）——可以共住一块；同理 B 和 D 共住一块；E 和 A 也不重叠可以回收 A 的……排下来**两到三块显存就够了**，省了将近一半。这本质上是个"区间不重叠就同色"的图着色问题，静态图上可以全局求解。配套手段还有**原地操作**（消费者是最后一个读者时直接覆写输入，零新增）和**重计算**——后者值得单算一笔账：

**例子：重计算的交换比。** 训练时每层的激活值都要留到反向传播用，长序列大模型的激活显存动辄几十 GB、常常超过权重本身。开启重计算：只在每层边界存一份"检查点"，中间激活全部丢弃、反向时从检查点重新算一遍前向。代价是**多算约三分之一的前向计算**；收益是激活显存**降到原来的几分之一**。按模块 01 的定调（算力便宜、搬运和容量贵），这笔"用计算换容量"的交易几乎总是划算的——它是那个定调在训练场景的直接应用。

## 6. 最新架构落点（知识截至 2026-08）

- **Inductor 的模板融合**日趋成熟：矩阵乘用现成模板、epilogue 自动缝合——第 2.2 节的搭便车已高度自动化。
- **低精度时代 epilogue 更关键**：fp8/fp4 的每块缩放因子读写必须搭矩阵乘的车，否则低精度省下的带宽被缩放张量吃回去。
- **推理引擎的定式**：vLLM/TensorRT-LLM 对固定的模型结构直接模式匹配到手写融合 kernel——图层优化与③层手工的深度混合。
- **融合的边界被往前推了一格，但推的方式值得注意**。§2.3 的结论是"需要改数学的融合编译器做不到"。FlexAttention 加 FA-4 的组合（第 3 节 §8、附录 A1）**没有推翻这条**——它的做法是**把已经被人改写好的数学（在线 softmax）做成一个骨架，让用户只填打分和掩码**。**这是把边界那一侧的成果搬到这一侧来复用，不是突破边界。** 判断任何"编译器现在也能做 X 了"的说法，用的都是这个判据：**它是发现了新数学，还是复用了已知数学？**
- **训练侧的图层优化正在和另外两件事耦合求解**。过去融合、显存规划、重计算选择是分三步各做各的；现在的方向是把三者放进同一个优化问题——**因为它们抢的是同一笔显存预算**（模块 09 第 1 节 §5 算过这笔账，本模块第 7 节 §7 讲了为什么自动微分的位置让这件事成为可能）。

## 7. 术语卡

### 算子融合（operator fusion）
**定义**：把相邻算子合并成一个 kernel，中间结果在寄存器里直接传递、不落显存。省的是"落地税"：每融合掉一个中间结果，省两趟它全尺寸的显存读写。
**为什么存在**：逐元素类算子是访存受限的，时间几乎全花在中间结果的往返上——融合直接砍掉往返，是全栈性价比最高的优化。
**语境例句**："这条链 compile 后融成了一个 kernel，快了 40%。" —— 意思是：几个逐元素算子的中间结果不再落显存，流量降到原来的几分之一——访存受限负载的标准收益。

### epilogue 融合
**定义**：把矩阵乘之后的零碎操作（偏置、激活、缩放）塞进矩阵乘 kernel 的写回阶段执行。
**为什么存在**：矩阵乘计算受限、写回时访存通道空闲——零活搭车近乎免费。"访存受限的活搭计算受限的车"是图层调度的第一原则。
**语境例句**："bias 和 gelu 都进 epilogue 了。" —— 意思是：这两个操作不再是独立 kernel，在矩阵乘写结果的路上顺手完成——时间线上看不到它们了，这是好事。

### graph break
**定义**：自动抓图被打断的位置（触发者常是 print、数据相关分支、不被识别的自定义算子）。图被切成两段，跨断点的融合机会全部丢失。
**为什么存在**（作为现象）：抓图机制只能处理"可静态化"的代码，遇到必须真执行才知道结果的东西就得停下——是动态语言灵活性的税。
**语境例句**："先跑 dynamo.explain 看看 break 在哪。" —— 意思是：融合效果不如预期时，第一件事是找出图在哪断了、为什么断——常常挪走一行日志打印就能连上。

### 数据排布（layout）与排布传播
**定义**：张量在内存里的存放顺序，及编译器在全图上统筹"谁转置、谁将就"使总转置成本最小的优化。
**为什么存在**：排布决定访存能否合并、能否直接喂进矩阵指令；而局部最优的排布选择会让转置在图里传染——必须全局算账。
**语境例句**："时间线上 copy 类 kernel 占了 15%。" —— 意思是：排布在图里打架，编译器被迫插入大量转置搬运——检查模型里有没有混用排布约定的层。

### 重计算（activation checkpointing）
**定义**：训练时丢弃中间激活、反向传播需要时从检查点重算的技术。多花约三分之一前向算力，激活显存降到几分之一。
**为什么存在**：激活显存随序列长度和模型深度暴涨，常是训练的第一瓶颈；而算力相对便宜——用便宜的换紧缺的。
**语境例句**："开了 checkpoint 才塞得下这个序列长度。" —— 意思是：显存不够时的第一个标准动作——代价是每步慢一点，换来能跑。

# 栈的分层全景

> **所属模块**：模块 04 · 软件优化栈
> **状态**：🟨 学习中（第一版，知识截至 2026-01）
> **一句话主旨**：软件栈是一台**逐层丢弃信息、逐层逼近硬件的翻译机**：框架层知道"整个模型长什么样"但不知道硬件；ISA 层知道每条指令但看不见模型。**每层能做的优化，恰好由"这层还剩下什么信息"决定**——所以融合只能在图层做（那里还看得见算子间关系）、tiling 只能在 kernel 层做（那里还看得见循环）、寄存器分配只能在 ptxas 做（那里才看得见物理寄存器）。栈的分层不是官僚主义，是**信息的自然衰减**。

### 1.2 题眼：信息衰减决定优化归属

每往下一层，就**丢一层信息、换一层精度**：

- **融合为什么只能在②**：到了③，一个 kernel 就是全世界——它根本**不知道**旁边还有个 elementwise 可以吸进来。反过来①层太早：还不知道后端有没有对应的融合 kernel 模板。
- **tiling 为什么只能在③**：②层看到的是"一个 matmul 节点"，没有循环可切；④层循环已经展开成指令流，切不动了。
- **寄存器分配为什么只能在④**：③层（PTX/Triton IR）的寄存器是无限虚拟的（§01-06）——物理寄存器堆只在 ptxas 眼里存在。
- **推论（重要）**：**性能问题要到"拥有该信息的那层"去解**。显存爆了去②（复用规划），Tensor Core 没吃到去③（tl.dot/形状），spill 了去④（-maxrregcount）——**拿着 profiler 结果先问"这是哪层的锅"**，是排查的第一分叉。

> 🔑 **信息衰减也解释了"跨层打穿"为什么又难又香**：FlashAttention 本质是把②层的知识（"这几个算子永远连在一起出现"）**人肉带进**③层写成一个 kernel——编译器自动做不到，因为②③之间的接口（"一个算子一个 kernel"）把这个信息切断了。**每一次著名的性能突破，几乎都是一次跨层信息走私**（FA、Paged attention、megakernel）。

### 1.3 两条栈的哲学（光谱的软件延伸，收 00 的线）

| | GPU 栈 | NPU/TPU 栈 |
| --- | --- | --- |
| 决策重心 | **偏运行时**：eager 执行、动态 shape、JIT（torch.compile 按需编译）、运行时调度 | **偏编译期**：全图静态编译（XLA/CANN）、shape 必须已知、编译器排定一切 |
| ②层地位 | 可选加速器（不 compile 也能跑） | **必经之路**（不过编译器就没法上芯片） |
| 灵活 vs 性能 | 动态性好，静态优化吃不满 | 全图优化吃得满，动态负载(MoE/变长)痛苦 |
| 对应硬件哲学 | 动态调度硬件（模块 01） | 静态时序硬件（模块 02） |

> **软硬件哲学是配套的**：动态硬件配运行时重的栈，静态硬件配编译期重的栈——00 的光谱完整地延伸进了软件。torch.compile 的崛起 = GPU 栈向右（静态）收编译红利；MoE/动态 shape 的流行 = 逼 NPU 栈向左补动态性。**两条栈也在互相靠近。**

### 1.4 主流工具点名（地图版，②③层细节留给 02/03 节）

- **②层**：XLA（TPU 正统/JAX）、**torch.compile/Inductor**（PyTorch 主线，产出 Triton）、TensorRT(-LLM)（NV 推理）、CANN/GE（昇腾）、TVM（学术/端侧经典）、**MLIR**（不是产品，是"造编译器的乐高"——XLA 新版、Triton、CANN 底下都是它）。
- **③层**：cuBLAS/cuDNN/FlashAttention 库（预制菜）、**CUTLASS/CuTe**（C++ 模板积木）、**Triton**（Python 写 kernel 的事实标准，Inductor 的后端）、Ascend C/TIK（昇腾）。
- **⑤层**：CUDA runtime/driver、**CUDA Graph**（把一串 launch 录成图重放，砍启动开销——decode 场景标配）、NCCL（通信，03-02）。

| 症状（profiler/现象） | 哪层的锅 | 去哪拧 |
| --- | --- | --- |
| kernel 之间空隙大、launch 密集 | ②/⑤ | torch.compile 融合；CUDA Graph |
| 单 kernel 慢、Tensor util 低 | ③ | Triton/CUTLASS 重写；形状对齐 |

| 通信占大头 | 栈外（并行策略） | 03-02 那张贴层表 |

## 3. 最新架构落点（时效锚点 · 知识截至 2026-01）

- **torch.compile 成为 PyTorch 默认路径**（2.x 系列持续强化），Inductor→Triton→ptxas 是新的主干道——**Triton 事实上成了②③层之间的通用接口语言**（NV/AMD/Intel 后端都有）。
- **MLIR 一统②层地基**：XLA(StableHLO)、Triton、CANN、各家 NPU 编译器全部构建其上——听到 "dialect/lowering/pass" 就是 MLIR 词汇。
- **推理引擎自成一栈**：vLLM/SGLang/TensorRT-LLM 把①②⑤压成一体（调度+KV管理+定制kernel），是"垂直打穿"的产品化。
- **AMD/昇腾**：ROCm 对齐 CUDA 各层（hipcc/rocBLAS/Composable Kernel）；CANN 全栈静态风格更重。

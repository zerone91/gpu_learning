# 模块 04 · 软件优化栈（自顶向下）

软件栈的本质就是**"把负载映射到硬件"**——所以放在硬件（01–03）之后。整条栈分五层：① 框架层 → ② 图编译层 → ③ kernel 层 → ④ 底层编译层 → ⑤ 运行时层 → 硬件。第 07 节「核心映射问题」是**整个学习计划的收束点**，把前面所有硬件概念和软件栈缝死。

## 小节

**第一部分：五层地图与逐层展开**

- ✅ [01 · 栈的分层全景](./01-栈的分层全景.md) —— 五层地图、信息衰减决定优化归属、按症状定层的排查表
- 🟨 [02 · 第①层 · 框架层](./02-框架层.md) —— 讲透的项目：PyTorch（对照 JAX）。一次 `x @ W` 调用的六站、反向图的显存账
- 🟨 [03 · 第②层 · 图编译层](./03-图编译层.md) —— 讲透的项目：torch.compile（对照 TensorRT）。融合 / 排布 / 显存规划，一个函数的六步编译
- 🟨 [04 · 第③层 · kernel 层](./04-kernel层.md) —— 讲透的项目：Triton。计算与调度分离、autotune、手排流水，一份矩阵乘源码里的七项功能
- 🟨 [05 · 第④层 · 底层编译层](./05-底层编译层.md) —— 讲透的项目：NVIDIA 编译工具链（对照 AMD）。一个十行 kernel 从 C++ 到 PTX 到 SASS 的两次变形
- 🟨 [06 · 第⑤层 · 运行时层](./06-运行时层.md) —— 讲透的项目：PyTorch 显存分配器、CUDA Graph。显存碎片怎么产生、启动开销怎么消除

**五层各章采用同一种结构**：层的定义 → 为什么在这里切一刀 → 输入与输出 → 上下边界的接口 → 看得见什么、看不见什么 → 功能集合 → 业界的典型项目 → 拿一个项目用例子讲透 → 开发者视角 → 最新架构落点 → 术语卡。
